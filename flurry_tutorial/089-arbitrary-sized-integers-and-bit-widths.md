## 一、 为什么需要非整字节的精确位宽类型？

在处理硬件寄存器、紧凑二进制协议、5/6-bit 颜色通道（如 RGB565）或 24-bit 音频采样时，数据的真实位宽往往并非 8、16、32、64 这样的 2 的幂次字节宽度。

如果只能使用 `u8`、`u16` 来近似表示这些字段，通常会带来两个问题：
1. **值域边界不精确**：例如 5 比特无符号通道的合法范围是 `0..=31`，若参数类型写成 `u8`（范围 `0..=255`），签名本身无法阻止调用方传入大于 31 的数值。
2. **位拼接宽度存在分歧**：在位向量代数（`BitVec<n>`）中，拼接 `a ++ b` 的结果宽度等于两侧位宽之和。如果红（5 位）、绿（6 位）、蓝（5 位）三个通道都存成 `u8`，它们的 `'bitvec` 视图都是 `BitVec<8>`，直接拼接会得到 24 位而非 16 位，还需要额外切片丢弃高位。

为此，Flurry 支持任意正整数位宽的有符号/无符号整数（如 `u4`、`u5`、`u6`、`i24`）以及定宽位向量 `BitVec<n>`。

## 二、 位表示宽度 vs 独立存储大小

理解任意位宽整数的核心，是区分**逻辑位表示宽度（Representation Bit-Width）**与**独立内存存储大小（Storage Byte Size）**：

> **位宽由被观察类型的逻辑位表示决定。例如 `u5` 的位表示固定为 5 位（`u5'bitvec` 的类型为 `BitVec<5>`），免因单独存放在内存中占用 1 个字节就变成 8 位。**

```text
                    一个 u5 类型的值（例如十进制 21 = 0b10101）
                                       │
         ┌─────────────────────────────┴─────────────────────────────┐
         ▼                                                           ▼
┌─────────────────────────────────────┐     ┌─────────────────────────────────────┐
│ 1. 逻辑位表示 (Representation Bits) │     │ 2. 独立内存存储 (Standalone Storage)│
├─────────────────────────────────────┤     ├─────────────────────────────────────┤
│  Bit 4   Bit 3   Bit 2   Bit 1  Bit0│     │  Pad   Pad   Pad  │ b4 b3 b2 b1 b0  │
│ ┌──────┬──────┬──────┬──────┬──────┐│     │ ┌─────┬─────┬─────┼──┬──┬──┬──┬──┐  │
│ │  1   │  0   │  1   │  0   │  1   ││     │ │  ?  │  ?  │  ?  │ 1│ 0│ 1│ 0│ 1│  │
│ └──────┴──────┴──────┴──────┴──────┘│     │ └─────┴─────┴─────┴──┴──┴──┴──┴──┘  │
│ ◀────────── 精确的 5 位 ───────────▶│     │ ◀─── 3 位填充 ───▶◀── 5 位有效 ──▶  │
│                                     │     │ ◀──── 物理内存对齐到 1 字节 ─────▶  │
│ • 值域范围: 0 ..= 31 (2^5 - 1)      │     │                                     │
│ • val'bitvec 类型为: BitVec<5>      │     │ • 填充位不属于 u5 的逻辑位表示      │
└─────────────────────────────────────┘     └─────────────────────────────────────┘
```

### 示例：使用精确位宽实现 RGB565 打包与解包

借助 `u5`、`u6`（或 `BitVec<5>`、`BitVec<6>`）与 `'bitvec` 视图，可以直接按字段位宽拼接与切片，无需手写移位和掩码：

```flurry
use std.prelude.*;

-- 使用精确位宽组装 16 位 RGB565 像素：5 + 6 + 5 = 16 bits
pure fn pack_rgb565(r: u5, g: u6, b: u5) -> u16 {
    (r'bitvec ++ g'bitvec ++ b'bitvec).as(u16)
}

pure fn extract_green(pixel: u16) -> u8 {
    let bits = pixel'bitvec;
    -- 索引 0 为最低有效位（LSB）：
    -- [0..5]   为蓝色通道 (5 bits)
    -- [5..11]  为绿色通道 (6 bits，类型为 BitVec<6>)
    -- [11..16] 为红色通道 (5 bits)
    let green_bits: BitVec<6> = bits[5..11];

    -- 从 BitVec<6> 向更宽的无符号整数 u8 (8 >= 6) 转换：高位自动补 0
    green_bits.as(u8)
}

test {
    let pixel = pack_rgb565(31, 42, 1);
    let g = extract_green(pixel);
    println("green channel: {}", g);
}
```

这里的位序规则固定且独立于宿主架构字节序：
1. **索引 `0` 为最低有效位（LSB）**，索引增大向高位移动；
2. **拼接 `a ++ b` 将 `a` 放在高位侧，将 `b` 放在低位侧**，与二进制字面量从高到低的书写顺序一致。

## 三、 静态检查边界：字面量范围、窄化截断与填充位

### 1. 字面量超出目标位宽时静态报错

将整数字面量赋给 `BitVec<n>` 或 `uN` 时，字面量数值必须满足 $0 \le \text{value} < 2^n$。前导零维持原状而无改于目标类型的位宽，超出范围的字面量免于发生隐式高位截断：

```flurry
fn reject_literal_overflow() {
    -- 编译错误：BitVec<5> 的合法范围为 0..=31，字面量 32 超出 5 位无符号表示范围
    let overflow_bits: BitVec<5> = 32;
}
```

### 2. 禁止通过 `.as(T)` 直接向更窄位宽转换

从 `BitVec<n>` 向等宽或更宽的 `BitVec<m>`、`uM`（$m \ge n$）执行 `.as(T)` 会自动在高位补零；但向更窄的目标类型直接调用 `.as(T)` 属于静态错误。若需要截取部分比特，必须先通过切片 `bits[lo..hi]` 显式指定保留的位区间：

```flurry
pure fn reject_narrowing_cast(wide: u16) -> u8 {
    let bits: BitVec<16> = wide'bitvec;
    -- 编译错误：禁止将 16 位的 BitVec<16> 直接窄化转换为 8 位的 u8
    bits.as(u8)
}

pure fn explicit_low_byte(wide: u16) -> u8 {
    let bits: BitVec<16> = wide'bitvec;
    -- 先显式切出低 8 位 [0..8]，再转换为 u8
    bits[0..8].as(u8)
}
```

### 3. 含未定义填充（Padding）的聚合体禁止直接作为普通 `BitVec` 整体读取

如果一个结构体内部或末尾包含未定义的对齐填充字节，其物理存储中存在未确定的比特。普通 `BitVec<n>` 要求每一位都是已定义的确定值，`'bitvec` 视图免将未定义填充位隐式清零，因此无法对含填充位的聚合体直接整体取 `'bitvec`，而应分别读取各个已定义的字段。

## 四、 本篇小结

| 概念 / 操作 | 语义契约 | 静态检查保证 |
| :--- | :--- | :--- |
| **逻辑位宽 vs 存储大小** | `u5` 的位表示宽度为 5 位（`BitVec<5>`） | 不因独立存储对齐到字节而改变逻辑位宽，填充位不混入位表示 |
| **字面量范围检查** | `uN` / `BitVec<n>` 要求 $0 \le \text{val} < 2^n$ | 越界字面量在编译期报错，免于发生隐式截断 |
| **扩宽转换 `.as(uM)`** | 当 $m \ge n$ 时合法 | 高位自动补 0，按无符号编码转换 |
| **窄化截取** | 禁止 $m < n$ 时直接 `.as(T)` | 必须先通过 `bits[lo..hi]` 显式切出目标位段 |
