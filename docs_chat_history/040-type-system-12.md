## 一、现在已经可以固定什么

039 的采纳包含以下地基：

- error 行和 effect 行是不同种类的集合式行。
- 标签身份包括完整的 error/effect 实例；同一实例去重，不同参数实例允许共存。
- 行变量在一个实例内指同一个待确定的完整行；包含关系另列约束。
- 成员、缺失、相等、包含、不相交可以成为 PTC 判断。
- 开放尾部未知不是缺失；标签相等未知不能按名字或哈希强行判异。
- Closure 是环境上下文，不属于行；可达性也不因具有多个依赖就套用 ROW。
- ordinary 需要证明 requirement；相容、可满足与蕴含不能混同。
- 实现先提供可靠基础片段，再扩大覆盖；未证明不伪装成 false。

**重要区分：行对象“精确”不等于执行轨迹“精确”。** 同一个行变量必须代入同一个集合；函数签名中的集合仍可以描述允许向外暴露的可能性，不表示其中每一种行为都会发生。后者是本轮建议采用的类型解释，见审阅 1。

## 二、行代数：可以直接演绎的部分

本节记号均为数学或内部表示，**不是新增 Flurry 语法/API**。

用 k 区分 Errors、Effects；R、S、ρ 是同种行，a、b 是该种行的标签。数学上，一次确定的行是有限标签集合。行表达式可含尚待确定的变量，但这不使一个实际行包含无限成员。

| 对象 | 数学解释 |
|---|---|
| ∅ₖ | k 种类的空行 |
| {a,b}ₖ | 含两个标签的行，相同标签按语义等式去重 |
| ρ | 一个完整行参数，不等于 ∅，也不等于“所有标签” |
| R ∪ S | 普通并集，允许两边已有同一标签 |
| R ∖ H | 删除 H 中全部同身份标签后的行 |
| a ∈ R / a ∉ R | 成员 / 缺失命题 |
| R ⊆ S | 行包含，不是类型相等或转换 |
| R ⟂ S | 两行不相交 |

由集合式选择直接得到：

~~~text
R ∪ ∅ = R
R ∪ R = R
R ∪ S = S ∪ R
(R ∪ S) ∪ U = R ∪ (S ∪ U)

a ∈ R ∪ S  ⇔  a ∈ R or a ∈ S
a ∈ R ∖ H  ⇔  a ∈ R and a ∉ H

R ⊆ S  ⇔  R ∖ S = ∅
R ⟂ S  ⇔  对 R 的每个标签，它都不属于 S
R = S  ⇔  R ⊆ S and S ⊆ R

(R ∖ H) ∖ K = R ∖ (H ∪ K)
(R ∪ S) ∖ H = (R ∖ H) ∪ (S ∖ H)
~~~

它们是在各自种类内成立的数学式。Errors 的 ∅ 与 Effects 的 ∅ 不能因为都为空就不带种类地互换。

但下面这些**推不出来**：

- 行没有顺序，所以产生效应的操作可以重排。
- 行没有重复，所以一个 effect 在 runtime 最多发生一次。
- 行 R 的标签当前都没看到，所以 R=∅。
- 行包含，所以所有承载这种行的类型都必然有子类型关系。
- effect 行为空，所以程序没有内存写入、一定终止或符合 pure 承诺。
- 类型上出现两个相同限定，所以它们必然在语义上可以合并。

前两项混淆了集合描述与执行顺序/次数；最后一项还需要限定类型构造自身的等式。

### 标签身份的后果

假设 a(T)、a(U) 表示同一 effect 定义的两个参数化实例：

- 已证明 T=U，则两个标签相同，可以去重。
- 已证明 T≠U，且该参数确实参与已定义的实例身份，则可区分。
- 两者相等性未知，保留等式条件；不能按两个语法项就算两个永久不同标签。
- 同一个调用两次传入不同的普通 runtime 载荷，不自动产生两个标签；载荷不是未经声明就参与实例化的类型参数。
- 某个依赖身份只有在它本来就是 effect 实例的语义参数时才参与标签身份；不把 handler 对象地址自动加入所有 effect 的标签键。

error 标签若以错误载荷类型为身份，类型别名沿真实类型等式处理，独立 newtype 沿其独立身份处理；不能以布局相同合并。这个“错误类型为标签”的具体接合，仍在审阅 2 中确认。

## 三、必须分开的四层类型信息

| 层 | 描述什么 | 没有承诺什么 |
|---|---|---|
| 行 | 哪些标签属于一个静态集合 | 不自行规定 runtime 存储 |
| error 限定 | 正常结果与可能出现的错误之间的契约 | 不仅因行是集合就确定 tag 编码 |
| effect 限定 | 某次计算可能向外传播哪些代数效应 | 不自动表示一个惰性对象，也不自动表示已发生的执行轨迹 |
| 函数与闭包 | 调用的参数/结果、潜在 error/effect、所需环境 | 取得函数值不等于调用；Closure 不参加行并集 |

为避免表面语法替我们偷做决定，推导采用内部记号：

~~~text
Err(E,T)          正常结果为 T、错误行为 E 的限定
Eff(P,T)          结果为 T、计算具有 effect 行 P 的限定
Call(A,B;E,P;C)   参数 A，正常结果 B，调用错误 E、效应 P、环境 C
~~~

这些名字都不是新增类型构造器 API。

作者在 029 已给出的例子仍是最好的教学起点，原样保留：

~~~flurry
fn map(monad: ?T, lambda f: %C #Effs !Errs fn(T) -> O) -> #Effs !Errs ?O
where T, O, C: Type.vars.Closure, Effs: Type.vars.Effects, Errs: Type.vars.Errors {
    monad match {
        some? => f(some)#!,
        null => null,
    }
}
~~~

该例已按现行 grammar 与作者随后明确的 % 闭包、限定和调用形式核对；没有给草稿中的旧语法改一个名字后冒充新例。

它可以演绎为：

1. C 说明调用 f 需要的环境；不是 map 的第三种 effect 行。
2. Effs/Errs 把回调调用的行为信息传到 map 的结果检查。
3. null 路径不调用 f；签名仍可保留 Effs/Errs，因为静态行描述可能性。
4. 只返回 f、存储 f，和真正调用 f，必须由类型系统区分。
5. 这个例子支持“回调调用的行”这一读法，但仍不足以把所有 # 前缀与函数类型位置都作统一无条件交换。

### 审阅 1：行在函数签名中描述“可能向外出现”的行为，函数限定默认指调用的行为吗？

- A. 是。闭合行限制允许向外出现的标签，不保证全部发生；已给例子中的函数限定约束调用。构造/求出函数值的效应另计。
- B. 闭合行要求精确的最小行为集合，并为构造函数值与调用统一使用一种限定含义。需要另行解释保守分支分析及高阶返回函数时的阶段。
- C. 采用可能性解释，但 #P fn(...) 专指“产生函数值的计算”；回调调用效应必须换一种定位形式。这需要修改现有 map 的解释。

**建议答复：A。明确静态行对象的精确身份与行为上界是两个层面；不以“行精确”要求精确预测每次 runtime 执行。**

## 四、effect 分组和 error 变体为什么不必对称

较新的 effect enum 草稿把每个成员视为独立 effect。因此一个自然候选是：

- 单独 effect 定义的完整实例是一个 effect 标签。
- effect enum 的成员各有标签身份；组名在行位置展开为成员集合。
- error 行以完整错误载荷类型为标签；某个 enum 的变体仍是该错误值类型内部的取值分类。

这能解释：处理日志组的一项操作，可以只移除该操作标签；只处理某错误 enum 的一个变体，未必能移除整个错误类型标签。

这里“组名展开”只是行里的组织规则，不需要先设计一套新的运行时 effect 分派机制。组名不是再次增加的总标签，否则同一操作会同时被算成成员标签和组标签。

本轮也不把 struct/enum 的字段或变体自动改为开放记录行；当前已确认的行种类仍是 Errors 与 Effects。

### 审阅 2：采用这种不对称粒度吗？

- A. effect 以独立操作的完整实例为标签，组名展开；error 以载荷类型为标签。只有覆盖某错误类型的所有可能值，才能从 error 行移除该类型。
- B. effect 组也作为一个整体标签；部分成员处理只能保留该组，或依靠另行定义的 refinement 表达。
- C. error 也细化到变体标签；精度更高，但需重新定义非 enum 错误、变体参数和类型级错误匹配之间的关系。

**建议答复：A。符合较新 effect 分组草稿的初衷，也能保留错误作为类型化数据的模型。部分错误匹配可有路径事实，但不等于 whole error 标签已被完全消去。**

## 五、从行等式到类型等式：中间还差构造规则

集合代数本身不决定类型构造；结合较早传播草稿，我建议增加下面这些规则。以下属于**本轮候选**：

~~~text
Err(∅,T) = T
Eff(∅,T) = T

Err(E,Err(F,T)) = Err(E ∪ F,T)
Eff(P,Eff(Q,T)) = Eff(P ∪ Q,T)
~~~

若采纳，则可以继续推导同类限定的去重与顺序无关。例如两层同一 error 标签不会制造两个不同的错误层。这与保留嵌套成功/失败层的独立容器不同，必须在类型定义中明说。

但这**不**推导出：

~~~text
Err(E,Optional(T)) = Optional(Err(E,T))
Err(E,Eff(P,T)) = Eff(P,Err(E,T))
Eff(P,Fn(A,B)) = Fn(A,Eff(P,B))
~~~

上面列的是不可自动使用的等式，不是宣称它们已经被语言一概禁止。混合限定、optional 与函数箭头各有语义位置；要加入等式须有独立规则。用户可写的多种前缀次序也不能由内部为了打印方便而规定成类型相等。

同样，Type.vars.Errors / Effects 是作者确认的标记类型；它们的存在不自动证明行是一个普通可变 List 或 Set API。这里的行代数首先是类型与 PTC 的语义对象。

### 审阅 3：同类 error/effect 限定是否按上述规则合并并消去空行？

- A. 两者都采用：同类嵌套是行并集，空行是恒等；混合限定另行定义。
- B. effect 采用，error 保留层次；error 行本身去重不等于错误限定的层次消失。
- C. 暂只定义行代数，两个限定都保留构造层次，之后逐个定归一规则。

**建议答复：A。它延续传播草稿的明确初衷，且能让 repeated qualifier 对应一个合并行；不顺带加入任何跨构造交换律。**

## 六、行包含、类型拓宽与组合器

### 1. 参数化不是任意填空

区分三个对象：

| 对象 | 可以怎样使用 |
|---|---|
| 定义端由调用者选择的行参数 ρ | 按任意满足声明条件的 ρ 检查，不可偷偷把它设成含有某个标签 |
| 调用点新建的待推断变量 α | 可在实参、期望类型和声明约束下求解；不能改变被调用定义已成立的泛型承诺 |
| 某固定行表达式中的未知尾部 | 它是该表达式的剩余信息；不是默认空行或新的万能行 |

因此，一个只声明“对任意 ρ，向外行是 ρ”的定义，不能无条件额外发出标签 a。否则调用者取 ρ=∅ 就不成立。它需要已有 a∈ρ 前提，或者输出行含 {a}∪ρ。这是全称参数语义的推论，也与 2026-1-30 草稿的透传意图吻合。

同一个精确 ρ 用在两个回调位置，原则上要求二者在该位置使用同一行。若实际行不同，可能通过已定义的拓宽使用共同上界，但不能单凭“都是泛型”把相等改成包含。

### 2. 不同回调的组合

若采用审阅 1 的行为上界解释，且一个组合器除了调用两个回调没有额外相关行为，内部推导为：

~~~text
callback f:  error E₁, effect P₁
callback g:  error E₂, effect P₂
combined:    error E₁ ∪ E₂, effect P₁ ∪ P₂
~~~

只执行其中一个的条件分支，也可以用这个并集作为安全的共同上界；知道某分支不可能时可收窄。并集不会表示两支在 runtime 都执行。

注意：把一类计算的潜在行求上界，与对任意值的类型汇合不是同一操作。既有“类型不同则汇合为 Any”的规则不会在这里被悄悄替换；若上下文引导两个带错误结果进入共同目标类型，需要使用已确认或本轮选定的转换规则。

### 3. 哪些 widening 可以有依据？

给定 E⊆F，只能首先说较小错误集合包含在较大集合内；把 Err(E,T) 用在 Err(F,T) 位置，是否叫子类型、是否需要转换，是下一条类型规则。

即使允许，也不推出 ABI 一样。两个表示的 tag 或布局可能不同，转换需要保留实际标签和载荷的语义。effect 调用契约的包含检查也不自动是对所有类型启用一个通用 subtyping 引擎。

### 审阅 4：行拓宽怎样接到类型使用规则？

- A. error 行拓宽作为明确的语言内建转换规则；effect 行以“被调用行为包含于允许行为”检查。二者不自动推广为所有限定的子类型规则。
- B. error 行包含直接产生对应限定类型的子类型关系；函数调用效应仍按行为包含检查。需为错误表示的使用/转换接合定义实现契约。
- C. 只有精确同行可以直接使用；行不同要显式表达目标或适配。规则小，但组合器更常需要标注。

**建议答复：A。源/目标正常结果先要求同型，只讨论行这一维；不引入任意用户隐式转换搜索，也不替整个函数方差系统拍板。**

## 七、开放行最容易出现的错误：并集不是“新增字段”

这一节是从已采纳集合语义推出的必要细化，而非重新选择行的语义。

### 1. 普通集合并集允许重叠

~~~text
{a} ∪ ρ = {a}
~~~

至少有 ρ=∅ 与 ρ={a} 两个解。不能为了容易统一只选前者。更准确的残余关系是 ρ⊆{a}。

同理：

~~~text
ρ = {a} ∪ ρ
~~~

有有限解，恰好要求 a∈ρ。它不是“要求无限行”的普通 occurs-check 错误。

再看：

~~~text
{a} ∪ ρ = {a} ∪ σ
~~~

不能取消共同 {a} 得到 ρ=σ。取 ρ=∅、σ={a} 就是反例。

集合式标签导致这种多解不是实现瑕疵。Koka 的相关论文特意选择保留重复标签来获得另一套统一性质；Flurry 已选择去重，因此不能照搬它那套消去规则。[Koka 的行与重复标签分析](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/paper-20.pdf)

### 2. 不相交扩展才有“拆头”性质

引入**内部记号** H ⊎ τ，表示 H∪τ 且 H⟂τ。这是附有前提的表示，不是新增语言运算符。

若已知 R 包含 H，可把剩余部分定义为：

~~~text
τ = R ∖ H
R = H ⊎ τ
H ⟂ τ
~~~

于是 {a}⊎τ={a} 才能推出 τ=∅。普通 {a}∪ρ 也可以规范表示成 {a}⊎(ρ∖{a})，但必须保留原 ρ 的身份与约束；不能把 ρ 直接改成这个新尾部。

039 的“共享尾部归并、排除标签、拒绝无限递归尾部”应限于这种带不相交前提的结构表示；一般集合方程仍按集合约束处理。这样保留上一轮架构，同时补足适用条件。

### 3. 两个不相交扩展的统一

仅在 H₁/H₂ 是已确定标签集合、对应尾部不含各自头部时：

~~~text
H₁ ⊎ τ₁ = H₂ ⊎ τ₂

A = H₁ ∖ H₂
B = H₂ ∖ H₁

τ₁ = B ∪ γ
τ₂ = A ∪ γ
γ ⟂ (H₁ ∪ H₂)
~~~

这可作为新尾部 γ 的约束化解。还要保持原尾部的身份、刚性和已有约束；不能给调用者的全称参数直接赋值。标签等式未知则先分支或保留关系，不能按语法差集计算 A/B。

### 审阅 5：是否保留一般集合行约束，而不强制所有关系化为一个替换？

- A. 保留 Union/Difference 等内部行表达式与残余 PTC 约束；只在证明不相交时采用结构拆头算法。可表达组合器，但未必有唯一替换。
- B. 源语言约束只允许更窄的规范行片段；一般并集方程需额外标注或拒绝。仍不能改变去重语义，也不能把有效集合方程误报成逻辑矛盾。

**建议答复：A。能用一组约束保留全部解时，不为了获得一个“统一结果”任意丢解。相关集合统一研究也区分不同表示与算法，不能将行多态笼统等同于普通一阶项统一。[Set Unification](https://arxiv.org/pdf/cs/0110023)**

## 八、handler 的行变换：删输入，再加实际逃出的行为

先只谈类型契约，不选择 shallow/deep、词法/动态绑定或 continuation ABI。

在某处理边界内，设：

- R_in：被处理计算的输入行。
- H_covered：在这个边界确实完整处理、不再向外传播的标签集合。
- R_escape：处理子句、返回分支、恢复路径等在实际处理作用域下仍向外逃出的行。

那么候选的外部行上界为：

~~~text
R_out = (R_in ∖ H_covered) ∪ R_escape
~~~

这是有条件的类型总结式，不是独立于 handler 执行语义的完整降码算法。R_escape 必须由既有处理作用域和路径契约求得，不能猜测 handler 自身发出的同名 effect 一定被自己处理。

该式只计算行，不决定正常结果类型。原成功路径和各处理路径的结果仍按各自契约检查；handler 若改变正常结果类型，要有明确的输出契约和合法汇合/转换，不能从“删掉了一个错误标签”推出它仍返回原来的 T。恢复所需的操作结果也必须满足对应操作契约；具体 continuation 形式留 handler 主题。

### 三个具体推演

**只处理一项，自己又产生另一项：**

~~~text
R_in       = {a,b}
H_covered  = {a}
R_escape   = {c}
R_out      = {b,c}
~~~

**处理之后又向外发出同一项：**

~~~text
R_in       = {a,b}
H_covered  = {a}
R_escape   = {a}
R_out      = {a,b}
~~~

“安装 handler”不保证 a 从外部行消失。把公式误写成 (R_in∪R_escape)∖H_covered 会错误删除新发出的 a。

**开放输入：**

~~~text
R_in  = {a} ∪ ρ
R_out = (ρ ∖ {a}) ∪ R_escape
~~~

不能直接说剩余行就是 ρ，因为普通 ρ 也可能含 a。只有事先知道 a∉ρ，才能化简成 ρ∪R_escape。这正是普通并集与不相交扩展的区别。

### 部分处理与不存在的标签

error 若采用类型粒度标签，匹配一个变体、一个 guarded 分支，或仅记录消息后再传播，都未必提供“完整消去整个错误类型”的证据。effect 若采用成员标签，也要覆盖该操作的有效调用情形；handler 声明与真实消去契约不能混同。

纯集合差总是允许删除不存在的成员：R∖{a}=R（若 a∉R）。但“handler 是否允许写一个不可能命中的分支”是源码合法性/诊断政策，不能由集合恒等式自动确认。2025-5-26 草稿倾向允许；本轮不据此改控制流规则。

### 审阅 6：handler 类型契约是否采用这种有条件的剩余行模型？

- A. 是。只减去已证明完整处理的输入标签，再加入各路径实际向外逃出的行；局部匹配或 handler 的名字不单独证明消去。
- B. 首版要求每个处理边界先取得具体闭合行，再计算消去和新增；符号输入行的透传暂不接受。规则易核对，但通用 handler 更依赖实例化或标注。

**建议答复：A。错误和效应各自计算，恢复/重发的作用域规则留 handler 专题；本轮只固定类型边界，不把运行机制补造成定案。**

## 九、行推断如何与 PTC 证明分开

“存在一个行代入使签名可用”与“对当前所有允许参数，该操作都有保证”不是同一个查询。

- 定义检查中，来自 where 的行参数是刚性的；可使用声明和已成立 PTC 事实，不能给它任意补标签。
- 调用点的推断变量可以解方程、选满足约束的行，但必须保留与实参/返回类型的关联。
- 同一个参数出现多次表示相同实例，不同调用点产生独立实例。
- 若只知道某变量至少包含 {a}，它不是已知恰好等于 {a}。
- 把未约束行默认为 ∅ 会丢掉可能性；不能用这种默认值让 ordinary requirement 成立。
- 如果期望目标行是 A，而实际传播行是 R，需要证明 R⊆A；证明 Γ 与 R⊆A 一起可满足不够。

对非递归、已完成行为收集的某个局部计算，可以用并集求出一个最小可表达上界；这不等于给所有泛型参数或所有集合方程选择“最小解”。

递归调用可能产生行包含环。若只涉及正向有限标签传播，可以按 SCC/worklist 收敛局部下界；涉及差、负约束、参数化标签或任意用户 predicate 时，不能套一个无条件最小不动点算法。语义递归方程、变量替换中的循环项和数据表示环也必须区分。

### 审阅 7：存在多解或开放残余时怎样交付推断结果？

- A. 能在既有契约形式中保留的约束继续保留；需要确定的边界要求标注或更多事实，ordinary 必检项未知仍失败。不默认空行，不承诺一般单一最一般替换。
- B. 每个局部调用必须立刻求出闭合行；不完整就要求显式标注。实现容易说明，但组合器可组合性更弱。
- C. 每次都选最小行作为答案。只适合已定义的特定推断问题，若用作通用规则会改变多处参数语义。

**建议答复：A。区分推断与证明，把残余约束当成有效信息；没有获准的契约载体时要求标注，而不是发明新的隐式泛化语法。**

## 十、ROW solver 的可机械执行实现

本节为编译器引导候选，不是新语言 API。沿用 039 的解释、作用域、预算和四类查询结果。

### 1. 表示与共享信息

内部行项：带种类的有限常量、刚性变量、可解变量、Union、Difference；不相交扩展可作带不变量的优化表示。重复项结构共享，但不将两个不同泛型实例的绑定合并。

标签项记录定义/类型身份、已绑定语义参数及必要依赖。其 Eq 来自对应类型/值 theory；哈希只用于索引。标签相等事实变化时，要重新触发成员去重、lacks 冲突及待决匹配。

原子仍是 A01、A16–A18。Empty 可表达为与空行相等，不需要增加一个独立 IsEmpty 原子；lacks 是负的 Contains。

### 2. 对任意行都可靠的传播

~~~text
Contains(a,Union(R,S)) ↔ Contains(a,R) or Contains(a,S)
Contains(a,Difference(R,H)) ↔ Contains(a,R) and not Contains(a,H)

Equal(R,S)  ⇒ 对已观察的 a，Contains(a,R) ↔ Contains(a,S)
Subset(R,S) ⇒ 对已观察的 a，Contains(a,R) ⇒ Contains(a,S)
Disjoint(R,S) ⇒ 对已观察的 a，not (Contains(a,R) and Contains(a,S))
~~~

这些是数学/内部约束。双向定义只用于行项运算本身有明确语义的情况；对开放行的全称关系只实例化已观察标签，是其必要条件，不能据此宣称整体满足。

最小冲突例：a∈R、R⊆S、a∉S。传播 a∈S 后，与 a∉S 冲突，解释只依赖这三项及标签身份条件。

### 3. 有完整有限标签域时的完整片段

若 Γ 已经保证参与查询的行都包含于已知有限域 D，且 D 内标签身份已确定，可为每对 (R,a) 创建成员布尔量。

逐标签编码并集/差；行相等是各成员相等的合取，包含是逐成员蕴含，不相交是逐成员不能同时为真。其否定分别为相应反例的析取。所有行运算都在这个域内，故模型可以回译为具体有限行。

大小约为 O(|D|·N)，N 是该编码的行项与关系规模；SAT 搜索仍可指数。只需一次源模型核对即可给这一片段的反例，不声称整个 PTC 都因此完备。

**不能为了得到这个片段，偷偷假设开放行只含当前见过的标签。** 域封闭必须来自已知常量、明确上界或其他已证明约束；不能由索引表大小推断。

### 4. 开放域与负关系

当标签域未封闭，逐已知标签检查至多提供部分信息：

- 正的 Subset/Equal/Disjoint 可以向已观察标签传播必要约束。
- 负的 Subset 需要一个属于左侧、不属于右侧的合法标签见证；不能只在当前标签表中没找到就否定其可能性。
- 负的 Equal 可能由尚未观察到的额外成员见证。
- 负的 Disjoint 需要共同标签见证。
- 可在有适用条件时引入作用域正确的符号见证并继续求解；否则保留原关系和 unknown。
- 忽略尚未处理关系构成保守弱化，其 UNSAT 若解释可靠可用于证明；在有限样本域内限制开放行则可能错误删解，不能拿它的 UNSAT 当证明。

未知标签等式同样交给共享 theory 或受控布尔分支。不能在某次比较未知时永久固定两个标签互异。

### 5. worklist 骨架：伪代码，非 Flurry

~~~text
solve_rows(facts):
    check row sorts, label domains, and operation prerequisites
    register row expressions and dependency watchers
    add justified constant/algebraic simplifications to worklist

    while budget remains:
        process label equalities and row facts
        propagate membership, lacks, equality, subset, disjointness
        if contradiction:
            return conflict with premises and label-equality reasons

        use disjoint-head rewriting only when its invariant is proved
        retain general union equations and rigid parameters
        if more justified consequences: continue

        if complete finite-domain encoding applies:
            solve jointly with the relevant Boolean/label fragment
            validate the returned model or conflict
            return the corresponding result

        return unresolved relations to the PTC coordinator

    return unknown(resource_limit)
~~~

存在一轮局部无冲突不是全局 SAT；其他 theory 的事实、作用域 guards 和标签模型也必须一致。回退恢复所有由当前假设引入的标签归并、缺失事实、尾部约束和推断替换。

### 6. 应交给表示与运行时的契约

行本身不强制携带 runtime 字典。具体实例交付时，错误表示、调用目标和必要 handler 环境仍须按既有机制确定。无法确定时的动态表示必须由别处明确定义，不能由 ROW solver 自动发明。

error 拓宽若改变表示，保持实际错误标签与载荷；不能假设所有行共享 tag 编码。2025 草稿提过以类型 ID 作 tag，但它仍仅是历史实现提案。

effect 行有包含关系，不表示对应 handler 表可按同一布局任意重解释。ROW 提供哪些操作必须有处理依据的契约；绑定、恢复、unwind 等仍由 effect 系统拥有。

## 十一、用反例检查推演是否越界

以下是数学和类型契约的验收方向，本轮不声称已被 Flurry 编译器验证。

| 情形 | 必须保留的结果 |
|---|---|
| 标签实例相同出现两次 | 行只保留一个成员，runtime 调用次数不因此减少 |
| a(T) 与 a(U) 的参数等式未知 | 保留条件，不能永久去重或判异 |
| a∈R、R⊆S、a∉S | 冲突并解释三项前提 |
| {a}∪ρ={a} | 允许至少 ∅ 与 {a} 两个 ρ，不任意选解 |
| ρ={a}∪ρ | 化为 a∈ρ，不作无限行错误 |
| {a}∪ρ={a}∪σ | 不能取消共同项推出 ρ=σ |
| {a}⊎τ={a} | 有 a∉τ 前提时可得 τ=∅ |
| 两开放行对当前已知标签一致 | 不单凭此宣布相等 |
| 任意 ρ 的函数无前提额外传播 a | ordinary 不能通过；不能给刚性 ρ 补标签 |
| map 的 null 路径 | 不调用回调，签名仍可保留回调行为上界 |
| 处理输入 a 后再次向外发 a | 输出仍含 a |
| 输入 {a}∪ρ 被完全处理 a | 剩余是 ρ∖{a}，不是无条件 ρ |
| 只处理错误类型的一部分值 | 不自动从错误行删整个类型 |
| 从较小错误行拓宽 | 类型规则获准后才使用，表示转换不由行等式省略 |
| effect 行为空 | 不据此断言 pure、无内存写入或终止 |

## 二、行代数：可以直接演绎的部分

本节记号均为数学或内部表示，**不是新增 Flurry 语法/API**。

用 k 区分 Errors、Effects；R、S、ρ 是同种行，a、b 是该种行的标签。数学上，一次确定的行是有限标签集合。行表达式可含尚待确定的变量，但这不使一个实际行包含无限成员。

| 对象 | 数学解释 |
|---|---|
| ∅ₖ | k 种类的空行 |
| {a,b}ₖ | 含两个标签的行，相同标签按语义等式去重 |
| ρ | 一个完整行参数，不等于 ∅，也不等于“所有标签” |
| R ∪ S | 普通并集，允许两边已有同一标签 |
| R ∖ H | 删除 H 中全部同身份标签后的行 |
| a ∈ R / a ∉ R | 成员 / 缺失命题 |
| R ⊆ S | 行包含，不是类型相等或转换 |
| R ⟂ S | 两行不相交 |

由集合式选择直接得到：

~~~text
R ∪ ∅ = R
R ∪ R = R
R ∪ S = S ∪ R
(R ∪ S) ∪ U = R ∪ (S ∪ U)

a ∈ R ∪ S  ⇔  a ∈ R or a ∈ S
a ∈ R ∖ H  ⇔  a ∈ R and a ∉ H

R ⊆ S  ⇔  R ∖ S = ∅
R ⟂ S  ⇔  对 R 的每个标签，它都不属于 S
R = S  ⇔  R ⊆ S and S ⊆ R

(R ∖ H) ∖ K = R ∖ (H ∪ K)
(R ∪ S) ∖ H = (R ∖ H) ∪ (S ∖ H)
~~~

它们是在各自种类内成立的数学式。Errors 的 ∅ 与 Effects 的 ∅ 不能因为都为空就不带种类地互换。

但下面这些**推不出来**：

- 行没有顺序，所以产生效应的操作可以重排。
- 行没有重复，所以一个 effect 在 runtime 最多发生一次。
- 行 R 的标签当前都没看到，所以 R=∅。
- 行包含，所以所有承载这种行的类型都必然有子类型关系。
- effect 行为空，所以程序没有内存写入、一定终止或符合 pure 承诺。
- 类型上出现两个相同限定，所以它们必然在语义上可以合并。

前两项混淆了集合描述与执行顺序/次数；最后一项还需要限定类型构造自身的等式。

### 标签身份的后果

假设 a(T)、a(U) 表示同一 effect 定义的两个参数化实例：

- 已证明 T=U，则两个标签相同，可以去重。
- 已证明 T≠U，且该参数确实参与已定义的实例身份，则可区分。
- 两者相等性未知，保留等式条件；不能按两个语法项就算两个永久不同标签。
- 同一个调用两次传入不同的普通 runtime 载荷，不自动产生两个标签；载荷不是未经声明就参与实例化的类型参数。
- 某个依赖身份只有在它本来就是 effect 实例的语义参数时才参与标签身份；不把 handler 对象地址自动加入所有 effect 的标签键。

error 标签若以错误载荷类型为身份，类型别名沿真实类型等式处理，独立 newtype 沿其独立身份处理；不能以布局相同合并。这个“错误类型为标签”的具体接合，仍在审阅 2 中确认。

## 三、必须分开的四层类型信息

| 层 | 描述什么 | 没有承诺什么 |
|---|---|---|
| 行 | 哪些标签属于一个静态集合 | 不自行规定 runtime 存储 |
| error 限定 | 正常结果与可能出现的错误之间的契约 | 不仅因行是集合就确定 tag 编码 |
| effect 限定 | 某次计算可能向外传播哪些代数效应 | 不自动表示一个惰性对象，也不自动表示已发生的执行轨迹 |
| 函数与闭包 | 调用的参数/结果、潜在 error/effect、所需环境 | 取得函数值不等于调用；Closure 不参加行并集 |

为避免表面语法替我们偷做决定，推导采用内部记号：

~~~text
Err(E,T)          正常结果为 T、错误行为 E 的限定
Eff(P,T)          结果为 T、计算具有 effect 行 P 的限定
Call(A,B;E,P;C)   参数 A，正常结果 B，调用错误 E、效应 P、环境 C
~~~

这些名字都不是新增类型构造器 API。

作者在 029 已给出的例子仍是最好的教学起点，原样保留：

~~~flurry
fn map(monad: ?T, lambda f: %C #Effs !Errs fn(T) -> O) -> #Effs !Errs ?O
where T, O, C: Type.vars.Closure, Effs: Type.vars.Effects, Errs: Type.vars.Errors {
    monad match {
        some? => f(some)#!,
        null => null,
    }
}
~~~

该例已按现行 grammar 与作者随后明确的 % 闭包、限定和调用形式核对；没有给草稿中的旧语法改一个名字后冒充新例。

它可以演绎为：

1. C 说明调用 f 需要的环境；不是 map 的第三种 effect 行。
2. Effs/Errs 把回调调用的行为信息传到 map 的结果检查。
3. null 路径不调用 f；签名仍可保留 Effs/Errs，因为静态行描述可能性。
4. 只返回 f、存储 f，和真正调用 f，必须由类型系统区分。
5. 这个例子支持“回调调用的行”这一读法，但仍不足以把所有 # 前缀与函数类型位置都作统一无条件交换。

### 审阅 1：行在函数签名中描述“可能向外出现”的行为，函数限定默认指调用的行为吗？

- A. 是。闭合行限制允许向外出现的标签，不保证全部发生；已给例子中的函数限定约束调用。构造/求出函数值的效应另计。
- B. 闭合行要求精确的最小行为集合，并为构造函数值与调用统一使用一种限定含义。需要另行解释保守分支分析及高阶返回函数时的阶段。
- C. 采用可能性解释，但 #P fn(...) 专指“产生函数值的计算”；回调调用效应必须换一种定位形式。这需要修改现有 map 的解释。

**建议答复：A。明确静态行对象的精确身份与行为上界是两个层面；不以“行精确”要求精确预测每次 runtime 执行。**

## 四、effect 分组和 error 变体为什么不必对称

较新的 effect enum 草稿把每个成员视为独立 effect。因此一个自然候选是：

- 单独 effect 定义的完整实例是一个 effect 标签。
- effect enum 的成员各有标签身份；组名在行位置展开为成员集合。
- error 行以完整错误载荷类型为标签；某个 enum 的变体仍是该错误值类型内部的取值分类。

这能解释：处理日志组的一项操作，可以只移除该操作标签；只处理某错误 enum 的一个变体，未必能移除整个错误类型标签。

这里“组名展开”只是行里的组织规则，不需要先设计一套新的运行时 effect 分派机制。组名不是再次增加的总标签，否则同一操作会同时被算成成员标签和组标签。

本轮也不把 struct/enum 的字段或变体自动改为开放记录行；当前已确认的行种类仍是 Errors 与 Effects。

### 审阅 2：采用这种不对称粒度吗？

- A. effect 以独立操作的完整实例为标签，组名展开；error 以载荷类型为标签。只有覆盖某错误类型的所有可能值，才能从 error 行移除该类型。
- B. effect 组也作为一个整体标签；部分成员处理只能保留该组，或依靠另行定义的 refinement 表达。
- C. error 也细化到变体标签；精度更高，但需重新定义非 enum 错误、变体参数和类型级错误匹配之间的关系。

**建议答复：A。符合较新 effect 分组草稿的初衷，也能保留错误作为类型化数据的模型。部分错误匹配可有路径事实，但不等于 whole error 标签已被完全消去。**

## 五、从行等式到类型等式：中间还差构造规则

集合代数本身不决定类型构造；结合较早传播草稿，我建议增加下面这些规则。以下属于**本轮候选**：

~~~text
Err(∅,T) = T
Eff(∅,T) = T

Err(E,Err(F,T)) = Err(E ∪ F,T)
Eff(P,Eff(Q,T)) = Eff(P ∪ Q,T)
~~~

若采纳，则可以继续推导同类限定的去重与顺序无关。例如两层同一 error 标签不会制造两个不同的错误层。这与保留嵌套成功/失败层的独立容器不同，必须在类型定义中明说。

但这**不**推导出：

~~~text
Err(E,Optional(T)) = Optional(Err(E,T))
Err(E,Eff(P,T)) = Eff(P,Err(E,T))
Eff(P,Fn(A,B)) = Fn(A,Eff(P,B))
~~~

上面列的是不可自动使用的等式，不是宣称它们已经被语言一概禁止。混合限定、optional 与函数箭头各有语义位置；要加入等式须有独立规则。用户可写的多种前缀次序也不能由内部为了打印方便而规定成类型相等。

同样，Type.vars.Errors / Effects 是作者确认的标记类型；它们的存在不自动证明行是一个普通可变 List 或 Set API。这里的行代数首先是类型与 PTC 的语义对象。

### 审阅 3：同类 error/effect 限定是否按上述规则合并并消去空行？

- A. 两者都采用：同类嵌套是行并集，空行是恒等；混合限定另行定义。
- B. effect 采用，error 保留层次；error 行本身去重不等于错误限定的层次消失。
- C. 暂只定义行代数，两个限定都保留构造层次，之后逐个定归一规则。

**建议答复：A。它延续传播草稿的明确初衷，且能让 repeated qualifier 对应一个合并行；不顺带加入任何跨构造交换律。**

## 六、行包含、类型拓宽与组合器

### 1. 参数化不是任意填空

区分三个对象：

| 对象 | 可以怎样使用 |
|---|---|
| 定义端由调用者选择的行参数 ρ | 按任意满足声明条件的 ρ 检查，不可偷偷把它设成含有某个标签 |
| 调用点新建的待推断变量 α | 可在实参、期望类型和声明约束下求解；不能改变被调用定义已成立的泛型承诺 |
| 某固定行表达式中的未知尾部 | 它是该表达式的剩余信息；不是默认空行或新的万能行 |

因此，一个只声明“对任意 ρ，向外行是 ρ”的定义，不能无条件额外发出标签 a。否则调用者取 ρ=∅ 就不成立。它需要已有 a∈ρ 前提，或者输出行含 {a}∪ρ。这是全称参数语义的推论，也与 2026-1-30 草稿的透传意图吻合。

同一个精确 ρ 用在两个回调位置，原则上要求二者在该位置使用同一行。若实际行不同，可能通过已定义的拓宽使用共同上界，但不能单凭“都是泛型”把相等改成包含。

### 2. 不同回调的组合

若采用审阅 1 的行为上界解释，且一个组合器除了调用两个回调没有额外相关行为，内部推导为：

~~~text
callback f:  error E₁, effect P₁
callback g:  error E₂, effect P₂
combined:    error E₁ ∪ E₂, effect P₁ ∪ P₂
~~~

只执行其中一个的条件分支，也可以用这个并集作为安全的共同上界；知道某分支不可能时可收窄。并集不会表示两支在 runtime 都执行。

注意：把一类计算的潜在行求上界，与对任意值的类型汇合不是同一操作。既有“类型不同则汇合为 Any”的规则不会在这里被悄悄替换；若上下文引导两个带错误结果进入共同目标类型，需要使用已确认或本轮选定的转换规则。

### 3. 哪些 widening 可以有依据？

给定 E⊆F，只能首先说较小错误集合包含在较大集合内；把 Err(E,T) 用在 Err(F,T) 位置，是否叫子类型、是否需要转换，是下一条类型规则。

即使允许，也不推出 ABI 一样。两个表示的 tag 或布局可能不同，转换需要保留实际标签和载荷的语义。effect 调用契约的包含检查也不自动是对所有类型启用一个通用 subtyping 引擎。

### 审阅 4：行拓宽怎样接到类型使用规则？

- A. error 行拓宽作为明确的语言内建转换规则；effect 行以“被调用行为包含于允许行为”检查。二者不自动推广为所有限定的子类型规则。
- B. error 行包含直接产生对应限定类型的子类型关系；函数调用效应仍按行为包含检查。需为错误表示的使用/转换接合定义实现契约。
- C. 只有精确同行可以直接使用；行不同要显式表达目标或适配。规则小，但组合器更常需要标注。

**建议答复：A。源/目标正常结果先要求同型，只讨论行这一维；不引入任意用户隐式转换搜索，也不替整个函数方差系统拍板。**

## 七、开放行最容易出现的错误：并集不是“新增字段”

这一节是从已采纳集合语义推出的必要细化，而非重新选择行的语义。

### 1. 普通集合并集允许重叠

~~~text
{a} ∪ ρ = {a}
~~~

至少有 ρ=∅ 与 ρ={a} 两个解。不能为了容易统一只选前者。更准确的残余关系是 ρ⊆{a}。

同理：

~~~text
ρ = {a} ∪ ρ
~~~

有有限解，恰好要求 a∈ρ。它不是“要求无限行”的普通 occurs-check 错误。

再看：

~~~text
{a} ∪ ρ = {a} ∪ σ
~~~

不能取消共同 {a} 得到 ρ=σ。取 ρ=∅、σ={a} 就是反例。

集合式标签导致这种多解不是实现瑕疵。Koka 的相关论文特意选择保留重复标签来获得另一套统一性质；Flurry 已选择去重，因此不能照搬它那套消去规则。[Koka 的行与重复标签分析](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/paper-20.pdf)

### 2. 不相交扩展才有“拆头”性质

引入**内部记号** H ⊎ τ，表示 H∪τ 且 H⟂τ。这是附有前提的表示，不是新增语言运算符。

若已知 R 包含 H，可把剩余部分定义为：

~~~text
τ = R ∖ H
R = H ⊎ τ
H ⟂ τ
~~~

于是 {a}⊎τ={a} 才能推出 τ=∅。普通 {a}∪ρ 也可以规范表示成 {a}⊎(ρ∖{a})，但必须保留原 ρ 的身份与约束；不能把 ρ 直接改成这个新尾部。

039 的“共享尾部归并、排除标签、拒绝无限递归尾部”应限于这种带不相交前提的结构表示；一般集合方程仍按集合约束处理。这样保留上一轮架构，同时补足适用条件。

### 3. 两个不相交扩展的统一

仅在 H₁/H₂ 是已确定标签集合、对应尾部不含各自头部时：

~~~text
H₁ ⊎ τ₁ = H₂ ⊎ τ₂

A = H₁ ∖ H₂
B = H₂ ∖ H₁

τ₁ = B ∪ γ
τ₂ = A ∪ γ
γ ⟂ (H₁ ∪ H₂)
~~~

这可作为新尾部 γ 的约束化解。还要保持原尾部的身份、刚性和已有约束；不能给调用者的全称参数直接赋值。标签等式未知则先分支或保留关系，不能按语法差集计算 A/B。

### 审阅 5：是否保留一般集合行约束，而不强制所有关系化为一个替换？

- A. 保留 Union/Difference 等内部行表达式与残余 PTC 约束；只在证明不相交时采用结构拆头算法。可表达组合器，但未必有唯一替换。
- B. 源语言约束只允许更窄的规范行片段；一般并集方程需额外标注或拒绝。仍不能改变去重语义，也不能把有效集合方程误报成逻辑矛盾。

**建议答复：A。能用一组约束保留全部解时，不为了获得一个“统一结果”任意丢解。相关集合统一研究也区分不同表示与算法，不能将行多态笼统等同于普通一阶项统一。[Set Unification](https://arxiv.org/pdf/cs/0110023)**

## 八、handler 的行变换：删输入，再加实际逃出的行为

先只谈类型契约，不选择 shallow/deep、词法/动态绑定或 continuation ABI。

在某处理边界内，设：

- R_in：被处理计算的输入行。
- H_covered：在这个边界确实完整处理、不再向外传播的标签集合。
- R_escape：处理子句、返回分支、恢复路径等在实际处理作用域下仍向外逃出的行。

那么候选的外部行上界为：

~~~text
R_out = (R_in ∖ H_covered) ∪ R_escape
~~~

这是有条件的类型总结式，不是独立于 handler 执行语义的完整降码算法。R_escape 必须由既有处理作用域和路径契约求得，不能猜测 handler 自身发出的同名 effect 一定被自己处理。

该式只计算行，不决定正常结果类型。原成功路径和各处理路径的结果仍按各自契约检查；handler 若改变正常结果类型，要有明确的输出契约和合法汇合/转换，不能从“删掉了一个错误标签”推出它仍返回原来的 T。恢复所需的操作结果也必须满足对应操作契约；具体 continuation 形式留 handler 主题。

### 三个具体推演

**只处理一项，自己又产生另一项：**

~~~text
R_in       = {a,b}
H_covered  = {a}
R_escape   = {c}
R_out      = {b,c}
~~~

**处理之后又向外发出同一项：**

~~~text
R_in       = {a,b}
H_covered  = {a}
R_escape   = {a}
R_out      = {a,b}
~~~

“安装 handler”不保证 a 从外部行消失。把公式误写成 (R_in∪R_escape)∖H_covered 会错误删除新发出的 a。

**开放输入：**

~~~text
R_in  = {a} ∪ ρ
R_out = (ρ ∖ {a}) ∪ R_escape
~~~

不能直接说剩余行就是 ρ，因为普通 ρ 也可能含 a。只有事先知道 a∉ρ，才能化简成 ρ∪R_escape。这正是普通并集与不相交扩展的区别。

### 部分处理与不存在的标签

error 若采用类型粒度标签，匹配一个变体、一个 guarded 分支，或仅记录消息后再传播，都未必提供“完整消去整个错误类型”的证据。effect 若采用成员标签，也要覆盖该操作的有效调用情形；handler 声明与真实消去契约不能混同。

纯集合差总是允许删除不存在的成员：R∖{a}=R（若 a∉R）。但“handler 是否允许写一个不可能命中的分支”是源码合法性/诊断政策，不能由集合恒等式自动确认。2025-5-26 草稿倾向允许；本轮不据此改控制流规则。

### 审阅 6：handler 类型契约是否采用这种有条件的剩余行模型？

- A. 是。只减去已证明完整处理的输入标签，再加入各路径实际向外逃出的行；局部匹配或 handler 的名字不单独证明消去。
- B. 首版要求每个处理边界先取得具体闭合行，再计算消去和新增；符号输入行的透传暂不接受。规则易核对，但通用 handler 更依赖实例化或标注。

**建议答复：A。错误和效应各自计算，恢复/重发的作用域规则留 handler 专题；本轮只固定类型边界，不把运行机制补造成定案。**

## 九、行推断如何与 PTC 证明分开

“存在一个行代入使签名可用”与“对当前所有允许参数，该操作都有保证”不是同一个查询。

- 定义检查中，来自 where 的行参数是刚性的；可使用声明和已成立 PTC 事实，不能给它任意补标签。
- 调用点的推断变量可以解方程、选满足约束的行，但必须保留与实参/返回类型的关联。
- 同一个参数出现多次表示相同实例，不同调用点产生独立实例。
- 若只知道某变量至少包含 {a}，它不是已知恰好等于 {a}。
- 把未约束行默认为 ∅ 会丢掉可能性；不能用这种默认值让 ordinary requirement 成立。
- 如果期望目标行是 A，而实际传播行是 R，需要证明 R⊆A；证明 Γ 与 R⊆A 一起可满足不够。

对非递归、已完成行为收集的某个局部计算，可以用并集求出一个最小可表达上界；这不等于给所有泛型参数或所有集合方程选择“最小解”。

递归调用可能产生行包含环。若只涉及正向有限标签传播，可以按 SCC/worklist 收敛局部下界；涉及差、负约束、参数化标签或任意用户 predicate 时，不能套一个无条件最小不动点算法。语义递归方程、变量替换中的循环项和数据表示环也必须区分。

### 审阅 7：存在多解或开放残余时怎样交付推断结果？

- A. 能在既有契约形式中保留的约束继续保留；需要确定的边界要求标注或更多事实，ordinary 必检项未知仍失败。不默认空行，不承诺一般单一最一般替换。
- B. 每个局部调用必须立刻求出闭合行；不完整就要求显式标注。实现容易说明，但组合器可组合性更弱。
- C. 每次都选最小行作为答案。只适合已定义的特定推断问题，若用作通用规则会改变多处参数语义。

**建议答复：A。区分推断与证明，把残余约束当成有效信息；没有获准的契约载体时要求标注，而不是发明新的隐式泛化语法。**

## 十、ROW solver 的可机械执行实现

本节为编译器引导候选，不是新语言 API。沿用 039 的解释、作用域、预算和四类查询结果。

### 1. 表示与共享信息

内部行项：带种类的有限常量、刚性变量、可解变量、Union、Difference；不相交扩展可作带不变量的优化表示。重复项结构共享，但不将两个不同泛型实例的绑定合并。

标签项记录定义/类型身份、已绑定语义参数及必要依赖。其 Eq 来自对应类型/值 theory；哈希只用于索引。标签相等事实变化时，要重新触发成员去重、lacks 冲突及待决匹配。

原子仍是 A01、A16–A18。Empty 可表达为与空行相等，不需要增加一个独立 IsEmpty 原子；lacks 是负的 Contains。

### 2. 对任意行都可靠的传播

~~~text
Contains(a,Union(R,S)) ↔ Contains(a,R) or Contains(a,S)
Contains(a,Difference(R,H)) ↔ Contains(a,R) and not Contains(a,H)

Equal(R,S)  ⇒ 对已观察的 a，Contains(a,R) ↔ Contains(a,S)
Subset(R,S) ⇒ 对已观察的 a，Contains(a,R) ⇒ Contains(a,S)
Disjoint(R,S) ⇒ 对已观察的 a，not (Contains(a,R) and Contains(a,S))
~~~

这些是数学/内部约束。双向定义只用于行项运算本身有明确语义的情况；对开放行的全称关系只实例化已观察标签，是其必要条件，不能据此宣称整体满足。

最小冲突例：a∈R、R⊆S、a∉S。传播 a∈S 后，与 a∉S 冲突，解释只依赖这三项及标签身份条件。

### 3. 有完整有限标签域时的完整片段

若 Γ 已经保证参与查询的行都包含于已知有限域 D，且 D 内标签身份已确定，可为每对 (R,a) 创建成员布尔量。

逐标签编码并集/差；行相等是各成员相等的合取，包含是逐成员蕴含，不相交是逐成员不能同时为真。其否定分别为相应反例的析取。所有行运算都在这个域内，故模型可以回译为具体有限行。

大小约为 O(|D|·N)，N 是该编码的行项与关系规模；SAT 搜索仍可指数。只需一次源模型核对即可给这一片段的反例，不声称整个 PTC 都因此完备。

**不能为了得到这个片段，偷偷假设开放行只含当前见过的标签。** 域封闭必须来自已知常量、明确上界或其他已证明约束；不能由索引表大小推断。

### 4. 开放域与负关系

当标签域未封闭，逐已知标签检查至多提供部分信息：

- 正的 Subset/Equal/Disjoint 可以向已观察标签传播必要约束。
- 负的 Subset 需要一个属于左侧、不属于右侧的合法标签见证；不能只在当前标签表中没找到就否定其可能性。
- 负的 Equal 可能由尚未观察到的额外成员见证。
- 负的 Disjoint 需要共同标签见证。
- 可在有适用条件时引入作用域正确的符号见证并继续求解；否则保留原关系和 unknown。
- 忽略尚未处理关系构成保守弱化，其 UNSAT 若解释可靠可用于证明；在有限样本域内限制开放行则可能错误删解，不能拿它的 UNSAT 当证明。

未知标签等式同样交给共享 theory 或受控布尔分支。不能在某次比较未知时永久固定两个标签互异。

### 5. worklist 骨架：伪代码，非 Flurry

~~~text
solve_rows(facts):
    check row sorts, label domains, and operation prerequisites
    register row expressions and dependency watchers
    add justified constant/algebraic simplifications to worklist

    while budget remains:
        process label equalities and row facts
        propagate membership, lacks, equality, subset, disjointness
        if contradiction:
            return conflict with premises and label-equality reasons

        use disjoint-head rewriting only when its invariant is proved
        retain general union equations and rigid parameters
        if more justified consequences: continue

        if complete finite-domain encoding applies:
            solve jointly with the relevant Boolean/label fragment
            validate the returned model or conflict
            return the corresponding result

        return unresolved relations to the PTC coordinator

    return unknown(resource_limit)
~~~

存在一轮局部无冲突不是全局 SAT；其他 theory 的事实、作用域 guards 和标签模型也必须一致。回退恢复所有由当前假设引入的标签归并、缺失事实、尾部约束和推断替换。

### 6. 应交给表示与运行时的契约

行本身不强制携带 runtime 字典。具体实例交付时，错误表示、调用目标和必要 handler 环境仍须按既有机制确定。无法确定时的动态表示必须由别处明确定义，不能由 ROW solver 自动发明。

error 拓宽若改变表示，保持实际错误标签与载荷；不能假设所有行共享 tag 编码。2025 草稿提过以类型 ID 作 tag，但它仍仅是历史实现提案。

effect 行有包含关系，不表示对应 handler 表可按同一布局任意重解释。ROW 提供哪些操作必须有处理依据的契约；绑定、恢复、unwind 等仍由 effect 系统拥有。

## 十一、用反例检查推演是否越界

以下是数学和类型契约的验收方向，本轮不声称已被 Flurry 编译器验证。

| 情形 | 必须保留的结果 |
|---|---|
| 标签实例相同出现两次 | 行只保留一个成员，runtime 调用次数不因此减少 |
| a(T) 与 a(U) 的参数等式未知 | 保留条件，不能永久去重或判异 |
| a∈R、R⊆S、a∉S | 冲突并解释三项前提 |
| {a}∪ρ={a} | 允许至少 ∅ 与 {a} 两个 ρ，不任意选解 |
| ρ={a}∪ρ | 化为 a∈ρ，不作无限行错误 |
| {a}∪ρ={a}∪σ | 不能取消共同项推出 ρ=σ |
| {a}⊎τ={a} | 有 a∉τ 前提时可得 τ=∅ |
| 两开放行对当前已知标签一致 | 不单凭此宣布相等 |
| 任意 ρ 的函数无前提额外传播 a | ordinary 不能通过；不能给刚性 ρ 补标签 |
| map 的 null 路径 | 不调用回调，签名仍可保留回调行为上界 |
| 处理输入 a 后再次向外发 a | 输出仍含 a |
| 输入 {a}∪ρ 被完全处理 a | 剩余是 ρ∖{a}，不是无条件 ρ |
| 只处理错误类型的一部分值 | 不自动从错误行删整个类型 |
| 从较小错误行拓宽 | 类型规则获准后才使用，表示转换不由行等式省略 |
| effect 行为空 | 不据此断言 pure、无内存写入或终止 |
