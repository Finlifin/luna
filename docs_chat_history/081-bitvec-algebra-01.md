## B1. BitVec 的值、阶段和零宽度

**建议 A：固定宽度的值类型，编译器保留其代数结构。**

`BitVec<N>` 在语义上是 N 个已定义比特组成的值，没有自带的有符号解释。N 是 comptime 参数；定义检查时可以尚未具体，交付实例时确定。比特内容可以来自 runtime，不能因为编译器掌握表达式结构就当成 comptime 已知值。它可以作为普通函数参数、结果和字段，且支持 Copy；这只复制比特，不复制原对象的资源资格。

建议允许 N=0：空位串只有一个值，是拼接的单位元；空切片不必单独分支。外部求解器不必支持零宽度：进入正宽度 BV 后端前消去空拼接、空比较和空切片即可。现有 PTC BV solver 的正宽度准入要求无需改成任意宽度。

- **A（建议）**：上述值语义，N≥0，允许空位串。普通调用边界可以物化值；是否物化由合法优化决定。

- **C**：BitVec 只是一种 comptime 映射描述；含 runtime 输入的描述不能按普通 runtime 值保存、传递，须在指定出口生成代码。需要把阶段及出口限制写入本章。

## B2. 比特顺序、宽度与字节序

**建议 A：数字从低位编号，拼接左侧占高位。**

约定 index 0 为最低有效位；`a ++ b` 中 a 位于高端、b 位于低端；模式文本从高位写到低位。因此 8 位的 0xAF 与 0x3C 拼接后得到 16 位的 0xAF3C，与宿主装载这个整数时采用的字节序无关。

位宽来自被观察的位表示：例如 u5 是 5 位，不因单独存储可能占一个字节就自动膨胀为 8 位。聚合的字段位置与填充仍由其表示契约给出，不能从字段声明顺序猜测。聚合的原始存储观察见 B6。

下面是 A 下的教学例，使用既有语法；不是当前编译器可运行性声明：

```flurry
use std.prelude.*;

pure fn join_bytes(high: u8, low: u8) -> u16 {
    (high'bitvec ++ low'bitvec).as(u16)
}

test {
    println("{}", join_bytes(0xAF, 0x3C));
}
```

预期十进制输出为 44860。

- **A（建议）**：上述顺序。内存中的字节序在读取／写入表示时处理，不改变已经得到的位向量运算。
- **B**：位串使用从左到右的序列编号，index 0 为最高位；拼接仍是左接右，数值转换按该顺序解释。切片例和实现公式须改用这一编号。
- **C**：以实际存储顺序作为统一编号基础，跨字节操作随目标表示变化。低层存储观察直接，但数值切段也需要携带目标布局约定。

**预填答复：A。数值位序、模式书写顺序、内存字节序分别说明。**

## B3. 本章锁定哪些操作及求值规则

**建议 A：锁定小而完整的代数，并支持定宽切片。**

| 操作 | 建议的契约 |
|---|---|
| 有明确 BitVec 目标的整数字面量 | 检查值可由 N 位无符号编码表示；超出范围静态拒绝，不按字面量字数补出另一种宽度，也不默默截断 |
| `a ++ b` | 输入宽度 m、n，结果宽度 m+n |
| `a and b`、`a or b`、`not a` | 二元操作要求同宽，结果同宽；逐比特计算 |
| `a == b`、`a != b` | 同宽值比较，结果为 bool |
| `bits[i]` | 结果为 BitVec<1>，要求 0≤i<N |
| `bits[lo..hi]` | 半开区间，结果宽度 hi−lo，要求 0≤lo≤hi≤N |

索引可以来自 runtime；切片的结果宽度必须能在 comptime 确定，起点可以来自 runtime。边界由既有 contract/assumes 路线处理：已知非法拒绝，无法静态建立但可执行检查的条件通过既有验证机制兑现，不引入本章私有的越界规则。比如移动起点取固定 4 位不要求引入运行时长度的 BitVec；任意运行时长度的位序列则不属于这个固定宽度类型。

`and`／`or` 在 BitVec 上按普通操作数规则求值两侧、各一次，不做 bool 式短路；不能因为掩码使结果恒零就删除有可观察行为的输入计算。bool 上既有的求值契约保持其本来含义。

不新增 xor、移位或旋转关键字。异或可以由上述代数组合；定宽移位、旋转、置换可以用切片与拼接说明，库 API 留给各自接口。需要数值算术或有符号比较时，先按相应转换契约取得数值解释，不把 SMT 后端支持的全部运算自动变成源语言操作。

```flurry
pure fn different_bits(left: BitVec<8>, right: BitVec<8>) -> BitVec<8> {
    (left and (not right)) or ((not left) and right)
}

pure fn swap_bytes(word: u16) -> u16 {
    let bits = word'bitvec;
    (bits[0..8] ++ bits[8..16]).as(u16)
}
```

在 A 的契约下，swap_bytes(0x1234) 得到 0x3412；后端可以选用等价的目标指令，但该指令不是源程序的语义定义。

- **A（建议）**：采纳操作表、严格求值和允许 runtime 起点的定宽切片。
- **B**：其余同 A，但索引与切片端点均要求 comptime 已知。合成输入更简单，但动态选位需通过数值接口或其他机制表达。
- **C**：本轮只锁定字面量、拼接、布尔代数和相等；切段只走已确认的 pattern，不在本章确定下标能力。

**预填答复：A。宽度静态，内容与合法位置可以动态；输入行为不随代数化简消失。**

早期 UTF-8 草稿出现过 `r'bitvec[0..7] = z`；这只是设计意向，不能直接当成今天已经确定的别名语义。关键是暂存结果与直接写入位置的区别。[早期草稿](/home/fin/vilya/examples/2024-11-11-utf8-decoding-by-bitvec-matching.fl:22)

**建议 A：读取产生值，直接用于赋值的位置投影可以写回。**

```flurry
use std.prelude.*;

test {
    var word: u16 = 0x1234;
    let snapshot = word'bitvec;
    word'bitvec[0..8] = 0xAB;
    println("{} {}", word, snapshot.as(u16));
}
```

A 的预期输出是 `4779 4660`，即 word 变为 0x12AB，snapshot 仍为 0x1234。这里的“值”不要求真实复制或分配，只要求后续观察等价。

直接更新还必须满足原对象的访问、初始化、表示和资源契约；BitVec 不授予额外写权限。局部位写不能破坏 enum 合法编码或覆盖仍有责任的资源。重叠写入先取得右侧值，再提交更新，不能让实现的逐位写入改变后续右侧读取。实际生成的读改写范围必须交给 memory effect 分析，不能仅凭两个比特区间不同就宣称并发写入互不干扰；也不自动提供 atomic／volatile 行为。

- **A（建议）**：上述值读取与直接位置投影规则；保存下来的 BitVec 值不会继续追踪源对象。
- **B**：取视图后保留与源存储的关联，保存和传递该视图时也携带依赖；复制视图继续观察同一存储。须在类型／环境中保留这种关联，并定义怎样显式取得独立位值。
- **C**：`'bitvec` 只产生值，不支持写回投影；先计算新位串，再经合法转换整体赋值给源对象。接口较小，但不采纳早期的局部位写用法。

**预填答复：A。位置来源由 elaboration 保留；已经读出的值遵守值语义。**

## B5. `.as(T)`：扩宽与同宽位转换

两份材料留下了需要一次说清的边界：设计备忘说“cast 为相应大小的类型”，UTF-8 例又把 5+6 位的拼接直接 `.as(u32)`；你另行确认了同 size 的任意类型 unsafe bitcast。不能把三者统称为一个不带条件的“转型”。

**建议 A：无符号扩宽补零，任意类型重解释要求同宽。**

1. BitVec<N> → BitVec<M> 或无符号整数 uM，M≥N：在高端补零；相等时保留全部位。
2. M<N：不自动截断；先显式选择要保留的位段，再转换。宽度不合法是静态错误。
3. 到其他 T 的位转换：要求与 T 的规定表示位宽一致，不做数值舍入或数值转换。已由类型契约保证所有相应位型均合法、且不带额外构造责任的目标可安全交付；一般 T 使用 unsafe 边界，并承担 B6 的责任。
4. 上述行为都复用 `.as(T)` 的现有形态，不增加 `bitcast` 关键字。该词在文档中仅用于解释位转换。

```flurry
pure fn assemble_payload(high: BitVec<5>, low: BitVec<6>) -> u32 {
    (high ++ low).as(u32)
}
```

A 会把 11 位载荷补成 32 位；这解释旧 UTF-8 草稿中的写法，而不把任意类型位转换扩展成任意宽度转换。

- **A（建议）**：上述分类，同宽重解释与无符号补零分别定义，窄化须显式切片。
- **B**：所有 BitVec 的 `.as(T)` 都要求精确同宽。扩宽也必须先显式拼入零位；旧 UTF-8 示例随之修改。
- **C**：同 A，但到 BitVec／无符号整数的窄化明确保留低位、丢弃高位。操作总有结果，但 `.as(T)` 本身就允许有损转换。

**预填答复：A。保留旧载荷组装写法，同时使丢位在代码中明确可见。**

## B6. 任意对象、填充位与 unsafe 构造

这部分直接连接你已经确定的资源系统，不能只写“同样大小就可以转”。

**建议 A：BitVec 中每一位都有确定值；未定义表示不能被取视图自动洗成确定值。**

安全读取要求被实际观察的位已初始化且访问合法。整数和已定义的定宽表示直接适用；含未定义填充的对象不能直接整体读成普通 BitVec。可以观察其已定义字段，或者由底层接口在满足初始化契约后提供整段表示。不根据优化器的方便把未定义填充默认为零；unsafe 也不能把一次无效读取当成定义值。

从位串形成一般 T 时，必须满足 T 的合法编码、不变量以及必要的环境和资源资格。一个指针的地址比特相同，不证明目标仍然有效；一段 owner 的比特可被复制，也不意味着能安全地重建两个独立拥有者。任意类型 unsafe bitcast 的能力保留，但调用者须维护这些条件；需要 runtime 依赖环境的 T 也不能只凭裸位串得到环境。

直接写回同样适用：对 u16 改合法位段可以保持有效值；对带受限编码或资源字段的对象，须在重新作为该类型使用前交付其要求，不能用局部位操作绕过初始化／移动／清理规则。

- **A（建议）**：普通 BitVec 只含已定义位；完整读取含未定义填充的表示不合法。资格与责任沿原系统检查或由 unsafe 调用者承担。
- **B**：规定取视图时把填充位规范化成零，未初始化的实际字段仍拒绝。用户得到确定值，但“观察”会规范化部分表示，原始存储回环不再逐位保真。
- **C**：BitVec 可携带部分未定义位及其状态，之后按观察需求检查。表达范围更广，但相等、分支、合成等价与 Copy 都须一起定义该状态，不能直接套用普通二值位向量代数。

**预填答复：A。比特内容可以复制，访问资格和终结责任不能据此复制。**

## B7. “程序合成”承诺到哪一步

**建议 A：合法映射总有基准降码，合成负责寻找并核验更好的实现。**

“loop-free”描述的是被提取的有限映射，不要求用户整段程序无循环，也不承诺全程序最优。普通循环可逐次计算位映射；只有已经合法展开或另有依据时才合并更大的区域。代码大小、延迟或吞吐的取舍属于编译选项及后端策略，不增加源级 BitVec 属性。

已知纯位输入上的常量传播可以消去计算节点；原输入表达式的调用、失败、内存读取与清理是否能删除，继续依据运行时纯度与资源契约。合成不等于把效果留在图上当作任意可交换节点。
