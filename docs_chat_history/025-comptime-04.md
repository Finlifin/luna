## 16. 两种执行模型的资源耗尽

建议答复：B。资源充足且输入相同的对应计算，应遵守相同的值、类型及副作用语义；预算可以不同，资源耗尽均使该次必需编译时求值失败，不得自动退回 runtime 执行。诊断可以说明是 interpretation 还是 execution 的预算耗尽。

## 17. query 缓存适用范围

建议答复：A 作为用户 comptime 函数调用结果的默认准入规则：显式 pure 承诺、输入满足 comptime Eq/Hash 契约，并且全部影响结果的输入都计入键或受正确失效管理。implicit 输入若影响结果，也不能因用户没手写就从输入中消失。

依据与取舍：这是缓存边界提案，不是已确认实现。编译器自身的解析、检查等 query 不能都被要求声明成用户 pure 函数。对于包含不纯求值的外层 query，不能仅凭内部某个调用 pure 就复用整个结果；需要保存及重放可重放的可观察产物，或重新进行相应求值。ordinary/loose 和是否终止都不能替代纯性准入判断。

建议答复：B 作为实现方向。保留用户 trait 的 comptime 相契约；为缓存键执行 Eq/Hash 时，不再次经由需要同一键才能进入的缓存路径，以免自举循环。Hash 只用于定位候选，是否命中还要依照 Eq；相等输入必须有相同 Hash。

依据与取舍：作者只确认 Eq/Hash 特殊处理，具体算法是本次建议。还需要求缓存使用的相等关系保持被缓存计算的结果及可观察行为；如果函数能区分被 Eq 判为相等的两个输入，单靠 Eq/Hash 名字就不足以安全复用。键形成期间的失败应终止该次查询，不能任意当作“不相等”；持久化格式与性能策略留实现主题。

建议答复：A 的修正版。先结合子表达式的阶段、声明要求和当前上下文判断 runtime 义务；无该义务且输入已知的 comptime 部分就地执行。仅依赖未知 comptime 参数的表达式仍是 comptime，留到输入确定，不因暂时算不出而降为 runtime。显式 runtime 函数不因实参都是常量就被当作 comptime 函数执行。

依据与取舍：无 runtime 义务优先 comptime 已确认。原 A 把所有 memory effect 都视作 runtime 义务过宽：对编译时局部状态的操作不能仅因有副作用就判为 runtime。具体内存效果分类不在本题扩展。HIR 中允许多趟完成分析，无须规定一次遍历算法。

建议答复：A。子表达式可以先在 comptime 求值，再按普通跨阶段规则供 runtime 部分使用。只有实际作为 runtime 数据嵌入的结果才要求对应的 Splice/表示条件；作为 comptime 参数传入并在运行时擦除的值，不因此必须可 splice。

## 23. 隐式 interpretation 的诊断副作用

建议答复：A。外层仍生成 runtime 代码，不妨碍实际发生的 comptime 求值产生编译诊断。区分检查表达式与执行表达式：ordinary 对 inline 两分支进行检查，不意味着在条件尚未知时执行两分支中的诊断。只有控制依赖允许、输入具备的计算才实际执行。

依据与取舍：允许不纯和诊断已有依据，执行与缓存的可观察契约是建议补足。建议错误/警告作为产生它的查询结果的一部分保存，缓存命中恢复有效诊断，失效撤销旧诊断；同一有效求值记录不因内部重复访问而重复报告。独立调用如何合并展示由诊断设计细化。不把用户任意日志都当作可安全去重的诊断，也不把这个方案写成保证宿主副作用恰好一次。

## 24. Splice 方法与 RuntimeTarget

建议答复：Other，沿用作者已提出的 trait 形态；RuntimeTarget 约束跨界结果的 runtime 类型，普通值 splice 必须保证目标值具有合法的表示和初始化语义。但不能从这个关联类型直接推导出“splice 方法的整个函数体都在 comptime 执行”。

依据与取舍：作者给的方法具有 comptime 输入，却未将方法本身标为 comptime；再结合“runtime 定义不能任意在 comptime 执行”，原 A 的“可直接嵌入”不足以说明执行阶段，不能读成整个方法在 comptime 执行，B 又把普通值强行归入 CMTT。因此建议本轮只保留输入/目标类型契约，方法体执行与降码规则暂缓确认；不改 trait 签名，也不把这个未解接口描述成已可机械实现。

## 25. 自动派生 Splice 的边界

建议答复：A 加上此前已确认的拒绝条件。只在指定聚合类型上尝试，递归确认成员具有可用 Splice，并能够建立合法目标表示；共享引用、循环结构、未初始化字段和 Drop 字段继续拒绝自动派生，复杂情况引导手写。

依据与取舍：原 B 的“无递归类型”比已确认的“无循环结构”更强，不直接采用。union 的初始化成员判定、闭包捕获与目标布局若缺少足够契约，就不能声称该类型已满足自动派生条件；不靠逐字节复制猜出语义。自动派生失败也不等于此类型一概禁止自定义 Splice。

## 26. 自定义 Splice 与自动派生重叠

建议答复：A。建议把自动派生定位为缺少适用显式实现时的补全。已有唯一适用的用户实现就使用它，不额外生成一个与它冲突的自动候选；多个显式实现之间仍按 coherence 检查，自动派生不替用户解决冲突。

## 27. 单向数据流与 quote

建议答复：A。单向限制指 runtime 的实际值不能被编译器在编译时读取；quote 所处理的是可在编译期持有的符号、代码或相关表示。它不把未来的运行时内存内容变成当前可用的普通值。
