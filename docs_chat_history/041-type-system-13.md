## 二、“主流行理论”提供了哪些真正不同的选择

有文献依据的方案不止一个，不能把“主流”缩写成“照搬某一门语言”。

| 方案 | 核心对象与等式 | 对本题的作用 |
|---|---|---|
| 唯一标签行 + lacks | 标签到类型的有限映射；扩展一个标签要求尾部没有它 | 适合描述错误结果的不同分支；移除一个分支后有明确的缺失事实 |
| scoped-label 行 | 允许同标签重复；不同标签可交换，同标签的先后层次保留 | 能描述处理一层后，同种效应仍可在外层存在 |
| 一般幂等集合约束 | 成员去重；合并可重叠，差集删掉该身份的全部成员 | 可以表达行为集合，但本身没有处理层次；一般开放并集也不等于普通拆头统一 |

唯一标签行及 lacks 约束有成熟的记录/变体演算；scoped labels 则是另一条允许重复标签的路线。[Gaster–Jones：Extensible Records and Variants](https://web.cecs.pdx.edu/~mpj/pubs/96-3.pdf)、[Leijen：Extensible Records with Scoped Labels](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/scopedlabels.pdf)。

Koka 将 scoped rows 用于效应，包括允许 handler 的外部行仍含同名效应的情况；这是可借鉴的模型，不是 Flurry 必须采纳的语义。[Koka：Programming with Row-polymorphic Effect Types](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/paper-20.pdf)。

**我的首选候选：error 使用唯一标签行，effect 使用 scoped-label 行。**

理由来自两者观察对象不同。错误结果在某次返回中选择一个分支，同一错误身份不必因为经过两个 handler 就变成两种错误。效应调用则需要确定由哪一层处理；内层 handler 执行期间，同一种效应可以继续交给外层。共享“开放尾部”机制，不要求共享重复标签规则。

代价也很具体：ROW 实现有两个 mode；同类限定的归一不能全部套同一条幂等式；effect 的层次必须在降码时有证据承载。若 Flurry 不需要这种层次表达，两者均用唯一标签行也是合理选择。

### 审阅 1：选择哪一种行代数？

- **A. error 唯一标签、effect scoped labels（建议）。** 错误分支与效应处理层次分别建模；实现共享框架但保留两套扩展规则。
- **B. 两者均为唯一标签行。** 行的用户模型更统一；同名 effect 向外转发需由独立的 handler 绑定/证据机制表达，不能要求残余行永远缺失该标签。
- **C. 两者均为 scoped-label 行。** 扩展与统一更一致；必须解释两个同身份错误分支如何区分，并给错误注入/嵌入增加层次语义，不能只改求解器。

**预填答复（待你修改）：** 选 A。Errors 描述分支，Effects 描述允许的处理层次。两者分 kind，也允许扩展代数不同；不为共享求解器而给错误值引入重复层次。

下文以 A 演绎，均为条件式候选。

## 三、先把“行”与“携带行的类型”分开

以下所有角括号、箭头、Comp、Error、Split、Embed 等均为**内部数学记号或伪代码，不是新增 Flurry 类型名、关键字或 API**。特别是 Comp 不承诺可储存的计算对象、协程或运行时包装。

~~~text
Error(E, A)      成功结果为 A、错误分支由 E 描述的类型之语义记号
Comp(ε, A)      某计算产生 A，允许向外请求 ε 所描述的效应
⟨⟩ₑ / ⟨⟩𝒻     两种空行
⟨a:s | ρ⟩      在尾行 ρ 前扩展标签 a；s 是相应载荷/操作签名
ρ、ε            行参数；并非“任何行均可随用随换”
α、β、γ         本次推断新建的可赋值元变量
~~~

相应签名来自 error/effect 的声明和实例化，不是允许用户在同一名义标签下随意替换的字段类型。

### Errors：扩展要求唯一

~~~text
well_formed(⟨a:s | ρ⟩ₑ)  要求  well_formed(ρ) 且 Lacks(ρ, a)

⟨a:s, b:t | ρ⟩ₑ = ⟨b:t, a:s | ρ⟩ₑ   当 a 与 b 已知不同
⟨a:s, a:s | ρ⟩ₑ                         不是合法的唯一标签行
~~~

“两个来源都可能报 a”不要求构造两个 a 字段。合并来源时，可以把两种结果分别嵌入同一个含 a 的输出错误行。**构造唯一行的扩展操作**与**合并错误可能性的运算**要分开；前者需要 lacks，后者可以处理重叠。

### Effects：扩展保留同标签层次

~~~text
well_formed(⟨a:s | ε⟩𝒻)  不要求 Lacks(ε, a)

⟨a:s, b:t | ε⟩𝒻 = ⟨b:t, a:s | ε⟩𝒻   当 a 与 b 已知不同
⟨a:s, a:s | ε⟩𝒻 ≠ ⟨a:s | ε⟩𝒻
~~~

对不同标签，交换次序不改变它们各自的处理链。对同一标签，选中第一层、越过第一层后选中第二层，是不同的操作路由。规范化必须保留这种区别；不能先去重再试图从运行时栈猜回来。

**重复标签不是调用次数。** 同一个函数连续调用两次 a，两次都可以使用同一个 a 处理入口，不因此要求两层 a。分支中只有一边调用 a，也可以在共同的允许效应行下检查。行描述允许行为及处理关系，不精确记录执行轨迹。

## 四、标签身份：不能无条件继承文献的推断保证

Flurry 已确认的完整实例标签可以包含尚未证明相等的参数。于是两个标签是否可交换，可能依赖 TYPE、EUF、INT 等理论。

例如内部记号 a(T) 与 a(U)：若不能证明 T = U，也不能证明 T ≠ U，就既不能认定为同一标签，也不能按两个不同标签重排。将两个未知参数“先统一成相等”只是求某个实例，不能作为普遍证明。

这个交界不是文献名称可以解决的。Koka 的相关演算比较标签头时忽略类型实参，再统一对应参数；那和“完整实例本身决定标签身份”是两种选择。[Type Directed Compilation of Row-Typed Algebraic Effects，§3](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/12/algeff.pdf)。

### 审阅 2：是否保留完整实例标签？

- **A. 保留（建议）。** 已证不同的参数实例可独立存在、交换；身份未决时保留约束，接受该片段不再无条件享有固定标签统一的完整性。
- **B. 标签 key 只取声明身份，实参作为该 occurrence 的参数。** 同声明的多个 occurrence 按层次对应并统一参数；重排和推断更接近固定标签演算，但参数实例的处理选择会改变。

**预填答复（待你修改）：** 选 A。不得为使行统一确定而改变已确认的实例身份。先完整实现身份已决片段；参数等式未知时保留带依赖的约束，不假报“不相等”。

## 五、重写原第七节：以扩展与统一为骨架

### 1. “拆出一个标签”究竟返回什么

Split(a, R) 是推断/检查操作：找出当前可选择的 a，返回签名、余行及重排/选择证据。

- 对 Errors，它拆出唯一的 a，余行附有 Lacks(ρ,a)。
- 对 Effects，它拆出最前面的 a，余行仍可能含 a。
- 对已知闭行且没有 a，可以报告失败。
- 对刚性开放尾部，不知道有没有 a；没有前提证据时是未证明，不能把尾部赋成含 a 的行。
- 对可赋值的推断元变量，可以在作用域、种类、occurs 与唯一性条件通过时扩展。

它不是一个无条件可执行的“按名字删除所有 a”函数。Split 的成功还提供类型等式 R = ⟨a:s | ρ⟩；它不必额外成为新的 PTC 布尔原子。

### 2. 固定且身份已决标签的统一骨架

下面是实现候选，输入是同 kind 的行等式。它只在局部推断阶段给允许赋值的元变量产生替换；证明已量化命题时不得用替换刚性参数来使目标成立。

~~~text
UnifyRows(R, S):
    应用已有替换，核对种类与已生成的良构性义务
    若 R 与 S 已相等：成功
    若一侧为可赋值元变量：执行 Bind；返回
    若两侧为空：成功
    若闭空行与扩展行相等：冲突
    若 R 是 ⟨a:s | ρ⟩：
        保存当前 tail(ρ) 作为本次 expose 的保护尾部
        在 S 中 expose 第一个 a；传入该保护尾部，失败或残余向上传递
        expose 只能越过已证不同的标签
        对应签名送交类型等式检查
        在更新的替换下，递归统一两个余行
    若需要展开刚性尾部、计算未归一标签、或选择未知标签等式：
        返回残余 obligation 及依赖，不猜测

Bind(α, R):
    验证 α 是本次允许求解的元变量
    验证 kind、occurs-check、作用域与参数逃逸限制
    唯一行模式下，把 α 携带的 lacks 约束传播到 R
    记录可回滚的替换及其原因

Expose(a, R, protected_tail):
    匹配行头 a：返回头签名、余行和选择证据
    行头 b 已证与 a 不同：递归并记录交换证据
    遇到闭空行：失败
    遇到可赋值尾变量 β：
        若 β 是 protected_tail：报告该结构统一冲突
        否则取得 a 的实例签名 s，新建余行 γ，经 Bind 令 β = ⟨a:s | γ⟩
        唯一行模式下生成并传播 Lacks(γ,a)
    遇到刚性尾部或标签身份未决：返回残余
~~~

“保护共同尾部”不能省略。scoped-label 行统一文献的重写算法专门有这个终止条件；普通 occurs-check 不能独自阻止不断扩展共同尾部的循环。[Scoped Labels，§7.1](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/scopedlabels.pdf)。

对 Flurry 的补充要求是：所有替换、lacks 传播和交换依据受 PTC 分支管理；撤回标签不等前提时，必须一并撤回依赖它的行结论。标签比较本身的求解成本不计为常数。

### 3. 三个必须能机械检查的例子

均为内部数学式，a 与 b 已知不同；涉及 α 的例子假设 α 是可赋值元变量。

~~~text
⟨a | α⟩ = ⟨a⟩
    α = 空行；scoped 模式也不能说“α 还可再含一个 a”

α = ⟨a | α⟩
    有限扩展行没有解；occurs-check 拒绝

⟨a | α⟩ = ⟨b | α⟩
    有限行没有解；不能反复扩展共同尾部 α 来“接近解”
~~~

两个不同的可赋值尾部则可有通常的共享余行解：

~~~text
⟨a | α⟩ = ⟨b | β⟩
    α = ⟨b | γ⟩
    β = ⟨a | γ⟩
~~~

唯一标签模式还须把两侧已有的 lacks 要求传播到 γ；scoped 模式无需为了扩展本身生成 lacks。若 α、β 是定义端的刚性参数，上式只是一项需要前提支持的关系，不能执行这些赋值。

链表式 expose 对 n 个显式标签的朴素重复扫描可达平方量级，此外还有签名统一、label identity 和约束传播成本。闭行可以索引；scoped 模式每个 key 的 occurrence 序列仍必须保序。这里不宣称整个 Flurry 行约束系统具有多项式完整求解。

## 六、组合计算：共享允许行，不按调用次数拼接

采用 scoped rows 后，顺序执行两个计算不能机械地把两个行首尾相接。连接会保留重复层次，而重复执行并不新建 handler。

建议在检查组合器时选定共同的允许行 ε，再把各子计算检查到 ε；有开放类型方案时，通过实例化与行统一保留必要标签。

~~~text
f 的调用允许行：⟨a | α⟩
g 的调用允许行：⟨b | β⟩
组合器采用共同允许行：ε

要求：
    ε = ⟨a | α⟩
    ε = ⟨b | β⟩

当 a ≠ b 且 α、β 可推断：
    ε = ⟨a,b | γ⟩
~~~

若 f 与 g 都只要求同一层 a，二者可在 ⟨a | γ⟩ 下执行，不会从次数得到 ⟨a,a | γ⟩。这种共享允许行的检查方式可参考 Koka 的推断规则；本稿把它作为 Flurry 的候选检查策略，而不引入其全部多态推广规则。[Koka 2014，§3](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/paper-20.pdf)。

还必须处理一个现实边界：**固定闭行不是开放类型方案**。固定要求 a 的计算与固定要求 b 的计算，不能只靠统一这两个不同闭行就组合成功。需要把各自的请求嵌入共同环境；这是有路由证据的适配，不是把两个类型宣告相等。

对于 effect，嵌入证据需指出每个已有 occurrence 对应目标的哪一个处理入口。不能增加同名层后随意改为调用另一个 handler。Errors 的分支嵌入则保留错误身份与载荷，不要求这种 handler 层次映射。

两个刚性开放行要组合时，可显式声明共同环境及嵌入 requirement，或保留可交付的约束；不能擅自给两者填尾，也不能为了得到一个答案把它们都改成空行。这里也不修改一般类型 join 的已确认规则。

### 审阅 3：组合与拓宽的基础路线？

- **A. 共享允许行 + 结构统一；需要时使用带证据的嵌入（建议）。** 常用开放参数走简单推断；闭行与独立行组合有明确适配契约，不能把存在某个适配当作已有唯一适配。
- **B. 包含/子效应约束作为主要机制。** 直接描述“允许更多行为”；需另外定义重复标签的匹配、多个嵌入的选择与 handler 路由一致性。
- **C. 任意行合并表达式作为主要机制。** 能直接保留两行的组合结果；需先为 effect 定义合并如何区分共用处理入口与新增层次，推断不再只靠扩展统一。

**预填答复（待你修改）：** 选 A。开放行优先共享环境；固定闭行或独立刚性行需要有证据的适配。effect 嵌入保留已有处理入口；无唯一或已声明路由时，不由求解器任选。普通行拓宽不自动升级为一般类型子类型规则。


## 七、重写原第八节之一：error 消去是分支处理

先讨论单个错误标签 e。输入行分解为 ⟨e:P | ρ⟩，其中 Lacks(ρ,e)；P 是这一错误的载荷。**输入余行 ρ 与 handler 输出错误行 σ 是两个对象。**

~~~text
输入：                 Error(⟨e:P | ρ⟩, A)
处理 e 的分支：        P → Error(σ, B)
处理成功结果的分支：   A → Error(σ, B)
未处理分支的要求：     EmbedError(ρ, σ)
输出：                 Error(σ, B)
~~~

这给出可执行的三路规则：

1. 输入成功携带 A：执行成功分支。
2. 输入是 e：执行对应错误分支。
3. 输入是 ρ 中其他错误：保留标签和载荷，经嵌入证据交付到 σ。

不需要变更成功结果类型时，取 B = A，成功分支只是已有成功值的保留。通用形式用 B 是为了把“处理器能否改变结果类型”写清，并不因此承诺当前表面语法已支持成功回调。

这个模型容许重新返回 e：σ 可以含 e，因为 Lacks(ρ,e) 约束的是**输入余行**，没有约束输出 σ。若把 σ 强行等同于 ρ，反而会错误禁止 rethrow。处理分支生成新的错误标签 d 时，同样要求输出 σ 容纳 d。

错误处理期间调用的 effect 另在 effect 行下检查。它们不变成 error 标签；普通错误值也不因此附带恢复失败位置之后执行的 continuation。若某构造能够中止或恢复计算，那部分规则必须由相应控制机制提供。

对 guarded/部分处理，未覆盖的 e 值必须有明确去向：继续向外返回，或者该构造拒绝不完备处理。它不能在只覆盖部分载荷时，声称输出一定没有 e。

## 八、重写原第八节之二：effect handler 必须定义恢复边界

以下推导采用**候选 deep handler，分支在被处理的边界外执行**。它是一个有依据的默认设计，不是从“行类型”必然推出的选择。deep/shallow 的差别在于恢复计算时是否重新安装当前 handler。[Pretnar：An Introduction to Algebraic Effects and Handlers](https://www.eff-lang.org/handlers-tutorial.pdf)。

### 1. 先区分三个结果类型

- A：被处理的完整计算原本返回什么。
- Y：某个 effect 操作要返回给其调用点什么。
- B：整个 handler 最终返回什么。

把 continuation 写成“接收 A”会错；它应接收操作结果 Y。把 handler 分支一律要求返回 Y 也会错；那只适用于直接返回到操作调用点的受限形式。

### 2. 可恢复处理的候选类型规则

设标签 a 的某操作签名为 X → Y：

~~~text
被处理计算：   Comp(⟨a | ε⟩, A)
正常完成分支： A → Comp(ε, B)

操作分支得到：
    参数 x : X
    恢复能力 k : Y → Comp(ε, B)

操作分支整体： (X, k) → Comp(ε, B)
整个处理结果： Comp(ε, B)
~~~

这是对标准 deep handler 类型形态的借鉴；是否把 k 暴露成源码可操作对象另见审阅 5。[Type Directed Compilation of Row-Typed Algebraic Effects，§3](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/12/algeff.pdf)。

这里没有 Lacks(ε,a)。handler 消去所选的一层 a，外部仍可以有同一标签。这不是“完整删除后重新扫描函数体添回标签”，而是从一开始就让各分支、恢复能力和输出共享同一个 ε。

例如 ε = ⟨a | δ⟩，则输入允许行是 ⟨a,a | δ⟩，输出允许行是 ⟨a | δ⟩。多出来的一层为 handler 分支向外请求 a 保留位置，不表示输入主体一定执行了两次 a。

### 3. 可机械执行的处理规则

使用内部操作树记号 Done(v) 与 Request(a,x,k)，k 是请求获得结果后继续计算的数学 continuation。**这是语义表示；不承诺运行时分配操作树，不新增源码构造。** H 的操作分支与完成分支在外部 ε 下运行。

~~~text
RunH(Done(v)):
    执行 H 的正常完成分支(v)

RunH(Request(a, x, k)):     请求选中的 occurrence 由 H 处理
    执行 H 的 a 分支(x, resume_h)
    其中 resume_h(y) = RunH(k(y))

RunH(Request(b, x, k)):     请求目标不由 H 处理
    向外转发请求及相应路由证据
    对外提供的继续执行部分为 y ↦ RunH(k(y))
~~~

第三条不能转发裸 k；否则外层给出结果后，内层 handler 会从后续计算中丢失。这同样适用于“同名、但目标是更外一层”的请求。Pretnar 的操作语义明确区分处理请求和转发请求，并在 deep 模型下保留恢复中的 handler。[Handlers Tutorial，§3](https://www.eff-lang.org/handlers-tutorial.pdf)。

对 Flurry 的关键适配：请求路由由已检查的 occurrence/绑定证据决定。仅检查标签字符串，再向当前栈顶重新派发，不足以保持静态行证明的含义。

### 4. 最有区分度的一条执行轨迹

设 inner 与 outer 都能处理 a。主体的 a 目标为 inner，inner 的分支又发出一个 a：

~~~text
主体请求 a
→ inner 的分支接收
→ 分支请求 a，由外部证据送达 outer
→ outer 给出该操作需要的结果
→ inner 分支恢复主体
→ 主体再次请求 a，仍送达 inner
~~~

这条轨迹同时检验三个独立条件：分支运行在外部；恢复重新安装 inner；分支里的 a 与主体的 a 不使用同一个入口。若实现把分支请求再次派发给 inner，就会出现原规则没有声明的自处理递归。

转发也不必重新执行原来产生请求之前的副作用。它传递当前请求与恢复路径，不是从头重跑被处理函数。

### 审阅 4：默认恢复与分支作用域采用哪一种？

- **A. deep；分支在当前边界外运行（建议）。** 恢复后主体继续受本 handler 处理，分支可自然向外请求同种效应；符合上述类型与执行规则。
- **B. shallow；分支在当前边界外运行。** 恢复后的主体不自动重新安装本 handler；恢复能力携带的效应契约不同，需要程序明确安排后续处理。
- **C. deep；分支也由本 handler 递归处理。** 分支发出的同名请求默认再次进入自身；向外转发必须另有明确操作，需重新写分支行与路由规则。

**预填答复（待你修改）：** 选 A 作为可恢复处理的基础。分支在外部环境执行，恢复时重新进入当前 handler；未处理请求向外转发时仍保留恢复中的当前 handler。不把“deep”误读成“分支也自动由自己处理”。

## 九、普通效应可以直接返回，不必暴露 continuation

1 月草稿提出普通效应高效处理、不挂起恢复。它与上面的语义模型不矛盾：continuation 可以只用于说明“调用后如何继续”，并非必须成为 Flurry 程序能捕获的值。

普通直接处理可取：

~~~text
操作声明：    X → Y
处理回调：    X → Comp(ε, Y)
主体请求 a：  调用选定处理回调，取得 Y，回到原操作调用点继续
~~~

对应可恢复规则里的受限分支是：先算出 Y，然后恰好一次在尾部继续主体。编译器可以采用普通调用/返回及已解析的 handler 参数；不能仅因用了代数效应这个名称就分配、复制或外带栈片段。

可恢复形式则允许分支决定是否继续、何时继续；若还允许外带或多次继续，就分别引出环境存活与复制契约。现有行参数只记录效应关系，不能证明捕获资源可复制，也不能代替变量解构规则。

**建议的首版候选**：普通效应直接调用；若 Flurry 需要显式恢复，首版限定 continuation 至多恢复一次、不能逃出这次处理。零次恢复必须走已定义的放弃/清理路径；在相应资源契约未定义或无法证明时静态拒绝，不能静默丢弃捕获资源。它不是承诺引入 Rust 的所有权语法。

对这种受限 continuation，可以要求编译器维护内部状态：

~~~text
Available → Resumed       恢复一次
Available → Abandoned     经已检查的清理路径放弃
Resumed / Abandoned       不再允许恢复或再次放弃
~~~

互斥分支合流检查状态；把 continuation 存进逃逸对象或无法约束调用次数的参数位置应被拒绝。若以后引入可逃逸或多次恢复，则需另定生命周期、复制及清理语义，不能把这个状态机直接放宽。

### 审阅 5：这一轮把恢复能力定义到哪一档？

- **A. 普通直接处理 + 受限的可恢复形式（建议）。** 前者不暴露 k；后者至多一次、不逃逸，放弃须有清理契约。两者共享行理论，但有不同控制能力。
- **B. 首版只定义普通直接处理。** 仍完成分支、外部请求与行契约；上述 continuation 规则只作未来模型，不将可恢复能力纳入初版语言承诺。
- **C. 首版包括可逃逸或多次恢复。** 表达力更大，但必须同时确定捕获环境的有效期、允许复制的资源、放弃与异常清理；行 solver 完成不代表这一档已可交付。

**预填答复（待你修改）：** 选 A 作为设计方向。普通效应的返回是回到操作调用点，不创建源码 continuation；可恢复形式首版至多一次且不逃逸。未满足清理契约时不得交付零次恢复路径。源码如何表达这两种形式仍须按现行语法单独定稿，不采用草稿里的类型名作为现有 API。

## 十、处理粒度、覆盖与 handler 自身的行为

处理“哪些操作”和处理“某操作的哪些输入”是两个维度。

若标签按独立操作划分，完整处理 a 不要求顺便处理同组 b；若标签代表整个家族，消去家族一层就要求对该层所有成员有定义。后一种是一些效应演算的选择，不能因借用其 handler 规则而把 Flurry 的分组草稿改成家族原子。

部分输入覆盖也需要明确规则。建议缺少的分支或 guard 不成立时，编译器补上**向外转发当前请求并保留 deep 恢复路径**。只要这样的请求可能向外逃出，输出允许行必须仍容纳该标签。若没有外部处理证据，静态拒绝；不能把 guard 当成“已消去整个标签”的依据。

一个 handler 自己调用其他 effect，同样检查在输出 ε 中；自己再次调用 a 则要求输出 ε 有可用的外层 a。handler 的选择、构造或安装表达式若发生行为，也由所在表达式规则检查，不能因为 handler 能消去主体的 a，就把它们提前抹掉。

### 审阅 6：标签粒度与不完备覆盖怎样定？

- **A. effect 按独立操作实例；不完备覆盖生成向外转发（建议）。** 组名只展开成员；每个已安装入口都有“处理或转发”的完整行为，输出保留可能外逃的标签。
- **B. effect 按独立操作实例；声明处理某标签就必须穷尽它的输入。** 缺臂或未证明穷尽的 guard 静态拒绝，另由显式转发构造表达过滤式 handler。
- **C. effect 按家族实例；消去一层要求整个家族完整覆盖。** 接近家族签名演算；部分成员处理必须保留整个家族或另设接口，改变草稿的独立成员方向。

**预填答复（待你修改）：** 选 A。error 标签继续按错误类型的完整实例；effect 标签按独立操作的完整实例，组是组织方式。缺失覆盖默认转发，但转发需有外部证据并保留恢复边界。行的“消去一层”不等于“从此不会再逃出同名效应”。

这一选择不决定模式匹配的全局穷尽算法；本章只消费 MATCH 已证明的覆盖结论。编译器不能证明 guard 完备时，按仍可能转发检查。


## 十一、同类限定的归一必须随行代数重审

040 曾建议 error/effect 同类限定都按幂等并集合并。若选择本轮 A，就不能原样保留该建议。

本节只使用现行 grammar 已有的前缀形态；R、S、E、F 表示合适种类的行表达式，a 表示单个 effect 实例，T 表示被限定类型。**下面是这些既有形态的语义候选，并非已定规则。**

| 表面片段 | 候选解释 |
|---|---|
| #a #a T | 两层同名 effect，不能归一成一层 |
| #R #S T | 在同一限定层中，先保留 R 的 occurrence，再接 S；同标签不得交换先后 |
| !E !F T | 合并可能的错误分支；重叠错误身份只保留一个分支，载荷按该身份确定 |
| 空行限定 | 候选消去该限定；不据此推导全程序纯性、终止或无内存行为 |

error 前缀的重叠合并先形成唯一分支行，不是先构造一个非法重复行再忽略错误。这与第三节严格扩展需要 lacks 的规则分属不同操作。

这里 effect 行的连接用于描述**类型里明确存在的层次**；第六节顺序执行两个计算仍共享允许环境，不使用这条连接替代组合检查。

在内部，候选的连接满足“空行连接 S 得到 S；扩展 a 的行连接 S，就保留 a 并递归连接余行”。若左侧是未知开放行变量，不能擅自把它展开成已知前缀，连接项可能需要保留。error 的重叠合并同样可能保留约束。

因此采用这条表面规则有一个真实代价：普通行统一不覆盖任意两个开放行的连接/合并方程。我们可以给这些项可靠的局部化简与具体求值契约；不能一面保留它们，一面宣称所有行关系都化为简单统一。

跨种类限定顺序仍不由本轮两套行代数自动决定；尤其不能从它们“都带一个行”推导 error/effect 限定可任意交换。当前内部 Error / Comp 的写法不是跨限定归一公理。

### 审阅 7：表面 effect 前缀是否忠实保留重复层次？

- **A. 保留（建议）。** #a #a T 表示两层；error 的同类合并继续按唯一分支解释。任意开放行的连接/合并可以留下约束，不冒充普通统一。
- **B. 表面 effect 前缀只收集去重的允许标签。** scoped 层次只在另一套绑定/内部信息中表达；需再提供完整类型如何显示、反射与约束这些层次的契约，单靠该前缀不足以表达全部行。

**预填答复（待你修改）：** 选 A 作为归一方向。effect 前缀保留 occurrence，error 前缀合并分支。空行限定可消去；跨种类限定的交换不在此次确认范围。开放行连接/合并作为带定义的项处理，不让普通统一任意猜解。

## 十二、handler 能否改变整个结果类型

第七、八节用 A 与 B 分开写，是为了暴露一个容易被简写掩盖的接口决定。原计算结果 A、操作返回 Y、handler 结果 B 各有职责；即使最终限制 A = B，也不能把 Y 混入其中。

### 审阅 8：是否允许 handler 改变结果类型？

- **A. 保留结果为默认；显式定义成功路径转换时允许 A → B（建议）。** 错误/操作分支、正常完成分支和恢复后的结果均检查到同一个 B；没有成功路径转换时不能凭某个分支猜出改变。
- **B. handler 一律保留 A。** 类型与表面形式更简单；结果转换另在处理结束后做，可恢复能力的结果也是 A，失去直接改变整个处理结果的能力。

**预填答复（待你修改）：** 选 A。默认 A = B；改变结果类型必须有可检查的成功路径转换。操作返回 Y 仍由操作声明决定。先确定这个契约，具体成功分支形式待现行语法专题确认，不新增本轮源码语法。

## 十三、PTC 原子目录怎样调整

本轮不需要把 039 的 PTC 引擎推倒；需要撤下“所有行都是集合”的默认解释。下面是与主候选匹配的实现调整，尚未写入正式文档。

| 入口 | Errors | Effects |
|---|---|---|
| Eq | 唯一标签行的结构等式与 lacks 良构性 | 保留重复 occurrence 的行等式 |
| A16 RowContains | 某错误身份存在；负文字是 lacks | 某身份至少有一层；该布尔事实不能单独确定调用哪层 |
| A17 RowSubset | 可继续表示分支域包含；变成类型嵌入仍需独立规则与证据 | 暂不沿用集合解释；作为通用公开原子先撤出首版承诺，待需要的 occurrence 关系明确后再定 |
| A18 RowDisjoint | 可保留无共同错误身份的可选关系 | 标签支撑集互斥可以有数学意义，但 handler 正确性不依赖它；不把它作为 scoped 核心要求 |
| Split | 返回余行、签名、等式和缺失证据 | 返回最前 occurrence、余行及选择证据 |
| 行扩展 | 构造项并检查唯一性要求 | 构造项并保留新 occurrence |
| Embed | 保持错误身份与载荷的分支适配 | 保持已有处理入口的 occurrence 适配；不能退化成布尔 Contains |
| 连接 / 合并 | 错误分支重叠合并的项契约 | 有序保留同标签的连接项契约；不用于按调用次数合并 |

“原子”“项运算”“推断操作”“降码证据”仍需区分。行扩展是项构造，Split 是产生等式和见证的操作，Embed 可由待检查的证据及其契约描述；没有理由为了凑齐目录把每一步都额外制造一个互不解释的布尔原子。

### theory solver 的交付边界

1. **固定标签的结构片段。** 提供有限行等式统一、闭行成员/缺失、唯一行的 lacks 传播、scoped 行的首层选择。对刚性参数只使用给定关系，不执行推断赋值。
2. **与其他 theory 的接合。** 标签/签名等式经受审计的 TYPE、EUF 等接口处理；参数计算未决时挂起依赖。恢复 worklist 时重新检查排序与匹配前提。
3. **较复杂行项。** 连接/合并在可见前缀或具体参数上化简；一般开放关系可以保留。不得将“还没拆出来”作为逻辑否定，也不能因为统一失败就把任意扩展语言里的公式判为 unsat。
4. **证明查询。** 正文字、负文字及行等式带原因回传布尔层；分支假设的依赖在回滚时撤销。模型若忽略未解释的行项，只能作为候选，不能报告为已验证反例。
5. **阶段契约。** ordinary 下 requirement 必须被当前事实蕴含；允许在 loose 阶段保留的义务按已确认规则在实例交付前兑现。本轮不新增“行未知就可运行”的例外。
6. **表示与降码。** 交付操作入口、转发入口与恢复边界的对应关系；可专门化为直接调用，也可由后续运行时方案携带证据。不能选定纯标签集合之后让运行时重新猜层次。

这些步骤分别有自己的成功与失败条件。完整的“row solver”不能只返回一个替换后行而丢掉前提、层次映射和残余义务。
