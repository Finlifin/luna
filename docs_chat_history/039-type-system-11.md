## 二、先区分项、原子、公式和操作

以下大写名称、公式和伪代码均为**内部设计记号，不是 Flurry 语法、标准库 API 或已确认的 IR 名字**。数学位运算也不是 Flurry 表面运算符。

| 对象 | 内部示例 | 职责 |
|---|---|---|
| 项 term | 类型值、长度、字段类型、关联类型、列表、调用结果 | 项没有真假；记录逻辑 sort、绑定身份与必要依赖 |
| 原子 atom | 类型相等、整数小于等于、trait 实例成立 | 有明确布尔含义，交相应 theory |
| 公式 formula | 否定、合取、析取、蕴含、量词 | 布尔层或量词层组合原子 |
| 操作与证据 | 名称解析、字段观察、实现选择、receiver adaptation | 有前提、结果、身份及失败；成功后提供事实，不能都压成 bool |

因此，不等是 Eq 的负文字；大小等于 8 是布局观察项的整数等式；字段类型等于某类型，是字段存在前提下的观察结果等式。不存在必要的第二套 SizeEquals、FieldTypeEquals 原子。

“当前 query 未完成”“此时知道具体值”是分析状态，不直接当作类型恒定性质。requires/ensures/assumes 是义务或事实进入系统的方式，不是 theory。forall/exists 在公式层；此前移除高阶类型语法，不等于删除布尔量词。

同名成员存在不保证可访问、来源唯一或可调用。调用需要的签名和选定来源仍由实际操作提供。

## 四、布尔层与 theory 接口

建议采用 CDCL(T)/DPLL(T) 分工：布尔层管理决策与学习，各 theory 接收文字、传播结论并解释冲突。这是架构选择，不代表采用现成 SMT 产品。[DPLL(T) 原始论文](https://homepage.cs.uiowa.edu/~tinelli/papers/NieOT-JACM-06.pdf)

更外层仍须有操作契约协调器，拥有 query 合法性、comptime 执行和源程序顺序。SAT 试探不能替代这些职责。

### 查询结果

证明 Γ 蕴含 Q，可尝试判 Γ ∧ ¬Q 不可满足。

| 结果 | 准确含义 | ordinary |
|---|---|---|
| Entailed(proof) | 当前前提下已证明 Q | 对应 requirement 通过 |
| NotEntailed(witness) | 有经原语义验证的 Γ ∧ ¬Q 模型 | 拒绝，可展示反例 |
| Unknown(reason,residuals) | 既未证明，也没有获验证的反例 | 拒绝当前必检要求，解释缺口 |
| IllFormed(diagnostic) | 命题输入/依赖/观察本身不合法 | 报其错误，不把它当 false |

NotEntailed **不是** Γ 蕴含 ¬Q。例如只知 n 非负，n 等于零可能真也可能假。要证明否定，另查 Γ ∧ Q 不可满足。

把真实函数抽象成未解释函数后，其 SAT 模型可能不可由源程序实现，只能得 unknown。只添加可靠约束的保守抽象若 UNSAT，则可用于证明。Γ 自身矛盾应标出不可能路径；逻辑上的矛盾推理不自动消除非法语法、命题良定义检查或尚需执行的 assumes。

### 最小接口：候选伪代码，非 Flurry

~~~text
register(term_or_atom, source, semantic_dependencies)
checkpoint() -> token
assert_literal(literal, reason)
propagate() -> implied_literals_with_reasons | conflict_with_reason
check_fragment() -> consistent_in_declared_fragment | conflict | unknown
explain(consequence) -> antecedents_and_rule
restore(token)
~~~

Consistent 只针对模块声明的片段，不是全局 SAT。字段类型等部分操作，必须先验证前提才产生可使用的观察项；不能给不存在字段分配任意 Type 来使操作“有定义”。

每项事实关联来源、前提、作用域、语义环境及未兑现阶段义务。要求理论传播和冲突可解释，首版不必公开通用证明对象或开发第三方 proof checker。

### 主流程：候选伪代码，非 Flurry

~~~text
prove(context, goal):
    validate well-formedness and semantic prerequisites
    lower justified semantics; retain unsupported obligations
    activate this context and query using guards
    ask Boolean engine for context AND NOT goal
    repeat within configured work budget:
        Boolean propagation
        send assigned theory literals to their owners
        collect consequences, equalities, and conflicts
        if conflict:
            learn its implication clause with required guards
            backjump and restore all affected theory state
            if query refuted at root: return Entailed
        else if a Boolean decision is needed:
            decide without executing source side effects
        else:
            request full checks within each declared fragment
            if a full check reports conflict: handle conflict as above
            if new justified consequences arrive: assert them and continue
            if justified theory split exists: add it and continue
            if jointly validated source model exists: return NotEntailed
            return Unknown with residual obligations
    return Unknown(resource_limit)
~~~

源程序 inline 分支与 solver 决策分支是两种东西：前者决定执行和生成，后者只搜索证明。solver 回溯不是执行两边源程序再回滚副作用。

## 五、11 个模块的实现骨架

以下均为候选算法与不变量，不指控到当前源码、crate 或函数。

### T1：EUF——等式与一致函数应用

负责 A01 的共享框架。对获准具有一致语义的函数应用使用同余：参数等价则结果等价；没有任意单射规则。[同余闭包原始论文](https://www.cs.upc.edu/~roberto/papers/IC06.pdf)

维护可回退的等价类、父项使用表、函数签名索引和独立解释边。合并类后重查受影响父项；同函数身份、同必要依赖、各参数同类的父项继续合并。已有不等的两项进入同类时，沿解释边生成冲突。回退同时恢复等价类、索引与附带事实。

Flurry 的接合约束：

1. 逻辑等式仅用于有等价/替换契约的对象；任意重载 Eq、缓存比较与 IEEE 浮点比较不直接混入。
2. 普通纯类型工厂按既有模型执行并复用结果；不同输入可能返回同一类型，结果相同不推出参数相同。
3. 符号调用的同余要求其语义依赖和良定义前提具备；pure 不证明终止，也不免除前提。
4. 只有另有确认的自由构造子才使用单射/不相交规则；不能套给所有尖括号调用。
5. 零阶 Tensor 与元素类型相等已有正式依据，不能采用“所有不同头都不等”。获准等式与保留形态观察分别处理。
6. Any 相容不能导致两个具体类型等价类合并。

整个模块含父项索引、解释与回退，不能拿普通 union-find 的近常数界当整体复杂度。

### 审阅 4：初版怎样组织已确认的内建类型等式？

- A. 有限、定向、带前提的重写规则配合 EUF；例如满足条件的零阶 Tensor 等式直接归约。规则单独检查适用条件，未覆盖的等式保持未决。
- B. 在等价图中对已确认等式作有预算的双向展开。可以发现更多等价形态，但项膨胀、回溯及来源形态维护更复杂，耗尽预算仍为 unknown。

**建议答复：A。先明确有限规则和前提；普通工厂的执行/缓存、保留形态匹配、语义等式继续各按已有契约。两种方案都不允许从任意工厂结果反推参数，也不开放用户逻辑公理。**

### T2：TYPE——类别、限定与结构

负责 A02–A05，使用部分描述事实，不要求先完整执行类型计算。

1. 为分类轴登记已确认蕴含/互斥关系。正事实限制候选，负事实排除类别，无法兼容时输出带前提解释的冲突。
2. 具体描述提供种类和成员；部分描述只提供契约保证。只知 tuple 不产生具体长度。
3. HasSlot 证据允许相应观察，结果项绑定同一结构与选择器身份。名称相同不等于同一声明。
4. 只有完整封闭描述可由缺项推否定；输入未知保持未完成。transactional build 不提供可观察半成品事实。
5. 限定按各自获准归一规则观察，未确认的穿透、重排、消去不加入重写表。

已知结构的一次遍历可为 O(V+E)；未知工厂执行和搜索不包含在此界内。

### T3：MATCH / REL——模式、相容、子类型

负责 A06–A09，不能只共用一个“unify 成功”结果。

匹配按模式树递归：确定域/保留头，检查获准位置与标签，为新绑定建立独立作用域身份；已有表达式引用按作者已确认的模式语义比较。成功才输出绑定与约束。不能分解的普通函数结果不逆解；不支持模式留残余。

相容使用已有通配方向与获准结构规则。经过 Any 的两次相容不组成 A、B 的等式或相容证明；Any 也不能偷换成可任意统一的推理变量。

子类型用目标驱动规则表：选已定义规则、产生前提、递归求解。循环目标在没有明示归纳/余归纳规则时未解决，不因 visited 成功。函数方差、限定拓宽、optional 注入等尚未完整定稿，本轮只保留入口，不套其他语言默认规则。

线性结构模式成本与结构大小成正比，析取/回溯另计。接收者适配仍返回实际来源及生成动作，不由 Compatible/Subtype 自动触发。

### T4：TRAIT——约束证据与实现选择

负责 A10；关联项是依赖选定证据的项。

1. 查询键包含主体、trait 身份/参数、阶段和可见实现环境；先读取已给约束证据，再索引实现候选。
2. 匹配候选头，生成并证明其前提；不得为了调用成功把待证前提直接加入 Γ。
3. 保存选定来源、成员身份及替换；关联类型从该来源产生。两个来源都叫 Output，不是同一项。
4. 参数或生成定义未决定则未决，多来源按既有选择/coherence 规则；不重开上一组查找题。
5. 用进行中/完成表避免重复搜索。进行中表示依赖环，不自动作余归纳证明。
6. 只有有效否定契约，或查询环境确实封闭且匹配穷尽，才能产生负事实；后续可能生成实现时不永久否定。

成本随候选数、子目标与递归深度变化。索引不保证任意递归实现搜索终止。

### 审阅 5：如何得到否定 trait 事实？

- A. 一般未找到/未决定是 unknown；固定且封闭环境穷尽适用候选才给否定，证据绑定该环境。
- B. 每个线性位置立即把当前可见候选视为封闭；否定事实严格绑定时点，不能跨后续生成定义复用。这需要公开时点语义。

**建议答复：A。真正完整的静态查询可判否定，未完成的参数化查询不等于没有实现。**

### T5：LAYOUT——表示性质与数值观察

负责 A11，把大小/对齐/偏移等观察结果交给 EUF/INT。

1. 依表示规则构造依赖图，区分必须取得完整内嵌表示与只需间接表示的边。指针宽度独立于 pointee 布局，沿用指针位宽等于 usize。
2. 按值表示依赖环用 DFS/SCC 检测；无获准打断规则的非法循环是布局错误，不能算成正常的 NotSized=true。
3. 输入具备则计算，部分输入只输出被契约支持的性质。runtime 依赖类型可以有固定表示，不能一概判变长。
4. 观察项绑定 target 与影响表示的属性。同一类型跨 target 的大小不是无环境全局常量。
5. 数值关系交 INT；实际布局由表示规则决定，不由算术 solver 自选。
6. 同大小不推出同类型、同对齐、任意位串合法、按位复制安全或任意转换。

固定依赖图检查 O(V+E)，执行与算术另计。输入不足返回 unknown，非法表示是 IllFormed。

### 审阅 6：is_not_sized 的否定究竟否定什么？

不是重问要不要 Sized trait，而是补齐作者已选择的谓词含义。

- A. 表示性质：对适用且合法的类型，大小不能仅由类型与 target 固定，还依赖值相关信息。参数尚未知是 unknown，不是 true。
- B. 当前能力：此时还取不到固定大小就为 true。它混合未知输入与值相关大小，必须绑定分析时点，不能当稳定类型性质。
- C. 另有含义，按骨架改写：“输入域……；true 表示……；不适用对象……；未知输入……”。

**建议答复：A。先限于具有相应表示语义的类型；仅 comptime 的描述对象若不适用，是前提不满足，不静默返回 true/false。**

### T6：INT——整数边界、线性关系与同余

负责整数 Eq、A12、可选 A13。数学整数与机器整数不直接混用。

第一层是常量折叠与差分逻辑。a − b ≤ c 编成 b→a、权重 c，加统一零点处理单变量界。负环给冲突和原约束解释；无负环的最短路可给差分界，在整数权重下给相应整数赋值。Bellman–Ford 是可核对基线，完整一轮 O(VE)。[MIT Bellman–Ford 课程材料](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/08c2314e3e4c4590bffc3409549f25eb_f9cVS_URPc0.pdf)

第二层是线性整数算术。规范化为整数系数线性和，乘法只允许一侧常数；用精确有理数线性可行性作松弛。不可行给线性矛盾解释；可行后仍检查整数性。分数赋值 x=r 可按 x≤floor(r) 或 x≥ceil(r) 的有效析取分支，配合正确整数 cuts。预算耗尽 unknown。此骨架不承诺朴素分支即可完整终止；若要完整 LIA 能力档，需采用经验证的完整程序。[Dutertre 与 de Moura 的算法讲义](https://yices.csl.sri.com/old/slides-cav06.pdf)、[Z3 算术片段说明](https://microsoft.github.io/z3guide/docs/theories/Arithmetic/)

整数 2x=1 的有理松弛可行，整数不可行。把 simplex 可行当整数模型是健全性错误。

第三层是模数为正常数的同余。a 与 r 模 m 同余可编码为 a−r=m·k，新 k 是整数见证。否定需正确余数范围或互补分支，不能随意固定 k。布局提供对齐约束，solver 不发明“所有对齐都满足某未确认规则”。

除法/余数的舍入、除零、溢出以及机器整数映射都必须接 Flurry 操作契约。SMT-LIB div/mod 有特定欧几里得定义，不能直接当语言规则；求解器的除零总函数化也不能让源程序非法操作合法。[SMT-LIB Ints](https://smt-lib.org/theories-Ints.shtml)

非线性项初版可具体执行或作有契约的未解释项，不套不可靠线性近似。浮点不转数学实数；未支持 IEEE 符号推理时只用获准的具体执行事实。

### 审阅 7：整数初版交付哪一档？

- A. 差分逻辑完整，常量线性化、一般线性与同余先可靠但可 unknown；公布基础档。复杂关系依赖显式结果契约。
- B. 首版即接经验证的完整无量词 LIA 程序/组件，PTC 协调自有；覆盖广，集成开发成本高。
- C. 仅具体计算与区间传播；实现最少，但不适合作跨变量关系的稳定基础。

**建议答复：A 作为可交付基线，B 为增强目标；如果首版必须广泛自动证明形状线性关系，可直接选 B。非线性整数不作完整判定承诺。**

### T7：SEQ——有限列表、元组结构与形状

主要处理项及 A01/A12，不新增 LengthEquals 原子。覆盖已有张量案例，不能只用“以后把列表当 UF”略过。

候选内部项包括具体列表、长度、带前提索引、头尾、已定义拼接；不是新增 meta.List API。

1. 具体有限列表直接计算，相等按长度和对应元素判断。
2. 已证明 0≤i<length(S) 且容器操作前提成立后，才使用元素观察和相应类型契约；空列表取头不返回任意项。
3. 对准入操作登记有前提的长度/元素等式，如非空尾部长度减一；不能用它的结果契约倒证同一操作的前提。
4. 长度固定且在预算内，列表相等展开为逐元素相等，不等展开为至少一个不同；长度未知保留关系。
5. 有限构造可结构递归；一般拼接方程、未知长度外延相等不承诺初版完整判定。
6. broadcastable 走 predicate 入口；获准展开才使用列表/整数规则，或在具体形状上执行。broadcast_shape 的保证来自契约或定义证明，不因函数名特殊而内置。

示意推导：S 长度 n，n≥1，合法 tail 的契约给 length(tail(S))=n−1，INT 可证尾部更短。没有提前取得任何元素，即能支持现有张量教学的降阶关系。

具体列表比较 O(n)，固定展开按元素数计费，一般序列方程不在此复杂度保证内。

### T8：ROW——error/effect 行

负责 A16–A18 和行等式。当前只确认行多态方向；下面是**集合式行候选**，必须经审阅 8 选择后才作为 Flurry 规则。Closure 不在这里。

若标签唯一，可用已知标签及开放尾部表示：

1. 共同标签的参数/载荷按已定义关系送 Eq 等 theory；不能只比打印名。
2. 命中已知标签给 Contains，封闭行确定缺失给负文字；开放尾部记录成员/排除约束。
3. 行等式先匹配共同标签，把剩余标签推给对方尾部。两边开放可引入共享尾部及标签排除约束；有限行模型不接受无限递归尾部。
4. Subset 把左侧已知成员推给右侧，另保留尾部包含边；不能只检查当前可见成员就宣布开放行包含。
5. Disjoint 使一侧成员成为另一侧 lacks；未知尾部间仍保留关系。lacks 是否定，不是没看见。
6. 扩展、并合、handler 消去为带契约的项运算；消去哪个参数化实例，由标签定义决定。

若标签身份含符号参数，标签等式也可能未知：应将匹配分支交给布尔层或保留残余，不能哈希成两个永久不同键。固定已知标签可索引归并；开放尾部和参数求解另计。

### 审阅 8：行标签身份与重复怎样处理？

- A. 集合式，完整 error/effect 实例为键；同实例去重，不同参数实例可共存。实例等式可能需求解。
- B. 集合式，声明身份为键、参数为载荷；同声明重复须协调参数，不能并存不同参数实例。
- C. 有序或多重行，保留重复；须定义顺序/重数和消去哪一次，集合式算法不直接适用。

**建议答复：A 作为候选，error/effect 分别确认；行变量先指一个待确定的完整行，包含另写关系。若 handler 设计要求 B/C，按其设计改写。**

### T9：BV——定宽位向量与模式集合

负责 A14/A15 及定宽 A01/A07。位运算产生项，比较才产生原子；宽度未知不造“任意宽 BV”。编码可核对 SMT-LIB，但仍须匹配 Flurry 操作语义。[SMT-LIB FixedSizeBitVectors](https://smt-lib.org/theories-FixedSizeBitVectors.shtml)

第一档是纯掩码快路径。模式用同宽 mask/value 表示，先规范化无关 value 位。两个纯掩码不相交，当且仅当共同固定位有相反要求，即数学式：

~~~text
((v₁ XOR v₂) AND (m₁ AND m₂)) ≠ 0
~~~

这是数学位向量式，不是 Flurry 运算符。额外 guard 存在时，掩码无冲突不证明完整模式有交集。

第二档把获准定宽操作布尔化为电路交 SAT，或用局部后端。相交检查存在同时匹配的位串；互斥是其 UNSAT。覆盖检查在 base type 的**合法编码域**内是否存在一个全不匹配的位串，不能遗漏合法性约束。

反例给具体位串与匹配条件。未知宽度、任意 predicate guard、跨元素 DST 解析不自动进完备片段；一般解析仍留已约定的程序合成主题。

掩码比较 O(w)，p 个模式朴素两两检查 O(p²w)。布尔电路规模依操作变化，简单加法/比较可线性，朴素乘法可平方；SAT 最坏指数，宽度有限不等于成本小。

### 审阅 9：BV 首版覆盖到哪里？

- A. 先覆盖 enum/模式独立判定，掩码与明确的定宽布尔片段，可用局部后端；未知宽度与一般解析不承诺完整。
- B. 同期接入全部机器整数符号运算；须先接齐溢出、移位、符号转换等契约，范围更大。

**建议答复：A。先兑现已讨论的模式互斥/覆盖需求，B 是后续扩展。**

### T10：PRED——可执行 predicate

负责 A19。准入需说明良定义域、重复引用是否同一命题、具体输入下怎样执行。

1. 获准内建/契约可展开为核心公式；部分定义只有在前提成立时展开。
2. 用户 predicate 可保留稳定原子身份，使用 Γ 已给正负事实；允许展开时只翻译支持的体内操作。
3. 循环、递归、一般 comptime 程序超出能力时停止展开并保留残余，返回 bool 不保证可 SMT 化。
4. 参数具备时在源语义允许的阶段执行；assumes 失败仍为实例化错误。SAT 试探不提前运行不纯操作。
5. 身份含定义、绑定实参及必要依赖；可能随未记录状态变化的两次调用不能合成同一逻辑命题。
6. 任意 inline bool 不可提取时，按现有文档不提供新的语义路径事实；不能默默升级成稳定 A19。

pure 是已有可信承诺，不新增自动纯性验证。这里要确认 predicate 的准入纪律，不重问可执行性。

### 审阅 10：predicate 是否要求稳定逻辑含义？

- A. 同一完整语义输入/依赖表示同一命题；采用合适纯性承诺或显式依赖。一般状态相关 bool 可做 inline 条件，但不自动取得逻辑 predicate 身份。
- B. 允许每次执行状态改变含义；原子必须带状态/事件身份，不能跨求值复用事实，须另定该身份契约。

**建议答复：A。稳定不等于可判定，也不要求证明终止；只是不能把可能不同的执行强行当同一命题。**

### T11：量词层

量词不是新增原子。建议基本能力：

- 完整已知有限域：forall 展合取，exists 展析取；空域分别真/假。当前见过几个类型不是 Type 全集。
- 全称目标：用新鲜不逃逸的任意参数证明，不能选一个方便的具体类型代替。
- 存在目标：给出并检验见证，没找到见证不是假。
- 全称前提：合法实例化，保持绑定与前提；可增加有预算的触发匹配。
- 取反时正确处理量词；见证依赖不能逃出作用域。递归造项超预算 unknown。

有限次实例化一般不能证明剩余所有实例都满足。E-matching 可作后续机制，其触发策略不替代证明。[Programming Z3：量词实例化](https://theory.stanford.edu/~nikolaj/programmingz3.html)

### 审阅 11：初版量词能力？

- A. 完整有限域展开加基本引入/实例化；一般递归触发和归纳不列必备。
- B. 同期做一般触发实例化和更多自动归纳；搜索与循环控制成本高，仍无任意命题完备承诺。

**建议答复：A。有限结构长度未知时先用操作契约，后续以真实案例驱动更强自动化。**

## 六、组合规则与其他分析的边界

共享等式能让 INT 的下标相等传给 SEQ，或让 trait 参数等式传给关联项；但通信接口不等于组合完备。

例如值只能有两个标签，另一模块却要求它不等于二者：不传有限域的穷尽条件，各模块可能都无冲突。需把有限域析取交 SAT，或由完整覆盖组合的后端处理。

经典 Nelson–Oppen 有签名分离、稳定无限等适用条件，BV 不满足稳定无限；不能把 TYPE/ROW/BV 插上等式通知就宣称获得其完备性。[Programming Z3：theory combination](https://theory.stanford.edu/~nikolaj/programmingz3.html)

建议每个跨域桥接写明 sort、语义关系与前提；等式交换不足则生成有依据的析取；能完整降低到支持片段的查询统一检查；其余组合可靠传播，联合模型不能验证就 unknown。

| 查询 | 拥有语义的地方 | PTC 接合 |
|---|---|---|
| 字段存在 | 结构描述 | A05 |
| 可见性、成员来源、关联项选择 | 名称解析与既有选择规则 | 成功来源/签名证据及 requirement |
| as 或 receiver adaptation | 既有转换/适配规则 | 前提和实际动作，不只是两个 Type 的 bool |

### 审阅 12：定义时不能证明的 ensures 怎样兑现？

- A. 内建契约是受审计规则；用户契约须定义证明，或按准许阶段规则留下具体执行验证，验证后才交付依赖它的实例。两者皆不能则拒绝。

实现不变量：

1. 调用前 Γ 证明 requirement；不能用同一调用尚未获准的 ensures 倒证其前提。
2. assumes 的定义端事实按已有阶段兑现；失败实例不交付，不授权 solver 抢先执行副作用。
3. 分支事实和绑定带作用域，退出恢复；汇合只保留各分支支持的事实，类型汇合沿用既有规则。
4. 学习子句保留依赖假设的 activation guard，局部结论不能泄漏到其他分支。
5. 缓存包含目标、相关前提、绑定、target、阶段、实现环境等实际语义依赖；避免无环境的全局属性缓存。
6. 证明可在必要前提和依赖仍有效时复用；unknown 只记录本配置下未完成，不能缓存成否定。
7. 用展开项数、实例数、决策数、递归深度等可控预算；耗尽给来源与残余，不静默换 false。

## 四、布尔层与 theory 接口

建议采用 CDCL(T)/DPLL(T) 分工：布尔层管理决策与学习，各 theory 接收文字、传播结论并解释冲突。这是架构选择，不代表采用现成 SMT 产品。[DPLL(T) 原始论文](https://homepage.cs.uiowa.edu/~tinelli/papers/NieOT-JACM-06.pdf)

更外层仍须有操作契约协调器，拥有 query 合法性、comptime 执行和源程序顺序。SAT 试探不能替代这些职责。

### 查询结果

证明 Γ 蕴含 Q，可尝试判 Γ ∧ ¬Q 不可满足。

| 结果 | 准确含义 | ordinary |
|---|---|---|
| Entailed(proof) | 当前前提下已证明 Q | 对应 requirement 通过 |
| NotEntailed(witness) | 有经原语义验证的 Γ ∧ ¬Q 模型 | 拒绝，可展示反例 |
| Unknown(reason,residuals) | 既未证明，也没有获验证的反例 | 拒绝当前必检要求，解释缺口 |
| IllFormed(diagnostic) | 命题输入/依赖/观察本身不合法 | 报其错误，不把它当 false |

NotEntailed **不是** Γ 蕴含 ¬Q。例如只知 n 非负，n 等于零可能真也可能假。要证明否定，另查 Γ ∧ Q 不可满足。

把真实函数抽象成未解释函数后，其 SAT 模型可能不可由源程序实现，只能得 unknown。只添加可靠约束的保守抽象若 UNSAT，则可用于证明。Γ 自身矛盾应标出不可能路径；逻辑上的矛盾推理不自动消除非法语法、命题良定义检查或尚需执行的 assumes。

### 最小接口：候选伪代码，非 Flurry

~~~text
register(term_or_atom, source, semantic_dependencies)
checkpoint() -> token
assert_literal(literal, reason)
propagate() -> implied_literals_with_reasons | conflict_with_reason
check_fragment() -> consistent_in_declared_fragment | conflict | unknown
explain(consequence) -> antecedents_and_rule
restore(token)
~~~

Consistent 只针对模块声明的片段，不是全局 SAT。字段类型等部分操作，必须先验证前提才产生可使用的观察项；不能给不存在字段分配任意 Type 来使操作“有定义”。

每项事实关联来源、前提、作用域、语义环境及未兑现阶段义务。要求理论传播和冲突可解释，首版不必公开通用证明对象或开发第三方 proof checker。

### 主流程：候选伪代码，非 Flurry

~~~text
prove(context, goal):
    validate well-formedness and semantic prerequisites
    lower justified semantics; retain unsupported obligations
    activate this context and query using guards
    ask Boolean engine for context AND NOT goal
    repeat within configured work budget:
        Boolean propagation
        send assigned theory literals to their owners
        collect consequences, equalities, and conflicts
        if conflict:
            learn its implication clause with required guards
            backjump and restore all affected theory state
            if query refuted at root: return Entailed
        else if a Boolean decision is needed:
            decide without executing source side effects
        else:
            request full checks within each declared fragment
            if a full check reports conflict: handle conflict as above
            if new justified consequences arrive: assert them and continue
            if justified theory split exists: add it and continue
            if jointly validated source model exists: return NotEntailed
            return Unknown with residual obligations
    return Unknown(resource_limit)
~~~

源程序 inline 分支与 solver 决策分支是两种东西：前者决定执行和生成，后者只搜索证明。solver 回溯不是执行两边源程序再回滚副作用。

### 审阅 3：如何承诺初版组合能力？

- A. 可靠但有明确 unknown 边界；模块报告覆盖片段，只用可靠 UNSAT 证明，反例要求联合验证；同时规定稳定基础能力档。
- B. 只接受一个整体可判定的严格受限片段；超出片段的命题可执行，但不尝试跨片段符号证明。边界简单，更多地方依赖显式契约。

**建议答复：A。不能用各模块局部无冲突冒充组合完备，也不能把全部基础证明都交给不稳定启发式。**

## 五、11 个模块的实现骨架

以下均为候选算法与不变量，不指控到当前源码、crate 或函数。

### T1：EUF——等式与一致函数应用

负责 A01 的共享框架。对获准具有一致语义的函数应用使用同余：参数等价则结果等价；没有任意单射规则。[同余闭包原始论文](https://www.cs.upc.edu/~roberto/papers/IC06.pdf)

维护可回退的等价类、父项使用表、函数签名索引和独立解释边。合并类后重查受影响父项；同函数身份、同必要依赖、各参数同类的父项继续合并。已有不等的两项进入同类时，沿解释边生成冲突。回退同时恢复等价类、索引与附带事实。

Flurry 的接合约束：

1. 逻辑等式仅用于有等价/替换契约的对象；任意重载 Eq、缓存比较与 IEEE 浮点比较不直接混入。
2. 普通纯类型工厂按既有模型执行并复用结果；不同输入可能返回同一类型，结果相同不推出参数相同。
3. 符号调用的同余要求其语义依赖和良定义前提具备；pure 不证明终止，也不免除前提。
4. 只有另有确认的自由构造子才使用单射/不相交规则；不能套给所有尖括号调用。
5. 零阶 Tensor 与元素类型相等已有正式依据，不能采用“所有不同头都不等”。获准等式与保留形态观察分别处理。
6. Any 相容不能导致两个具体类型等价类合并。

整个模块含父项索引、解释与回退，不能拿普通 union-find 的近常数界当整体复杂度。

### 审阅 4：初版怎样组织已确认的内建类型等式？

- A. 有限、定向、带前提的重写规则配合 EUF；例如满足条件的零阶 Tensor 等式直接归约。规则单独检查适用条件，未覆盖的等式保持未决。
- B. 在等价图中对已确认等式作有预算的双向展开。可以发现更多等价形态，但项膨胀、回溯及来源形态维护更复杂，耗尽预算仍为 unknown。

**建议答复：A。先明确有限规则和前提；普通工厂的执行/缓存、保留形态匹配、语义等式继续各按已有契约。两种方案都不允许从任意工厂结果反推参数，也不开放用户逻辑公理。**

### T2：TYPE——类别、限定与结构

负责 A02–A05，使用部分描述事实，不要求先完整执行类型计算。

1. 为分类轴登记已确认蕴含/互斥关系。正事实限制候选，负事实排除类别，无法兼容时输出带前提解释的冲突。
2. 具体描述提供种类和成员；部分描述只提供契约保证。只知 tuple 不产生具体长度。
3. HasSlot 证据允许相应观察，结果项绑定同一结构与选择器身份。名称相同不等于同一声明。
4. 只有完整封闭描述可由缺项推否定；输入未知保持未完成。transactional build 不提供可观察半成品事实。
5. 限定按各自获准归一规则观察，未确认的穿透、重排、消去不加入重写表。

已知结构的一次遍历可为 O(V+E)；未知工厂执行和搜索不包含在此界内。

### T3：MATCH / REL——模式、相容、子类型

负责 A06–A09，不能只共用一个“unify 成功”结果。

匹配按模式树递归：确定域/保留头，检查获准位置与标签，为新绑定建立独立作用域身份；已有表达式引用按作者已确认的模式语义比较。成功才输出绑定与约束。不能分解的普通函数结果不逆解；不支持模式留残余。

相容使用已有通配方向与获准结构规则。经过 Any 的两次相容不组成 A、B 的等式或相容证明；Any 也不能偷换成可任意统一的推理变量。

子类型用目标驱动规则表：选已定义规则、产生前提、递归求解。循环目标在没有明示归纳/余归纳规则时未解决，不因 visited 成功。函数方差、限定拓宽、optional 注入等尚未完整定稿，本轮只保留入口，不套其他语言默认规则。

线性结构模式成本与结构大小成正比，析取/回溯另计。接收者适配仍返回实际来源及生成动作，不由 Compatible/Subtype 自动触发。

### T4：TRAIT——约束证据与实现选择

负责 A10；关联项是依赖选定证据的项。

1. 查询键包含主体、trait 身份/参数、阶段和可见实现环境；先读取已给约束证据，再索引实现候选。
2. 匹配候选头，生成并证明其前提；不得为了调用成功把待证前提直接加入 Γ。
3. 保存选定来源、成员身份及替换；关联类型从该来源产生。两个来源都叫 Output，不是同一项。
4. 参数或生成定义未决定则未决，多来源按既有选择/coherence 规则；不重开上一组查找题。
5. 用进行中/完成表避免重复搜索。进行中表示依赖环，不自动作余归纳证明。
6. 只有有效否定契约，或查询环境确实封闭且匹配穷尽，才能产生负事实；后续可能生成实现时不永久否定。

成本随候选数、子目标与递归深度变化。索引不保证任意递归实现搜索终止。

### 审阅 5：如何得到否定 trait 事实？

- A. 一般未找到/未决定是 unknown；固定且封闭环境穷尽适用候选才给否定，证据绑定该环境。
- B. 每个线性位置立即把当前可见候选视为封闭；否定事实严格绑定时点，不能跨后续生成定义复用。这需要公开时点语义。

**建议答复：A。真正完整的静态查询可判否定，未完成的参数化查询不等于没有实现。**

### T5：LAYOUT——表示性质与数值观察

负责 A11，把大小/对齐/偏移等观察结果交给 EUF/INT。

1. 依表示规则构造依赖图，区分必须取得完整内嵌表示与只需间接表示的边。指针宽度独立于 pointee 布局，沿用指针位宽等于 usize。
2. 按值表示依赖环用 DFS/SCC 检测；无获准打断规则的非法循环是布局错误，不能算成正常的 NotSized=true。
3. 输入具备则计算，部分输入只输出被契约支持的性质。runtime 依赖类型可以有固定表示，不能一概判变长。
4. 观察项绑定 target 与影响表示的属性。同一类型跨 target 的大小不是无环境全局常量。
5. 数值关系交 INT；实际布局由表示规则决定，不由算术 solver 自选。
6. 同大小不推出同类型、同对齐、任意位串合法、按位复制安全或任意转换。

固定依赖图检查 O(V+E)，执行与算术另计。输入不足返回 unknown，非法表示是 IllFormed。

### 审阅 6：is_not_sized 的否定究竟否定什么？

不是重问要不要 Sized trait，而是补齐作者已选择的谓词含义。

- A. 表示性质：对适用且合法的类型，大小不能仅由类型与 target 固定，还依赖值相关信息。参数尚未知是 unknown，不是 true。
- B. 当前能力：此时还取不到固定大小就为 true。它混合未知输入与值相关大小，必须绑定分析时点，不能当稳定类型性质。
- C. 另有含义，按骨架改写：“输入域……；true 表示……；不适用对象……；未知输入……”。

**建议答复：A。先限于具有相应表示语义的类型；仅 comptime 的描述对象若不适用，是前提不满足，不静默返回 true/false。**

### T6：INT——整数边界、线性关系与同余

负责整数 Eq、A12、可选 A13。数学整数与机器整数不直接混用。

第一层是常量折叠与差分逻辑。a − b ≤ c 编成 b→a、权重 c，加统一零点处理单变量界。负环给冲突和原约束解释；无负环的最短路可给差分界，在整数权重下给相应整数赋值。Bellman–Ford 是可核对基线，完整一轮 O(VE)。[MIT Bellman–Ford 课程材料](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/08c2314e3e4c4590bffc3409549f25eb_f9cVS_URPc0.pdf)

第二层是线性整数算术。规范化为整数系数线性和，乘法只允许一侧常数；用精确有理数线性可行性作松弛。不可行给线性矛盾解释；可行后仍检查整数性。分数赋值 x=r 可按 x≤floor(r) 或 x≥ceil(r) 的有效析取分支，配合正确整数 cuts。预算耗尽 unknown。此骨架不承诺朴素分支即可完整终止；若要完整 LIA 能力档，需采用经验证的完整程序。[Dutertre 与 de Moura 的算法讲义](https://yices.csl.sri.com/old/slides-cav06.pdf)、[Z3 算术片段说明](https://microsoft.github.io/z3guide/docs/theories/Arithmetic/)

整数 2x=1 的有理松弛可行，整数不可行。把 simplex 可行当整数模型是健全性错误。

第三层是模数为正常数的同余。a 与 r 模 m 同余可编码为 a−r=m·k，新 k 是整数见证。否定需正确余数范围或互补分支，不能随意固定 k。布局提供对齐约束，solver 不发明“所有对齐都满足某未确认规则”。

除法/余数的舍入、除零、溢出以及机器整数映射都必须接 Flurry 操作契约。SMT-LIB div/mod 有特定欧几里得定义，不能直接当语言规则；求解器的除零总函数化也不能让源程序非法操作合法。[SMT-LIB Ints](https://smt-lib.org/theories-Ints.shtml)

非线性项初版可具体执行或作有契约的未解释项，不套不可靠线性近似。浮点不转数学实数；未支持 IEEE 符号推理时只用获准的具体执行事实。

### 审阅 7：整数初版交付哪一档？

- A. 差分逻辑完整，常量线性化、一般线性与同余先可靠但可 unknown；公布基础档。复杂关系依赖显式结果契约。
- B. 首版即接经验证的完整无量词 LIA 程序/组件，PTC 协调自有；覆盖广，集成开发成本高。
- C. 仅具体计算与区间传播；实现最少，但不适合作跨变量关系的稳定基础。

**建议答复：A 作为可交付基线，B 为增强目标；如果首版必须广泛自动证明形状线性关系，可直接选 B。非线性整数不作完整判定承诺。**

### T7：SEQ——有限列表、元组结构与形状

主要处理项及 A01/A12，不新增 LengthEquals 原子。覆盖已有张量案例，不能只用“以后把列表当 UF”略过。

候选内部项包括具体列表、长度、带前提索引、头尾、已定义拼接；不是新增 meta.List API。

1. 具体有限列表直接计算，相等按长度和对应元素判断。
2. 已证明 0≤i<length(S) 且容器操作前提成立后，才使用元素观察和相应类型契约；空列表取头不返回任意项。
3. 对准入操作登记有前提的长度/元素等式，如非空尾部长度减一；不能用它的结果契约倒证同一操作的前提。
4. 长度固定且在预算内，列表相等展开为逐元素相等，不等展开为至少一个不同；长度未知保留关系。
5. 有限构造可结构递归；一般拼接方程、未知长度外延相等不承诺初版完整判定。
6. broadcastable 走 predicate 入口；获准展开才使用列表/整数规则，或在具体形状上执行。broadcast_shape 的保证来自契约或定义证明，不因函数名特殊而内置。

示意推导：S 长度 n，n≥1，合法 tail 的契约给 length(tail(S))=n−1，INT 可证尾部更短。没有提前取得任何元素，即能支持现有张量教学的降阶关系。

具体列表比较 O(n)，固定展开按元素数计费，一般序列方程不在此复杂度保证内。

### T8：ROW——error/effect 行

负责 A16–A18 和行等式。当前只确认行多态方向；下面是**集合式行候选**，必须经审阅 8 选择后才作为 Flurry 规则。Closure 不在这里。

若标签唯一，可用已知标签及开放尾部表示：

1. 共同标签的参数/载荷按已定义关系送 Eq 等 theory；不能只比打印名。
2. 命中已知标签给 Contains，封闭行确定缺失给负文字；开放尾部记录成员/排除约束。
3. 行等式先匹配共同标签，把剩余标签推给对方尾部。两边开放可引入共享尾部及标签排除约束；有限行模型不接受无限递归尾部。
4. Subset 把左侧已知成员推给右侧，另保留尾部包含边；不能只检查当前可见成员就宣布开放行包含。
5. Disjoint 使一侧成员成为另一侧 lacks；未知尾部间仍保留关系。lacks 是否定，不是没看见。
6. 扩展、并合、handler 消去为带契约的项运算；消去哪个参数化实例，由标签定义决定。

若标签身份含符号参数，标签等式也可能未知：应将匹配分支交给布尔层或保留残余，不能哈希成两个永久不同键。固定已知标签可索引归并；开放尾部和参数求解另计。

### 审阅 8：行标签身份与重复怎样处理？

- A. 集合式，完整 error/effect 实例为键；同实例去重，不同参数实例可共存。实例等式可能需求解。
- B. 集合式，声明身份为键、参数为载荷；同声明重复须协调参数，不能并存不同参数实例。
- C. 有序或多重行，保留重复；须定义顺序/重数和消去哪一次，集合式算法不直接适用。

**建议答复：A 作为候选，error/effect 分别确认；行变量先指一个待确定的完整行，包含另写关系。若 handler 设计要求 B/C，按其设计改写。**

### T9：BV——定宽位向量与模式集合

负责 A14/A15 及定宽 A01/A07。位运算产生项，比较才产生原子；宽度未知不造“任意宽 BV”。编码可核对 SMT-LIB，但仍须匹配 Flurry 操作语义。[SMT-LIB FixedSizeBitVectors](https://smt-lib.org/theories-FixedSizeBitVectors.shtml)

第一档是纯掩码快路径。模式用同宽 mask/value 表示，先规范化无关 value 位。两个纯掩码不相交，当且仅当共同固定位有相反要求，即数学式：

~~~text
((v₁ XOR v₂) AND (m₁ AND m₂)) ≠ 0
~~~

这是数学位向量式，不是 Flurry 运算符。额外 guard 存在时，掩码无冲突不证明完整模式有交集。

第二档把获准定宽操作布尔化为电路交 SAT，或用局部后端。相交检查存在同时匹配的位串；互斥是其 UNSAT。覆盖检查在 base type 的**合法编码域**内是否存在一个全不匹配的位串，不能遗漏合法性约束。

反例给具体位串与匹配条件。未知宽度、任意 predicate guard、跨元素 DST 解析不自动进完备片段；一般解析仍留已约定的程序合成主题。

掩码比较 O(w)，p 个模式朴素两两检查 O(p²w)。布尔电路规模依操作变化，简单加法/比较可线性，朴素乘法可平方；SAT 最坏指数，宽度有限不等于成本小。

### 审阅 9：BV 首版覆盖到哪里？

- A. 先覆盖 enum/模式独立判定，掩码与明确的定宽布尔片段，可用局部后端；未知宽度与一般解析不承诺完整。
- B. 同期接入全部机器整数符号运算；须先接齐溢出、移位、符号转换等契约，范围更大。

**建议答复：A。先兑现已讨论的模式互斥/覆盖需求，B 是后续扩展。**

### T10：PRED——可执行 predicate

负责 A19。准入需说明良定义域、重复引用是否同一命题、具体输入下怎样执行。

1. 获准内建/契约可展开为核心公式；部分定义只有在前提成立时展开。
2. 用户 predicate 可保留稳定原子身份，使用 Γ 已给正负事实；允许展开时只翻译支持的体内操作。
3. 循环、递归、一般 comptime 程序超出能力时停止展开并保留残余，返回 bool 不保证可 SMT 化。
4. 参数具备时在源语义允许的阶段执行；assumes 失败仍为实例化错误。SAT 试探不提前运行不纯操作。
5. 身份含定义、绑定实参及必要依赖；可能随未记录状态变化的两次调用不能合成同一逻辑命题。
6. 任意 inline bool 不可提取时，按现有文档不提供新的语义路径事实；不能默默升级成稳定 A19。

pure 是已有可信承诺，不新增自动纯性验证。这里要确认 predicate 的准入纪律，不重问可执行性。

### 审阅 10：predicate 是否要求稳定逻辑含义？

- A. 同一完整语义输入/依赖表示同一命题；采用合适纯性承诺或显式依赖。一般状态相关 bool 可做 inline 条件，但不自动取得逻辑 predicate 身份。
- B. 允许每次执行状态改变含义；原子必须带状态/事件身份，不能跨求值复用事实，须另定该身份契约。

**建议答复：A。稳定不等于可判定，也不要求证明终止；只是不能把可能不同的执行强行当同一命题。**

### T11：量词层

量词不是新增原子。建议基本能力：

- 完整已知有限域：forall 展合取，exists 展析取；空域分别真/假。当前见过几个类型不是 Type 全集。
- 全称目标：用新鲜不逃逸的任意参数证明，不能选一个方便的具体类型代替。
- 存在目标：给出并检验见证，没找到见证不是假。
- 全称前提：合法实例化，保持绑定与前提；可增加有预算的触发匹配。
- 取反时正确处理量词；见证依赖不能逃出作用域。递归造项超预算 unknown。

有限次实例化一般不能证明剩余所有实例都满足。E-matching 可作后续机制，其触发策略不替代证明。[Programming Z3：量词实例化](https://theory.stanford.edu/~nikolaj/programmingz3.html)

### 审阅 11：初版量词能力？

- A. 完整有限域展开加基本引入/实例化；一般递归触发和归纳不列必备。
- B. 同期做一般触发实例化和更多自动归纳；搜索与循环控制成本高，仍无任意命题完备承诺。

**建议答复：A。有限结构长度未知时先用操作契约，后续以真实案例驱动更强自动化。**

## 六、组合规则与其他分析的边界

共享等式能让 INT 的下标相等传给 SEQ，或让 trait 参数等式传给关联项；但通信接口不等于组合完备。

例如值只能有两个标签，另一模块却要求它不等于二者：不传有限域的穷尽条件，各模块可能都无冲突。需把有限域析取交 SAT，或由完整覆盖组合的后端处理。

经典 Nelson–Oppen 有签名分离、稳定无限等适用条件，BV 不满足稳定无限；不能把 TYPE/ROW/BV 插上等式通知就宣称获得其完备性。[Programming Z3：theory combination](https://theory.stanford.edu/~nikolaj/programmingz3.html)

建议每个跨域桥接写明 sort、语义关系与前提；等式交换不足则生成有依据的析取；能完整降低到支持片段的查询统一检查；其余组合可靠传播，联合模型不能验证就 unknown。

| 查询 | 拥有语义的地方 | PTC 接合 |
|---|---|---|
| 字段存在 | 结构描述 | A05 |
| 可见性、成员来源、关联项选择 | 名称解析与既有选择规则 | 成功来源/签名证据及 requirement |
| as 或 receiver adaptation | 既有转换/适配规则 | 前提和实际动作，不只是两个 Type 的 bool |
| 可取地址、资源仍有效 | 表达式/资源分析 | 带表达式或状态身份的已定义事实 |
| runtime 依赖环境有效 | 可达性/资源契约 | 上下文身份与有效证据，不读取未来内存 |
| proxy、Splice | 跨阶段机制和 trait | 观察、实现证据及前置条件 |
| 生成代码/类型 | query/comptime 计算 | 先用合法结果契约，实际产物仍兑现 |

因此不为“列表完整”擅自设计分离逻辑、别名规则、ABI 定理；这些定义不足是显式边界，不是让通用 atom 掩盖的细节。

## 七、结果契约、作用域与缓存

assumes 实例化检查已确认；用户 ensures 的完整兑现方式尚需明确，不能凭声明存在便当真。

### 审阅 12：定义时不能证明的 ensures 怎样兑现？

- A. 内建契约是受审计规则；用户契约须定义证明，或按准许阶段规则留下具体执行验证，验证后才交付依赖它的实例。两者皆不能则拒绝。
- B. 用户 ensures 一律要求定义时证明，不允许具体执行替代；规则简洁，复杂 comptime 工厂受限。

**建议答复：A。normalization 可按合法声明继续检查；具体生成的结果不能把未兑现保证带进最终实例。两项都保留此前不开放任意用户公理的原则。**

实现不变量：

1. 调用前 Γ 证明 requirement；不能用同一调用尚未获准的 ensures 倒证其前提。
2. assumes 的定义端事实按已有阶段兑现；失败实例不交付，不授权 solver 抢先执行副作用。
3. 分支事实和绑定带作用域，退出恢复；汇合只保留各分支支持的事实，类型汇合沿用既有规则。
4. 学习子句保留依赖假设的 activation guard，局部结论不能泄漏到其他分支。
5. 缓存包含目标、相关前提、绑定、target、阶段、实现环境等实际语义依赖；避免无环境的全局属性缓存。
6. 证明可在必要前提和依赖仍有效时复用；unknown 只记录本配置下未完成，不能缓存成否定。
7. 用展开项数、实例数、决策数、递归深度等可控预算；耗尽给来源与残余，不静默换 false。
8. 非法布局环、comptime 求值不终止、递归 predicate 未证目标分别诊断，不能用 visited 即成功处理。

## 八、验收推理与实施顺序

以下是数学/内部验收方向，不是已编译的 Flurry 示例；本轮不创建编译器测试。

| 情形 | 必须得到的结果/边界 |
|---|---|
| a=b，f(a)≠f(b)，同余前提满足 | 冲突并解释等式链 |
| f(a)=f(b) | 不独自推出 a=b |
| A 与 Any 相容、Any 与 B 相容 | 不合并 A/B |
| 只知 T 是 tuple | 可用种类契约，不能造具体元素类型 |
| 语义等式与保留头来源不同 | 分开对象与证据，不错误传递 HasHeadShape |
| 0≤i<n 且容器/元素操作契约满足 | 可使用相应索引观察 |
| n≥1，合法尾部长度 n−1 | 推出尾部更短 |
| 整数 2x=1 | 不可满足，不采用有理模型 |
| 指针已知、pointee 布局未知 | 指针宽度仍可按 usize 得到 |
| 非法按值表示环 | 布局错误，不是 NotSized=true |
| 开放行一个已知标签 | 不据此否定其他标签 |
| 参数未定、暂时无 trait 候选 | unknown，不永久否定 |
| 同宽掩码共同位要求不同 | 不相交，指出冲突位 |
| 掩码兼容但额外 guard 未决 | 不宣称完整模式相交 |
| 只检查当前见过的几个类型 | 不宣称 Type 上全称成立 |
| inline bool 无法提取 | 不增添类型事实，不提前执行两侧 |
| 分支 A 的局部学习结论拿到 B | 缺少前提则禁止复用 |
| 用户结果保证具体检查失败 | 依赖实例不能交付 |

建议交付顺序：

| 阶段 | 产物 |
|---|---|
| 1. 共同契约 | 项/原子/操作区分、注册表、来源/阶段义务、四类结果 |
| 2. 基础证明 | 布尔层、EUF、已定义结构与分类、简单匹配、差分逻辑、解释/回退 |
| 3. 类型检查接合 | trait 证据、选定关联项、布局、有限序列、predicate 入口 |
| 4. 专门片段 | 确认后的行规则、定宽模式、基础量词 |
| 5. 增强 | 完整 LIA、更多获准列表定律、触发实例化、联合模型检查 |

基础能力档由有限规则/片段清单及稳定预算策略规定；可以增强，但不能把基本同余和差分证明全部交给偶然启发式。具体接受程序范围待本轮选定后再形成正式契约。
