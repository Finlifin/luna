## 语义边界与可行性评估

### 阶段与接口

quote 构造 comptime 代码值，其 runtime 主体不在构造时执行。Ψ 可以含多个有依赖次序的 runtime 绑定；空 Ψ 不表示纯。rank-1 的操作性边界是最外层上下文量化，代码参数使用本次实例接口，不把高秩方案隐藏进 Any 后继续任意实例化。

expr 使用上下文，pattern 在成功后输出上下文。完整 arm 保存模式、成功绑定及主体，表面由 quote fn 和函数级模式表达。独立 pattern 的公开输出接口不能暗藏未交代的 runtime 局部输入。

### 默认替换与身份

代码接口、原绑定、模板供应和 pattern 成功关系提供默认对应。显式表左边选代码接口、右边指这次供应或导出的绑定；同时替换作用于主体、类型依赖和控制关系。普通同名变量不会自动取代原身份，每次 pattern splice 引入新鲜成功绑定。

示例覆盖原绑定被后续同名变量遮蔽、开放端口重定向、两个端口同时交换、模板默认供应、模式与正文配对，以及同一模式代码的两次接入。

### Any 的危险边界

区分 q: Any、结果为 Any 的 contextual 代码、接口通配描述与把 any 直接当代码。代码经 Any 保存仍须保留实际类别、接口、依赖、主体和义务；接入处恢复证据，而不是从期待的结果类型反向伪造代码。

拒绝例覆盖错误结果类型、pattern 被接到 expr 位置、直接 splice any、runtime 条件选择 comptime 代码值。资源与内存状态义务归程序验证；PTC 只处理类型命题。

### Quote 函数与单洞

quote fn 保证接入，普通实参求值一次，包括未使用实参的效果；return 完成本次逻辑应用。模板可以复用所有非 comptime 函数类别，也可以通过 quote lambda 提供受检正文接口。

每份 quote 按其展开前 runtime 主体统计显式 splice、quote fn 应用和有协议的 arm use 接入。被调用代码独立检查；普通函数体可有多个独立接入。互斥分支、Any 和后续优化不能把原本两个洞洗成一个。

### 有限程序组装

完整示例从四条状态转移生成条件链，再用 runtime 循环识别 ASCII 的 a[bc]*d。生成器在 comptime 从末尾逐层包裹一份 previous 代码，每层一个 splice；执行图有回边，而生成器只处理有限边集。代码同时展示生成器、等价展开、消费循环和正反输入。

这展示了代码组装能力，也明确保留单洞的真实限制：任意两个独立代码值的二元组合仍需有输入输出契约的模板或组合操作，不能只声称多套几层 quote 就解决。没有把 regex 草案中仍属候选的 code_sequence／code_match 名字当成已确认公共 API，也没有用 open code 注册自动机边。

运行时条件链代价为 O(L×E)，状态为 O(1)；生成目标大小 O(E)。共享节点可避免构造时反复深复制导致的 O(E²)。捕获的接口和回滚另按库契约设计，不把布尔识别器当成完整正则捕获实现。
