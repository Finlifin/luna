# PTC 理论求解器

## Intro

不同事实需要不同算法。例如，整数边界适合图算法，类型相等需要身份与同余，而行还需要处理开放尾部和标签层次。

各求解器只解释自己负责的语义。它们共同工作，但不能因为共享了一个等式表，就宣称所有组合问题都可判定。这种模块化分工遵循 Nelson-Oppen 组合理论的思路：每个 theory 独立维护自身的不变量，通过受控的等式共享进行协作。

## 语法

本篇算法使用内部数学记号，不新增 Flurry 产生式。公开入口沿用[PTC](index.md)中的谓词、要求与布尔表达式。

## 正式定义

求解能力分为完整基础片段与可靠但可未决的片段。基础包括布尔组合、准入同余、已定义封闭结构和数学整数差分逻辑；更复杂运算必须说明自己的前提及覆盖。

任何一个模块都不能把“没发现冲突”当作完整源语义模型；也不能把“资源耗尽”当作假。跨域事实仅通过有前提的语义关系交换。

## 常见示例

让数组形态、元素类型和长度约束共同决定一个编译时查询：

~~~flurry
pure comptime fn has_four_words(T: Type) -> bool {
    inline if T is do {
        Array<'u32, length> => length == 4,
        _ => false,
    }
}

comptime {
    assumes has_four_words(Array<u32, 4>);
    assumes not has_four_words(Array<u32, 8>);
    assumes not has_four_words(Array<f32, 4>);
}
~~~

第一步观察 Array 的保留头，第二步比较元素类型，第三步比较长度。三次调用分别在全部条件成立、长度不符、元素类型不符的位置结束。实现不能用一个无条件的“数组就是四个字”分类结论代替这些关系。

整数推理可以单独观察：

~~~flurry
pure comptime fn checked_index(index: Integer, length: Integer) -> Integer
where requires 0 <= index and index < length {
    index
}

pure comptime fn advance(index: Integer, length: Integer) -> Integer
where requires 0 <= index and index + 1 < length {
    checked_index(index + 1, length)
}

test {
    const NEXT: usize = advance(2, 5).as(usize);
    println("next: {}", NEXT);
}
~~~

输出 `next: 3`。INT 模块把上界换成适用的整数差分约束，再证明调用中的下界与上界。这里所有待证项属于数学整数；把它们直接套在可能溢出的机器加法上，需要另外的桥接依据。

最后用一个真实位模式把 BV 的输入写出来：

~~~flurry
fn is_control_byte(value: u8) -> bool {
    value'bitvec match {
        0b1110 (_: u4) => true,
        _ => false,
    }
}

test {
    println("control: {}", is_control_byte(0xe3));
    println("control: {}", is_control_byte(0xd3));
}
~~~

输出 `control: true`、`control: false`。固定高四位决定接纳集合，低四位不参与判别。枚举表示的互斥与覆盖查询可以复用这种固定位约束，但运行时执行的这个判断本身仍需读取参数。

| 代码所需信息 | 主要协作 |
|---|---|
| Array 头、参数绑定、元素类型相等 | MATCH、TYPE、EUF |
| 长度和下标边界 | INT；实际序列观察另由 SEQ 验证前提 |
| 类型表示及指针大小 | LAYOUT、TYPE |
| 固定位模式的接纳、相交与覆盖 | BV、MATCH、布尔层 |
| 传播错误与选择效应入口 | ROW，加上携带路由的实际操作 |

后三类还有完整的[布局示例](../reflection-and-layout.md#常见示例)、[指令解码](../user-defined-types/fixed-width-enum-example.md#常见示例)和[行类型示例](../rows.md#常见示例)。下文按模块给出其内部算法。

## 与 Rust / Zig / C / C++ 的关键差异

C/C++ 的静态断言、Rust 的泛型检查和 Zig 的编译时执行各自提供检查手段；本篇讨论的是 Flurry 命题引擎的内部算法，没有逐一对应的语言构造。与源级约束的对照见[PTC 总览](index.md#与-rust--zig--c--c-的关键差异)。

## 运行时实现设计引导

求解器生成的静态证明可以消去。其产生的布局方案、关联项选择与效应路由必须交给相应降码环节。任何运行时辅助检查都必须来自源操作契约；求解模块不能自行插入一个改变程序许可范围的检查。

## 编译器实现引导

### 1. EUF：等式与准入同余

输入为 A01 正负文字与登记过的同余项。使用可回退并查集、项签名索引与解释森林。

1. a=b 合并等价类，记录原始理由。
2. 重算受影响父项的规范参数类；相同头、相同参数类且满足同余契约的项合并。
3. 检查已有不等式两端是否落入同类；若是，回溯解释边构造冲突。
4. 向其他模块通知有意义的共享等式。
5. 回退恢复合并、签名表和解释状态。

只有受审计的逻辑等式进入 EUF。Any 相容、任意用户重载相等及浮点比较不能直接成为等价类规则。f(a)=f(b) 不反推 a=b，除非 f 被定义为适用且单射的构造子。

范式应用以保留的头与实参参与检查，不展开头的函数体来生成等式。Identity<T> 的函数体即使返回 T，normalized IR 也不因此提供 Identity<T> 与 T 之间的关系；纯性标记、具体实参和 typealias 均不能成为合并这两项的理由。

并查集可提供近常数摊还查找；完整成本还包括父项重访与解释。避免用不可回退的路径压缩破坏回溯，可使用按秩合并或记录全部压缩写入。

### 2. TYPE：分类、限定与结构观察

输入为 A02–A05 及相关等式。结构描述可以完整，也可以只暴露契约许可的片段。

1. 检查观察适用性：字段、变体、tuple 位置和函数参数是不同选择器。
2. 由规范描述提供正分类及实际槽信息。
3. 只由完整封闭描述给出确定缺失；未知或开放描述保留残余。
4. 只应用已定义的类别包含与互斥，不把分类表做成单一枚举。
5. 限定按照各自规则归一，载荷交给对应模块；Closure 不能交给 ROW 当集合处理。

结构存在不意味着可见、可访问或来源唯一；这些由实际成员操作检查。查询字段类型之前必须建立字段存在和观察合法性，不能令非法观察成为任意自由项。

对有限结构建立名称与位置索引后，单次查找可为对数或均摊常数；生成全部字段信息仍与字段数成正比。

### 3. MATCH/REL：模式与类型关系

A06 观察保留头对象，A07 检查模式并产生绑定；A08/A09 保持独立关系。

1. 对已知形态进行结构匹配。
2. 参数位置产生局部绑定，引用表达式产生关系检查。
3. 将长度、元素、位模式子问题分派给 SEQ、INT、BV。
4. 成功返回绑定及理由；否定返回排除依据；未完成保留原始模式。
5. 相容与子类型只使用已定义推导，不添加通用传递或协变规则。

头形状属于带来源的保留项。类型语义相等可以共享类型性质，却不一定共享构造来源。任意纯工厂不作为自由单射构造子。

### 4. TRAIT：实现证据

A10 的身份包含主体、完整 trait 应用与合法实现环境。

正事实来自当前要求或经实现选择规则验证的适用实现。关联项观察携带所选来源和替换；不能仅凭同名关联项合并。

否定需要完整且适用的候选空间排除证据。参数未知、实现环境尚未完成、候选要求未决时，暂时没有成功候选不能证明不实现。

模块接收[实现选择](../../traits/implementation-resolution.md)与[包归属](../../traits/coherence.md)的结果，不自行制定重叠优先级或孤儿规则。递归目标重复出现只说明需要循环控制，不能一律视为成功。缓存同时保留实现环境和依赖假设。

### 5. LAYOUT：表示与固定大小

输入为 A11、类型表示描述和带前提的大小/对齐/偏移观察。

建立表示依赖图：按值字段依赖其类型表示，指针本体只依赖指针表示，不依赖 pointee 的完整布局。检查直接或间接按值布局环；非法环是 IllFormed，不能归类成“非固定大小”。

区分三种状态：

| 状态 | 含义 |
|---|---|
| 固定表示，但参数值尚未知 | 保留符号大小；不推出 NotSized |
| 大小需要值相关信息 | 在适用域内 NotSized 成立 |
| 表示不适用或非法 | 报告前提/布局错误 |

固定依赖图遍历为 O(V+E)，具体算术与类型计算另计。对跨目标缓存纳入 target；依赖对象或属性变化不能复用失效布局。

### 6. INT：差分逻辑、线性整数与同余

数学整数不溢出；机器整数只在对应操作契约支持的桥接后进入此理论。

**基础差分片段。** 把 a−b≤c 编为边 b→a，权重 c。单变量界通过零点表示。以可检查的最短路径算法传播界；负环给出不可满足解释。Bellman–Ford 的完整一轮基线为 O(VE)，整数权重可对应整数赋值。严格不等在整数域中正确调整一个单位。

**一般线性片段。** 规范化为整数系数和，乘法只有一侧常数时才线性化。使用精确有理数松弛；松弛不可行可证明整数不可行，松弛可行必须继续检查整数性。对分数值 r 可引入有效析取 x≤floor(r) 或 x≥ceil(r)，配合正确整数 cuts。预算耗尽返回 Unknown；朴素分支不承诺完整终止。

**同余。** 正常数 m 下 a≡r mod m 可降为 a−r=m·k，k 是整数见证。否定必须覆盖所有可能余数，不可随意选一个 k。未知或非正模数不属于该原子定义域。

除法、余数、移位及溢出必须接源操作契约。后端的总函数化或除零解释不能使源程序非法运算合法。非线性整数可具体执行或保留受约束项；浮点不能直接转成实数算术。

### 7. SEQ：有限序列与形状

输入包括具体列表、长度、合法索引、头尾、已定义拼接以及它们的等式。

1. 具体列表按长度和对应元素比较。
2. 先证明非空或索引界，再形成头、尾或元素观察。
3. 登记有前提的长度/元素契约，不用结果倒证操作前提。
4. 已知长度且预算允许时逐元素展开相等；不等展开为至少一项不同。
5. 符号长度、一般拼接方程与无限制外延等式保留残余。

具体列表比较 O(n)。未知长度不能因当前见过有限个元素就当作完整。broadcastable 等形状谓词使用 PRED 入口，展开依据定义或契约，函数名本身没有特殊证明权。

### 8. ROW：两类行

A16–A18、行等式、split 与 embedding 的完整算法见[行类型](../rows.md)。核心不变量是：

- error 标签唯一，严格扩展携带 lacks。
- effect 保留同标签 occurrence 次序；不同标签只有在已证明不等时才能交换。
- 未知标签身份不哈希成永久不同键。
- 调用推断元变量与定义端刚性参数分开；后者不被统一器赋值。
- 效应包含布尔事实不能替代 occurrence 路由证据。
- 发生检查与公共尾部保护共同保证只接受有限行。

### 9. BV：定宽位向量与模式集合

A14/A15、同宽等式和定宽匹配由此解释。宽度必须为已知正值；合法值域和用户 guard 单独保留。

纯掩码模式用同宽 mask/value 表示，先清除 value 中未约束位。两个纯掩码互斥恰当条件为：

~~~text
((v1 XOR v2) AND (m1 AND m2)) != 0
~~~

这是数学位运算，不是 Flurry 运算符。存在额外 guard 时，掩码兼容不证明完整模式相交。

准入定宽运算可 bit-blast 成布尔电路：相交询问合法域内是否有位串同时满足两个模式；覆盖询问是否有位串全不匹配。必须包含 base type 合法编码域。

掩码比较 O(w)，p 个模式朴素两两检查 O(p²w)。电路和 SAT 成本另外计算；定宽不意味着便宜。未知宽度、任意 predicate guard、跨元素一般解析不属于完整片段。[SMT-LIB 位向量定义](https://smt-lib.org/theories-FixedSizeBitVectors.shtml)

### 10. PRED：可执行命题

A19 的身份包含定义、绑定实参和必要语义依赖。同一完整语义输入表示同一命题；一般状态相关 bool 不自动获得这个身份。

1. 使用已给正负事实。
2. 前提成立时，按准入定义或契约展开到核心公式。
3. 只翻译支持的体内操作。
4. 在允许阶段、输入足够时执行源 predicate。
5. 递归、循环或造项超预算时停止，保留残余。

pure 的承诺不等于求解器证明终止；可执行也不等于可 SMT 化。SAT 试探不能执行不纯源操作。用户定义 predicate 不等于注册未经证明的逻辑定律。

### 11. 量词层

量词属于公式，不新增原子。

| 情形 | 规则 |
|---|---|
| 完整已知有限域 | forall 展合取，exists 展析取；空域分别真/假 |
| 全称目标 | 用新鲜任意参数证明，禁止只选方便实例 |
| 存在目标 | 提供并验证见证；找不到不是假 |
| 全称前提 | 合法实例化，保留前提和作用域 |
| 取反 | 正确交换量词与否定，保持见证依赖 |
| 搜索超预算 | 保留未覆盖实例及原公式 |

当前编译中出现过的几个类型不是 Type 全集。有限实例化不能证明其余全部输入。触发匹配可帮助搜索，但不能替代证明或让见证逃出作用域。
