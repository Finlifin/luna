# 内存视图

## Intro

容器描述符、它指向的缓冲区和其中一个元素，是三个不同的访问目标。给它们分别命名，才能说明"更新这个字段不会影响那个视图"。

内存视图描述区域，不执行一次内存读取，也不会单凭一个名字授予访问资格。

## 语法

区域表达式复用已有字段和下标形态；下面只列本节使用的写法。

~~~text
projection -> expr.id
index_application -> expr[expr]
dereference -> expr.*
read_footprint -> read<expr>
write_footprint -> write<expr>
~~~

memory view 的作用是为规格提供目标。自定义容器暴露的视图属于其接口契约，具体方法名不由语言统一规定。

## 正式定义

### 目标身份

视图在建立时绑定实际对象、生命周期世代、范围和必要依据。来源变量或索引后来变化，不改变已经取得的目标。

编译器必须区分存放指针的槽位、指针所指分配及分配中的子区间。读取描述符字段不等于读取全部元素；修改索引结构也不必然搬动独立节点。

### 分离性

区域分离必须有对象身份、布局或区间证据。可使用的依据包括：

- 已证明互不重叠的结构字段；
- 同一有效数组中的不相交元素或区间；
- 已核验契约交付的独立分配或稳定节点。

不同字段名不保证 union 成员分离；不同 key 不自动证明两个查找结果位于不同存储。零大小布局、共享位域或重叠表示也不能只用数值地址不等来判断。

区间采用半开边界时，分割点可以位于任一端；空区间不包含可解引用元素。逻辑元素区间到字节区间的映射，还须保证尺寸、对齐和地址运算合法。

### 快照位置

requires 与效果足迹中的选择器按调用入口状态解释。ensures 使用对应出口状态，`'old` 指向入口值。结果区域在实际返回分支交付时绑定；没有结果的分支不凭空求值结果选择器。

因此，追加元素的写入位置可以是入口长度处，而不是把调用后的长度重新代入同一个表达式。已返回视图也不因下一次调用改变容器而重新解释。

### 自定义视图的保证

视图接口可以隐藏物理偏移，公开用户需要的字段、元素或区间关系。实现必须证明这些关系成立；声明一个名为 buffer 的方法，不足以证明地址稳定或不与其他视图重叠。

构造描述本身是元层工作，动态索引作为符号参与。为实际执行生成的寻址、读取或检查仍按运行时行为核验，不借视图构造隐藏任意副作用。

## 常见示例

### 精确字段足迹跨过调用边界

~~~flurry
struct Counters {
    left: i32,
    right: i32,

    fn clear_right(*self)
    where outcomes write<self.right>
    {
        self.right.* = 0;
    }
}

fn preserve_left(counters: *Counters) -> i32 {
    let left = counters.left;
    counters.clear_right();
    left.*
}
~~~

调用方根据字段布局及 clear_right 的足迹保留 left，不需要展开方法实现。把声明扩大为整个对象的任意修改，会失去这份精度。

### 动态下标需要明确的关系

~~~flurry
fn write_distinct(values: *Array<i32, n>, first: usize, second: usize) -> i32
where n: usize,
    requires first < n and second < n and first != second,
    outcomes write<values.*[first]> and write<values.*[second]>
        and read<values.*[first]>
{
    values.*[first] = 11;
    values.*[second] = 22;
    values.*[first]
}
~~~

由 i32 布局、合法下标和不等条件，最终读取为 `11`。如果不要求下标不同，顺序执行仍可合法，但编译器不能保证结果总是 `11`。

### 已取得的指针不跟随索引变量

~~~flurry
test {
    var values: Array<i32, 2> = [3, 5];
    var index = 0usize;
    let selected = values[index].ref;
    index = 1usize;
    values[index] = 9;
    println("{}", selected.*);
}
~~~

输出 `3`。selected 已绑定第一个元素，而非一个以后反复读取 index 的延迟选择器。

## 与 Rust / Zig / C / C++ 的关键差异

Rust 有字段分离和切片分割 API，可用实际接口取得不重叠区域；Flurry 用区域足迹将相应保持关系带过一般调用边界。[Rust 字段与切片分离](https://doc.rust-lang.org/nomicon/borrow-splitting.html)

C 的 `restrict` 是另一种访问约束承诺，不能从两个普通指针或两个字段名自动得到。C++ 的 span 与 Zig 的 slice 描述连续范围，但一个范围描述本身不等于它与另一范围不重叠的证据。

## 运行时实现设计引导

编译期区域描述可以降为普通偏移和长度计算。需要运行检查时，实现先验证索引、容量、溢出和目标有效性，再形成可使用地址。

范围检查不能先执行可能溢出的地址加法，再把溢出后的数值拿来证明安全。空区间允许作为描述存在，但不得通过首元素解引用来构造它。

## 编译器实现引导

编译器将视图规范化为分析记录：

~~~text
View = 对象身份、世代、布局路径或区间、建立时的符号值、所需事实
~~~

1. 从类型与布局取得投影关系。
2. 在正确的入口或出口快照中解释选择器。
3. 固定相关身份和索引值，避免后续重新绑定。
4. 用身份区分、区间关系及已交付契约证明包含或分离。
5. 对未知重叠保守合并影响；要求分离的操作保留待兑现义务。
6. 在写入、终结或管理状态变化后失效相应关系。

访问范围索引可按对象分组，再按字段或区间查询；复杂度由命中的区域与关系决定。范围过多时可汇总，但只能损失精度，不能制造分离保证。
