# 内存效果

## Intro

一次调用可以只改一个计数器，也可以替换整个缓冲区。调用方需要知道它影响哪里，以及调用后哪些访问仍然成立。

内存效果描述这些行为；前后条件与结果关系补足它们的状态含义。声明一次 write，不等于已经取得任意写入许可。

## 语法

~~~text
outcome_clause -> outcomes expr
memory_predicate -> predicate id(parameter*) (-> expr)? clauses? block
requires_clause -> requires expr
ensures_clause -> ensures expr
~~~

程序 predicate 使用普通 `predicate` 声明，不加 comptime。区域参数可通过 quote 参数保留表达式及其绑定。read/write 等接受区域表达式，示例使用已有的尖括号或谓词调用形式。

## 正式定义

### 六种效果

| 效果 | 描述的行为 | 不自动提供的保证 |
|---|---|---|
| read | 读取指定区域 | 目标存活、初始化和类型合法仍需检查 |
| write | 修改指定区域，撤销受影响旧内容事实 | 不自动释放对象，也不自动使所有指针失效 |
| kill | 终结指定区域的当前世代 | 不递归析构所有保存其地址的对象 |
| connect | 目标保留来源提供的依赖 | 不取得来源所有权，不使失效来源复活 |
| move | 转移值、要求与可转移责任 | 不自动终结所拥有的所有外部分配 |
| system | 外部可观察作用，如输出 | 不替代真实 read/write/kill 或逃逸契约 |

复制视图时，connect 传播其实际目标要求，不把中间变量的存储变成来源。move 的目的位置由赋值、参数或返回动作确定。

常量读取可以在对调用者无额外有效性负担时省略表面标注；但实际操作仍要满足值与布局条件。接收者形式不决定效果：`*self` 不自动表示读写整个对象，按值 self 也不自动表示释放全部可达资源。

### outcomes 是行为上界

没有显式 outcomes 时，编译器从实际操作及已交付契约推导可用摘要。显式 outcomes 限制允许行为，编译器仍须核验实现；不能在遗漏 write 后自动扩大声明使其通过。

效果合取表达允许范围或相应规格条件，不规定执行次序。read 与 kill 同时出现在上界里，不能为"先终结，再读取"提供合法性。

完整调用契约还须保存入口前提、各出口状态、结果依赖、责任转移及保持关系。无序效果集合无法表示这些全部信息。

### 条件与出口

条件摘要依据入口快照选择适用行为。条件未证真不等于已证假；当条件未知时，编译器保留所有可行路径的效果，只保留它们共同保证的性质。

成功、错误、无结果等出口分别检查。容器扩容失败是否保留旧分配，是该操作的契约；不能从错误类型或函数名字推出强失败保证。

### 规格的所属层

MemoryEffect predicate 构造程序行为规格，不执行它所描述的内存动作。返回 MemoryEffect 的 predicate 中，裸 id 参数是 `quote id: lift Any` 的简写；普通 predicate 默认返回 bool，不自动采用这种 quote 参数解释。程序状态、路径、区域和内存效果由独立的程序验证体系处理，即使其表达式出现在限定类型或子句中，也不成为 PTC 的类型原子命题。

## 常见示例

### 同时声明读取与写入

~~~flurry
predicate modify(quote target: lift Any) -> MemoryEffect {
    read<target> and write<target>
}

fn set_if_zero(target: *i32, value: i32)
where outcomes modify(target)
{
    if target.* == 0 {
        target.* = value;
    }
}
~~~

modify 描述目标允许被读取和修改。它不隐含 kill；对仍存活的 i32 槽位写入后，其他合法指针会读到新值。

### 显式上界不能掩盖实际写入

~~~flurry
-- 拒绝：实际行为不被只读上界允许。
fn wrong_read_only(target: *i32)
where outcomes read<target>
{
    target.* = 0;
}
~~~

### 读取指针表示与读取目标不同

~~~flurry
struct PointerBox {
    pointer: *i32,

    fn pointer_value(*self) -> *i32
    where outcomes read<self.pointer>
    {
        self.pointer.*
    }
}

test {
    let number = 6i32;
    let holder = PointerBox { pointer: number.ref }
    let pointer = holder.pointer_value();
    println("{}", pointer.*);
}
~~~

pointer_value 读取存放指针的字段，结果继续携带 number 的依赖；输出时的解引用才读取 i32 目标。因此字段读取上界不能抹去返回指针的依赖关系。

### 清理效果属于函数行为

~~~flurry
struct Trace {
    id: u32,
}

impl Drop for Trace {
    fn drop(*self) {
        println("drop {}", self.id.*);
    }
}

fn quiet_body() {
    let value = Trace { id: 7 }
}
~~~

quiet_body 的完整行为包含输出。只扫描显式函数调用而漏掉清理，会错误地把它当成无外部效果。

## 与 Rust / Zig / C / C++ 的关键差异

这些语言的普通函数签名没有与整套六种效果及状态关系对等的通用入口。Rust 的引用和生命周期、C 的 restrict、C++ 的资源包装以及 Zig 的显式 allocator 参数，分别表达部分访问或责任约束，不能单独代替完整关系契约。

编译器内部也会区分内存读取、写入等效果；LLVM 的相关属性是后端优化契约，不能只按名称与源语言效果互换。[LLVM 函数属性](https://llvm.org/docs/LangRef.html#function-attributes)

## 运行时实现设计引导

效果描述不要求每次 read/write 都进入运行时日志。静态已验证的行为直接执行；需要动态保持的条件由具体检查或协议承担。

受检调用在取得前置依据后执行，并按实际出口交付后置状态。系统动作和 allocator 行为不能因为没有最终返回值或发生在私有实现中而自动删除。

## 编译器实现引导

编译器为每个操作应用顺序转移，再生成边界摘要：

~~~text
State = 位置状态、责任、区域与世代、依赖、内容事实、有效环境
Contract = 入口要求、可能效果、各出口状态关系、结果要求、剩余责任
~~~

1. 应用操作前提，区分不成立与未知。
2. 记录真实读取、写入、终结和外界动作。
3. 更新状态、内容版本及反向依赖。
4. 纳入所有隐式清理和被调用契约。
5. 在边界隐藏已证明不可观察的私有动作。
6. 核验可见行为被显式上界允许，交付其余关系。

分支合成取可能影响的并集、共同保证的交集，并保留预算内可表达的条件关联。循环和递归采用有预算的不动点；超限返回未知或保守摘要，不默认为无效果。

局部存储的位置身份与参数所指向的位置身份必须分开。将局部字段的地址传给辅助函数后，辅助函数的读写契约仍要在实际位置上检查；只有在生成调用边界摘要时，才能隐藏已确认不逃逸的私有存储访问。不能把局部变量编号当作参数编号，也不能因为外部摘要没有记录某次写入，就跳过所有者可用性、初始化或析构检查。

```flurry
fn flip(pointer: *bool) -> bool {
    pointer.* = not pointer.*;
    pointer.*
}

fn local_result() -> bool {
    let value = false;
    flip(value.ref)
}
```

这里 `flip` 的指针访问在调用处落到 `value`；`local_result` 返回的是布尔值，不需要向调用者暴露 `value` 的位置。若改为返回 `value.ref`，则必须拒绝悬垂的局部来源；经过返回实参的辅助函数，也不能消除这一限制。

当前实现已区分这两类根，支持无指针的拥有型局部存储及其字段取址、调用契约重定位，并在发布指针结果时拒绝局部来源。局部指针槽的间接加载／写入还需要额外的存储内容契约，尚未由这套摘要支持；这一实现限制不等于语言禁止局部指针变量。

局部根的布局依据独立于当前表达式的名称绑定环境保存。分析默认实参时，名称查找切换到准备好的形参环境，但这些形参携带的指针仍可指向调用方的局部存储；切换环境不能丢失原有布局，也不能凭布局依据恢复已移动的资源。源代码中读取指针内容的默认表达式还须单独通过 P3 稳定性与有限完成检查。当前支持分析器能够确认 Copy 的读取结果和受检字段投影，并逐个检查所调用的辅助函数；资源层继续检查实际读取位置的有效性，不以纯度结论代替内存安全依据。

立即调用的闭包可以同时携带直接指针捕获与已知代码捕获。内存分析分别保存指针来源、命名函数候选和匿名闭包的环境依据，并在普通实参求值前取得捕获快照；之后给原回调变量赋值，不会改写已经构造的环境。回调实参则在各自求值位置取得依据。相同函数类型不提供代码身份，缺失的回调契约仍保持未知。这是内存摘要能力，不自动使代码捕获通过独立的 P3／P4 检查。

这种调用可以返回不含指针的拥有型聚合，或带有已知代码依据的结果。例如读取指针后构造结构体、元组或枚举，不要求将这些结果变成 Copy；资源层仍跟踪移动和析构。返回代码既保留命名候选，也保留匿名闭包环境，以便后续字段调用和高阶传参继续检查其真实行为。支持的聚合布局也能携带指针结果，按下文的结果字段契约保留来源；直接返回局部地址不会因经过闭包而合法化。

核验已选择的 trait 方法摘要时，接口签名中的关联类型可在同一不可变实现环境中解析后与实现签名比较。这个步骤只取得类型身份依据，不展开 normal-form 头，也不免除调用的程序前提和实际内存检查。查询有独立的预算份额，完成结果仅在当前摘要分析中复用。按值参数内的指针来源需另外经过跨调用映射和存活检查，不能借助关联类型解析跳过这些检查。

直接从泛型定义生成摘要时，类型参数和值参数按声明的种类分别替换，包括 `T, tag:T` 这样的依赖输入。方法签名、主体中的类型、闭包环境及回调候选使用同一组参数身份；不同值实参仍属于不同实例。读取已确定的标量值参数本身不访问运行时存储，但方法对指针的读取、写入和结果来源继续进入摘要。例如：

```flurry
struct Cell where T, tag:T { value:T }
impl Cell<T,tag> where T, tag:T {
    fn view(*self) -> *T {
        let pass = |pointer:*T| pointer;
        pass(self.*.value.ref)
    }
}
```

已完成的 bool 值参数可以决定 `if` 和布尔短路分支，摘要仅保留实际可达分支的指针来源；普通 runtime 条件仍合并所有可能分支。此判断不调用函数，也不展开 normal-form 头。 嵌套记录值参数中的 bool 字段同样适用：例如 `mode.enabled and not mode.nested.ready`。投影之前检查整个记录的字段名、结构和各字段的声明域，不能用一个合法字段掩盖其他字段的错误。记录仅携带已完成的编译期数据时，读取它不引入运行时存储来源；指针和代码值仍需要各自的来源契约。替换、域检查和投影均受摘要预算限制，预算耗尽不能作为分支已确定的依据。

`view` 的返回指针仍指向接收者的 `value` 字段。闭包转发不延长接收者的存活期；已知回调也必须与替换后的实际签名一致，不能因代码身份已知就忽略类型不匹配。这里不把值参数命题交给 PTC，程序内存关系仍由程序验证层检查。

摘要生成端现在能区分“按值形参内的指针字段”和“沿指针访问的目标字段”。例如下面的读取来源是形参 `link` 的 `target` 字段所保存的指针，不能解释成对 `link` 本身取址后访问字段：

```flurry
struct Link { target: *bool }

fn read(link: Link) -> bool {
    let saved = link;
    saved.target.*
}
```

此类来源在摘要中保留独立的 `input-fields` 路径，支持嵌套字段、局部绑定、整体赋值以及分支来源合并。赋值替换旧来源；某条路径缺失依据时仍保持未知。摘要之间的调用组合会先用 `input-fields` 选择实参中保存的指针来源，再拼接被调用方的目标路径。形参换位、嵌套字段投影和返回指针都保留这一顺序；默认实参使用已准备好的前序形参来源。字段路径不会被当作指针目标的附加偏移。

`if` 和 `match` 的聚合结果也保留字段指针来源。分析先在各分支自己的环境中取得结果快照，再合并能正常产生结果的分支；已知失败的 guard 和提前返回的分支不贡献该结果的来源。分支已经执行的访问仍保留。某条可返回路径缺少字段依据时，合并结果保持未知，不能沿用另一分支的已知目标。

```flurry
fn read_selected(flag: bool, left: *bool, right: *bool) -> bool {
    let link = if flag {
        Link { target: left }
    } else {
        Link { target: right }
    };
    link.target.*
}
```

嵌套字段和 newtype 包装保持同样的路径映射；分支内先保存聚合、再改绑原指针变量，不改变已保存的字段来源。

普通函数的聚合返回值按结果字段记录来源。例如：

```flurry
fn make_link(target: *bool) -> Link {
    Link { target: target }
}

fn forward_link(link: Link) -> Link {
    link
}

fn read_returned(target: *bool) -> bool {
    let link = forward_link(make_link(target));
    link.target.*
}
```

`make_link` 的结果字段指向第一个形参所指的存储；`forward_link` 的结果字段来源于第一个形参中保存的指针字段。摘要分别保留结果路径和输入路径，调用方用已求值实参的来源重映射，不能重新求值实参。显式返回、条件返回、嵌套字段和 newtype 包装遵循同样的规则。返回局部变量地址的聚合仍然是非法逃逸；未知来源也不能作为安全读取的依据。当前执行接线覆盖普通函数的直接调用，以及局部函数值指向一个或多个已知普通函数的调用。多个候选分别提供返回契约，来源合并后再映射到同一组已求值实参；读取被调用值本身仍遵守通常的资源规则。临时表达式产生的已知普通函数也保留这些来源，包括条件选择和从临时结构体投影出的函数；临时被调用值的清理责任仍保留到所属完整表达式结束。被调用表达式和实参各按通常顺序求值一次。默认实参也能从已经准备好的前序参数构造含指针字段的聚合。

闭包也能从显式指针参数或直接捕获的指针组装返回聚合：

```flurry
fn link_from_closure(target: *bool) -> Link {
    let make = || Link { target: target };
    make()
}
```

闭包摘要用虚拟输入槽描述捕获指针，调用方将结果字段映射回这次调用的参数与捕获来源。不同闭包候选的捕获槽分别映射，不能混为同一个来源；立即调用、保存后调用、显式返回及分支返回保持这一规则。返回闭包局部变量地址仍然非法。

局部闭包也可以捕获含指针字段的拥有型聚合：

```flurry
fn captured_link(target: *bool) -> Link {
    let link = Link { target: target };
    let make = || Link { target: link.target };
    make()
}
```

捕获时按聚合字段保存指针来源快照，调用时把这些字段作为隐式输入映射回原有存储；嵌套字段和同一聚合中的已知函数字段分别保留依据。读取或写入 `link.target.*` 仍要求目标存储存活；返回 `link.target` 不等于返回闭包环境自身的地址。资源层继续承担聚合捕获的移动和析构责任，内存摘要的虚拟输入不改变运行时传递方式。

含指针捕获聚合中的基础标量字段可以更新；已知布局且不含指针或代码的嵌套数据字段也可以整体替换，不必为这些更新重新描述相邻指针字段的来源：

```flurry
struct Cursor { target: *bool, flipped: bool }

fn toggle_twice(target: *bool) -> bool {
    var cursor = Cursor { target: target, flipped: false };
    let action = || {
        cursor.flipped = not cursor.flipped;
        cursor.target.* = cursor.flipped;
        cursor.flipped
    };
    let first = action();
    let second = action();
    first and not second
}
```

第二次调用使用更新后的标量状态；指针字段继续保留构造时的来源，且每次访问都检查目标存活。如果标量状态决定返回哪个指针，摘要保留所有可能分支的来源，不把第一次调用的状态固定为后续调用的前提。捕获的拥有值一旦被消费，后续调用也不能恢复其可用性。

例如，可以把上例的 `flipped` 包装成独立的数据字段：

```flurry
struct ToggleState { flipped: bool }
struct CursorState { target: *bool, state: ToggleState }

fn replace_state(target: *bool) -> bool {
    var cursor = CursorState {
        target: target, state: ToggleState { flipped: false }
    };
    let action = || {
        cursor.state = ToggleState { flipped: not cursor.state.flipped };
        cursor.target.* = cursor.state.flipped;
        cursor.state.flipped
    };
    action()
}
```

这个允许条件递归检查数据布局，包括 newtype 表示和枚举载荷；藏在包装或字段中的指针和代码不会被当作普通数据。旧字段值的析构、新值的移动及后续调用的可用性仍由资源层检查，这项布局依据不授予 Copy 权限。

当前实现允许直接捕获的指针及聚合中的指针字段改绑，也允许整体替换指针字段布局已知的结构体、元组及其 newtype 包装。替换后的字段来源进入下一次调用的环境状态；旧值的析构使用旧来源，新值的后续访问和析构使用新来源。代码字段可以替换为固定定义的函数或满足捕获约束的匿名代码；可复用摘要将所有可达回调身份纳入固定点推导。局部闭包的直接回调捕获及聚合代码字段可以接收本次调用实参提供的已知代码身份，正常返回后按闭包实例更新；未知身份和缺少可导出借用契约的回调环境仍被拒绝。返回闭包等跨调用边界的代码依据继续需要可复用身份约束。带枚举分支的代码捕获连同分支缺席信息参与逐次传递；枚举指针捕获的载荷切换也会更新下一次调用的标签与来源；正常返回、失败和效应退出分别保留自己的标签快照。取得捕获槽自身的地址，以及指向闭包自有存储的返回依赖，也仍需要环境写回与存储契约。携带这些借用来源的闭包跨函数作为代码实参或结果传递，还需扩展可复用的环境契约；局部调用的来源快照不直接作为可导出的代码依据。

资源报告分别记录正常返回、拒绝退出和效应退出时仍可能可用的捕获指针槽及其目标集合，并与各自的退出状态逐项对齐。完全消费的捕获槽不再输出来源；仅在部分路径上保留的槽仍携带供条件清理使用的来源，但不能据此无条件读取或再次移动。缺少某个槽的记录也不表示它一定不含指针，仍须结合布局与可用性检查。

闭包退出时，资源层把调用内部的借用位置映射回实参及捕获环境，核验指针槽和目标类型，再恢复调用方的来源记录。它分别处理三类退出，只合并仍持有该槽的路径；来源缺失保持未知，调用局部存储不能写回为外部捕获的目标，已消费槽的旧来源会移除。目标存活仍由实际访问和清理检查，恢复来源不会使已失效的存储重新有效。S-expression dump 分别显示三类快照，不能用成功返回的来源替代拒绝或效应退出的来源。正常返回的内存摘要也参与局部闭包环境的状态转换，供下一次调用使用。

闭包内存摘要现在还记录正常完成时各形参指针槽的来源，dump 使用 `input-pointer-exits`，每项带有形参编号、输入字段路径和目标集合。显式返回与隐式尾部完成共同合并；任何返回路径上的未知来源使相应项保持未知，调用局部地址不会导出其内部位置身份。转换后的聚合捕获保留原有输入字段路径。

代码形参槽也有正常返回后的身份记录，dump 使用 `input-code-exits`。记录区分具名代码、保留环境定义的匿名代码和未知身份；显式返回与尾部完成合并所有可达身份，任一路径未知时结果保持未知。缺少可导出借用环境契约的匿名代码不会在这里丢弃其指针依赖后冒充普通代码。没有正常返回时，不产生正常退出记录。

局部调用已使用这份记录更新直接捕获的回调及聚合中的回调字段。每个闭包实例保留独立状态；相同状态可复用以使循环收敛。普通按值代码实参仍是 callee 的局部槽，不因为记录了最终身份就变成对 caller 的写入。

这里记录的是调用内部形参槽的最终来源，不能解释成对普通按值实参的写入。只有被转换为隐式输入的捕获槽用于后续环境状态转换；使用前仍要结合资源退出状态核验可用性，并保留各个闭包实例的环境身份。局部调用为更新后的来源建立独立状态，不原地改写其他闭包实例的快照；循环中的相同状态可复用并参与合并。此机制不授予闭包 Copy 权限。

例如，下列闭包第一次读 `first` 指向的位置，第二次读 `second` 指向的位置：

```flurry
fn read_then_switch(first: *bool, second: *bool) -> bool {
    var current = first;
    let action = || {
        let seen = current.*;
        current = second;
        seen
    };
    action();
    action()
}
```

整体替换也遵循同样的顺序：

```flurry
struct Link { target: *bool }

fn replace_link(first: *bool, second: *bool) -> bool {
    var link = Link { target: first };
    let action = || {
        let seen = link.target.*;
        link = Link { target: second };
        seen
    };
    action();
    action()
}
```

如果 `Link` 有析构协议，每次赋值先完成右侧求值，再按资源规则析构被替换的旧值；闭包退出作用域时还要清理最终保留的捕获值。能推导字段来源不等于获得 Copy 权限。

同一个捕获聚合可以同时保存指针与回调：

```flurry
struct Cursor { target: *bool, action: fn(*bool) -> bool }

fn read_flag(target: *bool) -> bool { target.* }
fn set_flag(target: *bool) -> bool { target.* = true; true }

fn switch_action(target: *bool) -> bool {
    var cursor = Cursor { target: target, action: read_flag };
    let action = || {
        let seen = cursor.action(cursor.target);
        cursor.action = set_flag;
        seen
    };
    action();
    action()
}
```

运行时第二次调用使用 `set_flag`。可复用内存摘要同时包含可能的读取和写入，不能因为初始回调只读就把整个闭包判定为只读。指针字段的来源恢复与回调身份推导分别进行，两者在调用处共同决定访问义务。

替换值也可以来自同一捕获环境中另一个已知回调槽，例如 `cursor.action = cursor.next`，或在这些槽之间做条件选择。分析将各槽中可达的代码身份共同纳入固定点；匿名回调仍需满足其捕获环境的布局约束。取用回调槽遵守正常的移动与复制规则：若要反复从 `next` 取值，必须建立相应的 Copy 许可，代码身份可推导本身不构成复制许可。

也可以在每次调用时交付新的回调：

```flurry
fn install_action(target: *bool) -> bool {
    var cursor = Cursor { target: target, action: read_flag };
    let step = |next: fn(*bool) -> bool| {
        let seen = cursor.action(cursor.target);
        cursor.action = next;
        seen
    };
    step(set_flag);
    step(read_flag)
}
```

第一次 `step` 只执行当前的 `read_flag`；安装 `set_flag` 不等于执行它。第二次才执行写入，然后换回 `read_flag`。摘要按这个次序传递回调状态，不能把未来写入提前算到安装调用，也不能把其他闭包实例的回调一起替换。通过未知高阶接口传入的回调还需要足够的身份或行为契约，不能仅凭函数类型建立这些访问义务。

不必为了获得这项能力而把回调放进带指针的结构体：

```flurry
fn switch_direct(target: *bool) -> bool {
    var current = read_flag;
    let step = |next: fn(*bool) -> bool| {
        let seen = current(target);
        current = next;
        seen
    };
    step(set_flag);
    step(read_flag)
}
```

枚举中的回调字段还保留分支限定路径。某分支的代码候选已知为空，表示该分支缺席，不能与未知回调混为一谈。返回闭包的资源依据会把这种信息恢复为条件标签约束；嵌套枚举若所有内层标签都被排除，约束继续向外层传播，已经不可达的子路径约束随之移除。因此，在工厂中先调用一次、改变回调所在分支再返回，不会恢复成调用前的分支，也不会丢掉实际后续目标的存活检查。

直接回调捕获和独立指针捕获分别恢复其状态。实现保留指针捕获的输入编号，把额外的代码捕获放在其后；内部编号变化不会改变程序里的参数求值和资源交付顺序。




改绑后的实际访问检查新目标存活；旧目标不再因 `current` 的历史来源被保留为必需目标。若闭包把调用局部地址留在捕获槽中，后续调用不能将其当作有效外部目标读取。指针实参仍按普通调用规则求值，改绑捕获槽不会反向改写调用者的指针变量。

默认聚合的字段来源在独立默认值环境中推导，再映射回调用方已经求值的实参：

```flurry
fn read_default(target: *bool, .link: Link = do {
    Link { target: target }
}, .pointer: *bool = link.target) -> bool {
    pointer.*
}
```

后续默认参数可以继续使用前一个默认聚合的字段。显式实参先按调用求值顺序准备，再按声明顺序求默认值；后续显式实参改绑调用方的指针变量，不会替换已准备参数保存的来源。若后续实参移动了被指向对象，默认值不能用自己的独立借用环境掩盖调用方位置已经失效的事实。

返回成功不会解除结果字段的指针依赖。结果保存到局部变量后，若源对象被移动，后续通过该字段读取仍须拒绝；若只有析构方法访问该目标，也须在准备执行时依据清理点的状态拒绝，不能仅检查返回发生时目标是否有效。

拥有型结构体的解构也传递字段中保存的指针来源：

```flurry
fn read_bound(link: Link) -> bool {
    let { target } = link;
    target.*
}

fn read_matched(link: Link) -> bool {
    link match {
        { target } => target.*,
    }
}
```

两者的读取来源都是形参 `link` 的 `target` 字段。嵌套解构逐层投影来源路径；整值绑定保留整个字段映射。`or` 模式将各分支的绑定重映射到共同绑定时，也合并对应的指针来源。计算模式产生的新指针使用计算结果自身的来源，不能借用被匹配值的来源。以上传播只提供来源依据，是否允许复制、移动以及匹配失败后的状态仍由资源检查决定。

资源调用分析现在会在每个实参求值时保存字段中指针的实际来源，再将摘要中的符号来源映射到这些位置。读写前仍核验位置状态：即使结构体已经交付，指针指向的对象若被后续实参移动，访问仍须拒绝。默认实参和闭包主体使用独立的借用分析环境；其中的假定位置不能替代调用方的实际来源检查。

当前资源分析用例已覆盖先绑定聚合再传参、直接构造聚合实参、返回字段指针和依赖前序字段的默认指针参数。调用分派会检查实参在当前运行时作用域内求值的子表达式：结构体构造或块内部取得指针时，也须经过内存检查；尚未执行的闭包主体不作为这次实参求值的行为。

cleanup 调度现在显式记录字段指针的借用前提：参数槽、拥有型字段路径以及指向类型。生成清理计划前先核验函数的内存摘要，随后核对分析报告中的前提是否一致；普通函数及带具体回调上下文的函数分别核验。入口函数不会仅因参数类型含指针就自动获得这些前提。

隐式析构也可能通过保存的指针访问调用方存储，因此不能只用函数体中的显式读写描述调用效果。例如：

```flurry
struct Watch { target: *bool }
impl Drop for Watch {
    fn drop(*self) { self.target.*.* = true; }
}
fn mark_on_exit(p: *bool) {
    let watch = Watch { target: p };
}
```

这里 `mark_on_exit` 的调用效果包含对 `p` 指向位置的写入，即使函数体没有显式赋值。生成执行清理计划时，资源报告保留借用位置对应的形参、输入字段和间接加载路径；将已取得的析构访问映射回这些来源后，按完整函数实例身份加入摘要。访问集合增长时，必须重做调用方检查，不能发布依赖旧摘要的清理计划。普通具名调用和具名高阶调用上下文共同参与这一过程；中间函数转发不能省略该写入。

实现中的这条接线目前发生在执行清理计划生成阶段。它还不能替代所有阶段的完整内存契约：闭包调用已开始把实际执行的清理访问映射回捕获值或实参的位置，并纳入外层函数报告；显式指针实参和直接调用的指针捕获已有检查。捕获指针的局部闭包保存后调用会使用构造时的来源快照；别名和分支选择保留各自的快照。不同候选的捕获输入分开映射，不能把一个候选的字段路径套到另一个候选的目标上。这个来源目前属于局部调用分析，尚不能替代返回、再捕获或任意高阶传递所需的环境契约；局部闭包的指针改绑已接入上述环境状态转换；handler 捕获指针改绑和跨作用域清理来源仍需完善。取得清理信息之前，标量分析对可能运行用户清理的调用采用保守失效：不能仅凭显式摘要没有写入就保留旧内存事实。该标记独立于契约拒绝标记，并通过调用和默认实参传播；调用后的 `assumes` 可以重新建立事实。此阶段尚未按已选析构器证明精确的只读性，因此某些实际不写内存的拥有型调用也可能失去旧事实。


函数工厂读取字段指针后返回命名函数时，回调结果分析也保留同样的借用前提。中间函数转发结果或将工厂作为回调传入，不会省略调用时的来源检查：

```flurry
fn enabled() -> bool { true }
fn disabled() -> bool { false }

fn choose(link: Link) -> fn() -> bool {
    if link.target.* { enabled } else { disabled }
}
```

这里读取发生在 `choose` 调用期间；返回值是选中的函数，并没有因此捕获 `link.target`。带 `comptime Type` 参数的工厂仍将类型输入与运行时存储分开处理。

只移动聚合、不依赖指针有效性的函数可以使用不带字段借用前提的清理计划。调度先在受限预算内尝试这种分析，不能因为聚合里含指针就强加无关的借用要求。需要字段借用时再取得完整的调用摘要依据，失败的尝试也计入预算。局部枚举在已知标签下的载荷清理已能使用对应字段布局和指针来源；嵌套标签仅在所有外层标签均已确定时成为无条件清理依据。替换枚举时，旧值按旧标签和旧指针来源析构，再安装新值的证据：

```flurry
enum Pending {
    first(Watch),
    second(bool, Watch),
}

fn mark_both(a: *bool, b: *bool) {
    var pending = Pending.first(Watch { target: a });
    pending = Pending.second(false, Watch { target: b });
}
```

替换清理写入 `a`，作用域结束清理写入 `b`，两者都要求目标仍存活。资源位置仍使用普通字段路径，选中标签提供该位置的载荷布局；不会将代码身份使用的分支限定路径混入所有权位置。局部控制流合流后，清理计划也保留可达标签集合；集合外的载荷不再要求不存在的指针来源。标签编号不连续时，降码保留显式标签检查，不能压缩编号后按数组下标选择错误的析构分支。嵌套集合若依赖动态外层标签，会保留外层标签限定；清理遍历进入对应分支后才使用内层集合。只有所有外层标签均已确定时，才能将它简化成无条件的物理位置依据。局部控制流合流会查询各分支的类型布局和标签域：查询会递归进入 newtype 的私有表示，包括泛型实例化后的表示，因此包装枚举的条件替换和循环合流遵循同一规则。某个物理字段在该分支不可能是指针时，其缺席不制造未知来源；字段可能存在但没有来源证据时，仍保留未知并拒绝依赖其有效性的访问。相同物理路径上的可能目标取并集，因此仍是保守检查，不保留标签与目标之间的完整关联。更精确的标签与目标关联仍需继续扩展。

枚举指针实参已接入调用摘要：输入路径保留载荷标签，调用点按实参求值时的标签域映射来源。已排除的载荷不产生访问目标；可能活跃但没有来源的字段仍未知。普通函数转发和具名高阶转发保留这些输入路径，例如：

```flurry
enum MaybeAddress {
    none,
    some(*bool),
}

fn read_address(value: MaybeAddress) -> bool {
    value match {
        .none => false,
        .some(p) => p.*,
    }
}

fn forward_address(value: MaybeAddress) -> bool {
    read_address(value)
}
```

传入 `.some(p)` 时，调用者仍必须证明实际被读目标存活；不能因为外层是拥有型枚举就省略借用检查。来源在各个实参自己的求值点取得，后续实参的副作用不能改写已经准备的输入。返回带指针的枚举也会保留符号输入来源，并在交付时映射回调用方的物理字段。普通转发、闭包调用结果、默认实参及 newtype 包装采用同一布局约定：

```flurry
fn address_when(p: *bool, enabled: bool) -> MaybeAddress {
    if enabled { MaybeAddress.some(p) } else { MaybeAddress.none }
}
```

不同载荷若共用物理字段编号，来源取并集，不能由后一个载荷覆盖前一个。这是保守近似：它仍可能要求多个候选目标同时存活，不代表已建立完整的标签与目标关联。返回局部地址依旧被拒绝，返回拥有型枚举不会延长其中指针目标的生命周期。局部闭包的只读枚举指针捕获也会保存构造时的标签和来源快照。捕获标签同时进入闭包值的环境字段布局，因此闭包即使从未调用，或被移动到元组等聚合中，其作用域结束清理也能选择正确载荷。调用更新捕获后，清理使用退出点的新标签。分支选择闭包值时，来源合流也会进入闭包环境的字段布局，结合各分支的捕获标签判断指针槽是否存在。标签域证明不存在的载荷不需要指针来源；其余载荷仍按可能目标检查存活。重复调用不会重新从外部同名变量取得来源，动态选择多个载荷时保留所有可能义务。枚举是否可复制仍由 Copy 协议决定，来源分析不授予复制权限。局部捕获环境切换载荷后，下一次调用使用更新后的标签和指针来源。失败与效应退出的清理使用各自退出点的标签，不与正常返回后的标签混合。更精确的跨分支目标关联，以及借用环境跨函数导出的契约仍需完善。

具备明确环境布局的闭包返回值现在也携带指针字段摘要。例如：

```flurry
typealias Reader = %{p: *bool} fn() -> bool;

fn make_reader(p: *bool) -> Reader {
    || p.*
}

fn example() -> bool {
    let cell = true;
    let reader = make_reader(cell.ref);
    reader()
}
```

这里返回的是闭包拥有的环境，`p` 指向的存储仍属于调用者。摘要将环境字段来源映射到 `make_reader` 的实参；经普通函数转发时继续保留该映射。工厂本身是闭包时，返回的闭包环境也按字段传递来源，包括无捕获工厂的普通指针实参和工厂自身捕获的指针。聚合投影与分支选择保留各自的来源依据，不能把闭包返回值当作不含存储依赖的代码指针。调用前目标失效仍被拒绝，返回捕获函数局部地址的闭包也被拒绝。工厂若先调用闭包并改绑捕获，返回摘要使用调用后的捕获快照，同时更新局部环境字段来源，不能继续使用构造时的旧来源。已知代码候选的闭包也可以作为普通形参传入、转发和调用：

```flurry
fn apply(reader: Reader) -> bool {
    reader()
}

fn forwarded(reader: Reader) -> bool {
    apply(reader)
}
```

调用摘要把捕获来源表示为形参环境的字段路径，而不引用调用者的词法绑定。普通函数内部取得工厂返回的闭包后，也会把已映射到本次调用的环境来源绑定回代码候选，再分析闭包调用。递归和相互递归工厂也可以返回指针闭包：环境字段以空来源作为不动点初值，随后汇总所有真实返回来源。有限的资源遍历无法展开递归时，只有为每个仍可能存在的指针字段提供完整、非空返回来源的可复制捕获布局才可恢复代码候选；恢复代码身份不证明目标存活，局部地址逃逸仍被拒绝。这也允许枚举捕获：恢复时保留全部可能标签，共用物理字段的目标取并集。已收敛摘要中，变体限定字段的明确空来源可证明该载荷缺席，并恢复相应捕获标签域；嵌套标签全部被排除时，缺席证据继续传向外层。无条件字段的空来源、缺失项和未知来源不能据此获得有效性。仍可能出现的任一目标失效都会被拒绝。这份返回标签证据也独立交给清理分析：即使仿射捕获不能通过 Copy 条件恢复可调用候选，从未调用的闭包仍可按已证明的载荷清理。移入聚合不会丢掉这些标签；空载荷不产生析构借用，实际载荷中的 Drop 则继续检查其目标。此能力不授予仿射环境 Copy，也不替代调用所需的完整环境状态依据。普通函数只移动或返回闭包时，不要求提前恢复可调用候选；它仍按传入的标签与环境来源检查清理，并把结果证据传回调用者。真正调用闭包时才需要代码身份及对应环境状态，转交不能免除这些条件。若被调函数销毁所接收的闭包，捕获载荷的析构访问也通过环境字段路径导入调用摘要；调用者须提供这些访问的有效目标。闭包先装入记录再转交给清理函数时，同样保留外层字段前缀。同一段闭包代码生成的不同环境实例不能仅因代码身份相同而共享捕获来源；各自调用、改绑和返回后仍保留各自的快照。多个同类型闭包实参各自保留来源；嵌套在聚合字段里的闭包加上对应字段前缀，枚举捕获继续使用变体限定路径。资源分析为环境中的指针字段建立条件借用前提，并在调用点对实际目标核验；后续实参使先前目标失效也不能绕过检查。被调函数可以先调用、改绑环境，再将闭包交还，返回摘要使用新来源。外层闭包再捕获内层闭包时，同样为内层环境的指针字段建立条件借用前提；代码身份单独保留，不能替代这些前提。当前已覆盖局部再捕获、工厂包装后返回、重复调用，以及内层指针改绑后下一次外层调用使用新来源的路径。工厂也可以先调用外层闭包、由内层改绑指针，再返回整个外层环境。退出摘要只有在对应环境字段已具备指针退出槽位时才保留借用闭包的代码身份；身份与新来源共同交付，不能只恢复旧代码而遗失环境状态。这仍不等于任意高阶借用环境契约已经完成；缺少代码身份或环境状态的候选不能因此获得调用许可。

泛型函数和泛型闭包可以在字段布局尚未确定时转发整个聚合：

```flurry
struct Box where T { value: T }

pure fn forward(value: Box<T>) -> Box<T> where T {
    let action = |item: Box<T>| item;
    action(value)
}
```

定义阶段按拥有值检查移动次数，不为了转发整个 `Box<T>` 而强求未知 `T` 的指针布局。实例化后再根据具体输入取得字段来源和调用契约。若 `T` 是指针，结果仍指向原有存储；随后移动该存储，再通过结果读取，仍会被拒绝。延后布局查询不允许重复消费同一个泛型值，也不展开类型的 normal-form 头。

候选观察的内存摘要复用普通表达式的求值顺序与代码来源分析。工厂返回、局部计算模式和内层 match 取得的回调，可以继续出现在普通模式或 handler 的 guard 中：

```flurry
trait Copy {}
typealias Action = fn(bool) -> bool;
impl Copy for Action {}
struct Packet { flag: bool }
fn accept(value: bool) -> bool { value }
fn produce() -> Action { accept }

fn inspect(packet: Packet, gate: *bool) -> bool {
    packet match {
        item if do {
            let _ and produce() is action = false;
            action(gate.*)
        } => item.flag,
        _ => false
    }
}
```

摘要保留 `gate.*` 的真实读取和回调调用契约，计算绑定携带的是 `produce` 结果自己的代码来源。先检查观察结构是否合法，再做普通内存分析，不用一套仅接受标量的旁路代替代码身份传递。局部赋值只能改写该观察块声明的变量，嵌套分支不能隐藏外部写入。内存摘要仍不证明 Copy，也不授权回退：可能拒绝的目标、候选所有者的交付及 handler 转发由资源层单独检查。

“不会拒绝”的证据也必须覆盖隐式清理。辅助函数即使只显式返回一个布尔值，退出时仍可能调用局部对象、未使用参数或捕获环境的 Drop；不能仅因函数体没有显式检查，就允许它进入 guard。拒绝分析现在结合责任取得时固定的 Drop 选择，逐个检查所有可能清理的组件。独立内存摘要对尚未取得这些证据的聚合构造和非空捕获环境仍保留可能拒绝的结果；安全析构的既有辅助调用不会因此被一概禁止。无捕获代码的构造本身不执行其主体；后续调用再检查主体行为。普通观察块及生成返回区域中的无指针拥有型局部值已接入这项检查，实际退休仍核验剩余字段、访问前提和次序。


### 指针模式绑定与失败出口

内存摘要也跟踪以指针为输入的模式绑定。计算模式中的新绑定来自计算结果；`let-else` 的失败出口使用匹配前的环境，并保留失败路径自己的访问及返回来源。

```flurry
fn select(a: *bool, b: *bool) -> *bool {
    let p and p.* is true = a else {
        b.* = true;
        return b;
    };
    p
}
```

这个函数观察 `a` 指向的值，失败分支写入 `b` 的目标，并可能从两个入口指针中的任意一个返回地址。调用者不能只保留成功分支的来源；任一候选目标在结果读取前被移动或失效，都需要资源检查处理。这些摘要不把函数提升为 P4，也不延长任何目标的存活期。


直接返回指针时，程序验证层把该返回路径的存储来源关联到结果绑定，因此 `requires p.* < 255` 可用于验证返回 `p` 的函数所声明的 `ensures result.* < 255`。尾表达式与显式 return 使用相同检查。返回另一函数已经验证过来源的指针时，结果绑定也继承仍有效的地址来源，支持转发链、字段返回和逐分支验证后置条件。关联带有来源和结果绑定的版本信息；返回另一指针、把局部指针改绑到不同或未知来源，或改写目标后，不能把旧观察当作当前事实；若重赋的来源已证明相同且目标未改变，仍可保留该地址的观察。内存摘要也把结果绑定关联到所有可能的返回目标，再分析后置条件中的读取，避免只读函数因新增结果契约而被误判为不透明调用。已知局部地址的范围可跨此类调用保留，真实写入仍使旧事实失效。若调用摘要证明结果直接返回唯一的指针实参，调用分析保留该实参求值时的地址来源；只有来源版本在后续实参与调用执行后仍有效时，返回值及其局部绑定才复用该来源的读取事实。内存写入仍使已有读取事实失效。这一外部地址传递路径也支持返回所指对象的字段地址，以及在返回指针上继续投影字段；路径保留字段所属类型与索引，不能把相邻字段或另一对象的范围事实用于当前读取。返回摘要包含多个候选时，若代入实际参数后所有候选都对应同一个有效地址及字段路径，仍可保留该地址的观察。例如 `choose(flag, p, p)` 不会仅因有两个返回分支就丢失来源。不同地址或不同字段保持为各自独立的候选。对于直接指针实参及所指对象的字段，验证器读取每一个仍有效候选的当前观察，再取范围的并集；只有所有候选都满足约束，才可据此证明后续运算。候选集合可经局部绑定、普通函数转发和继续字段投影传递，并保留调用帧和来源版本。任一候选未知或失效时，不能选取其他候选代替；写入之后也不能沿用写入前的范围。聚合实参已经携带字段来源时，返回摘要也按输入字段路径取得实际指针；嵌套结构体和局部保存的聚合同样保留字段来源，不能把输入字段路径误当成所指对象的字段路径。局部地址恢复为局部存储位置，外部地址保留版本化候选。写入摘要也使用求值时保存的聚合字段来源映射局部目标，完整写入集合确定后才选择性清除这些位置的范围事实。循环扫描也可使用稳定的结构体指针字段来源；间接指针链与未知聚合字段来源仍需进一步完善。


多个标量指针读取可用 and、or、not 组合为程序条件。验证器在短路分支前为可静态标识的读取建立无约束符号标识，使组合条件在分支合并后仍能引用同一存储观察；这不执行指针表达式，不执行被跳过的调用，也不提供内存安全许可。真实写入仍使旧观察失效。or 成立只说明至少一侧成立，不能据此取得任意一侧的范围。


```flurry
typealias Byte = .u8'builtin;

fn choose(flag: bool, p: *Byte, q: *Byte) -> *Byte {
    if flag { p } else { q }
}

fn read(flag: bool, p: *Byte, q: *Byte) -> Byte
where requires p.* <= 250 and q.* <= 252 {
    let selected = choose(flag, p, q);
    selected.* + 3
}
```

这里无需知道运行时选择了哪一个地址：两个候选的读取范围都足以证明加法不会溢出。删去任一输入的范围前提就不足以证明；在选择之后改写任一可能目标，也需要重新建立读取事实。这份标量证明不提供目标存活或访问权限，内存与资源检查仍独立执行。


```flurry
struct Links { p: *Byte, q: *Byte }

fn select_link(flag: bool, links: Links) -> *Byte {
    if flag { links.p } else { links.q }
}

fn read_links(flag: bool, p: *Byte, q: *Byte) -> Byte
where requires p.* <= 250 and q.* <= 252 {
    let links = Links { p: p, q: q };
    select_link(flag, links).* + 3
}
```

构造 `links` 时保存两个字段各自的指针来源，调用后按 `select_link` 的完整返回候选恢复读取范围。它并不复制或取得指针目标的所有权；聚合交付仍遵守普通资源规则。


```flurry
fn write_first(links: Links) {
    links.p.* = 255;
}

fn unchanged_second() -> Byte {
    let a: Byte = 10;
    let b: Byte = 20;
    write_first(Links { p: a.ref, q: b.ref });
    b + 3
}
```

这里两个局部值的地址都已暴露，但完整摘要只写入 `p` 对应的 `a`，因此 `b + 3` 仍有范围依据。若改为读取 `a + 3`，旧的 `a = 10` 不能继续用于证明。分支可能写入两个字段时，两个目标都失效；如果任一写入目标无法映射，则不能仅清除已知部分。通过指针写入仍使外部读取缓存失效，因为已知局部目标不等于已证明它与所有外部指针互不别名。


循环中的聚合指针调用同样区分指针槽与它指向的存储。只有槽在整轮循环中保持稳定，入口来源才可用于计算写入集合：

```flurry
fn loop_read(flag: bool) -> Byte {
    let a: Byte = 10;
    let b: Byte = 20;
    let links = Links { p: a.ref, q: b.ref };
    var again = flag;
    while again {
        write_first(links);
        again = false;
    }
    b + 3
}
```

`write_first` 改写 `a`，但没有替换 `links.p`，因此循环不会因此抹掉 `b` 的范围。若循环内将 `links.p` 改绑为 `b.ref`，即使改绑出现在调用之后，下一次迭代也可能写入 `b`。扫描对所有可能修改的路径反复计算，直到集合稳定；指针字段或它的父聚合被替换后，不能继续套用入口目标。无法恢复完整目标集合时仍采用保守失效。


循环调用的聚合实参也可由 `if` 或 `match` 选择。每个分支中所需指针字段的来源分别恢复后取并集；例如 `write_first(if flag { left } else { right })` 必须使 `left.p` 和 `right.p` 的所有可能目标失效，而不是只按第一个分支处理。如果其中任一来源未知，或对应指针槽在循环内被替换，则不能把其余已知分支当作完整写入集合。这个静态来源分析不执行条件、guard 或分支代码，真实副作用仍由循环的表达式遍历处理。


结构体形参没有在当前函数中显式构造时，程序验证层仍可从声明取得其已知字段布局，并将字段指针的观察交给转发调用。嵌套结构体和已实例化的泛型结构体遵循相同规则；这一步不展开类型函数的 normal-form 头。

```flurry
fn read_selected(flag: bool, links: Links) -> Byte
where requires links.p.* <= 250 and links.q.* <= 252 {
    select_link(flag, links).* + 3
}
```

调用前置条件需要读取聚合中的指针目标时，验证器在所有实参求值后导入当前观察：局部地址读取对应局部存储的当前范围；外部地址要求求值时记录的来源版本仍有效。输入字段路径先找到指针槽，后续字段路径再选择所指对象的字段。字段读取参与短路条件的符号观察，但不会因此执行本应跳过的表达式或获得额外访问权限。


局部地址和外部地址可以出现在同一个返回候选集合中：

```flurry
fn read_mixed(flag: bool, p: *Byte) -> Byte
where requires p.* <= 252 {
    let local: Byte = 10;
    let selected = choose(flag, local.ref, p);
    selected.* + 3
}
```

验证器保留两类来源的完整集合，读取时分别取得当前局部存储范围与仍有效的外部观察，再合并范围。局部绑定、分支选择、函数转发、聚合包装和字段投影不丢弃其中一类候选。前置条件也必须由所有候选共同满足；局部值有界不能弥补外部候选缺少范围。

这种混合来源证明不等于完整的别名分离证明。目前通过混合指针写入时仍采用保守失效，不能只清除已知局部候选而保留可能被同次写入影响的外部事实。外部来源的版本失效后，也不能删去该候选、继续使用剩余局部地址的范围。


只读函数也可以通过本地指针槽加载返回地址：

```flurry
fn load_pointer(slot: **Byte) -> *Byte {
    slot.*
}

fn read_loaded() -> Byte {
    let first: Byte = 10;
    let second: Byte = 20;
    var pointer = first.ref;
    let before = load_pointer(pointer.ref).* + 3;
    pointer = second.ref;
    let after = load_pointer(pointer.ref).* + 3;
    after
}
```

程序验证层依次读取已知本地槽的当前来源，支持多层槽及结构体字段槽；最终目标可以是局部地址或外部指针。多个返回分支中的每条链都必须完整解析。槽内容在全部实参求值之后取得，后续实参对槽的改绑不能被忽略。

当前这条返回来源规则要求 callee 的完整内存摘要不含写入。若 callee 自身可能先写槽再读，或者保存旧指针后再写槽，就需要更细的时序关系，不能直接使用调用入口或退出时的槽内容代替。外部指针槽的加载同样需要单独的版本化存储模型；来源未知的中间链不能从候选集合中丢弃。


内存摘要也在当前求值点解析本地指针槽：先取得槽中已建立的来源，再继续剩余的间接路径。因此外层函数经本地槽转交只读访问时，仍可导出实际外部读取，不会仅因中间使用了本地槽就丢失只读摘要。普通绑定或字段替换使用更新后的环境；未知槽来源仍拒绝导出，加载出的局部地址也不能借此逃逸。


循环写入扫描可以沿稳定的本地指针槽继续加载目标，包括直接多次解引用及只读函数返回的间接指针。每一层都检查保存指针的存储位置是否与循环的可能写入集合相交；结构体槽还检查父路径。通过槽写入最终目标只使目标值的事实失效，不会自动把整个槽链视为未知。

如果循环中直接改绑槽、经槽地址写入新指针，或替换包含该槽的结构体，则下一轮可能使用不同目标。扫描会重新计算并在无法恢复完整候选时保守失效。该规则不依赖改绑与使用在源码中的先后位置；循环体内新建但入口尚无来源证据的槽，以及外部未知槽仍需更完整的推导。


外部指针槽也可以建立符号观察。每次有效的槽加载取得独立指针身份，同一未失效观察可重复使用：

```flurry
fn checked_indirect(slot: **Byte) -> Byte {
    assumes slot.*.* <= 252;
    slot.*.* + 3
}
```

`assumes` 保留运行时检查；满足条件之后，范围证明才允许加法。多层加载和短路布尔条件采用同样规则。符号观察不会执行短路跳过的指针工厂，也不授予存储访问权限。

写入使读取缓存失效，重新加载槽取得新的身份。保存下来的旧指针不能借用新加载目标的范围；若旧来源已失效，验证器保持未知，而不是将其重新解释为当前槽内容。函数内观察及其条件推导、跨调用的固定间接读取前置条件传递已接通；精确槽写入仍需继续实现。只读函数返回的外部槽来源采用下面的加载规则。


只读函数返回外部槽中的指针时，调用分析按摘要记录的每层加载类型和路径复用这些观察：

```flurry
fn use_loaded(slot: **Byte) -> Byte {
    assumes slot.*.* <= 252;
    load_pointer(slot).* + 3
}
```

摘要必须为每一层间接路径提供对应的指针读取，不能把槽的地址身份当作槽中存储的指针身份。所有实参求值完成后，再按当前来源逐层加载；函数转发、多候选返回和加载后的字段投影保持完整路径。任一候选缺少范围、来源版本失效或槽被写入，都不能借用其他候选的证明。此规则继续要求 callee 的完整内存摘要不含写入，不推断含槽写入函数的入口／出口时序关系。


调用前置条件可以沿固定的多层指针加载导入调用方事实，包括结构体中保存的指针及两个加载值之间的关系：

```flurry
fn difference(first: **Byte, second: **Byte) -> Byte
    where requires first.*.* <= second.*.* {
    second.*.* - first.*.*
}

fn checked_difference(first: **Byte, second: **Byte) -> Byte {
    assumes first.*.* <= second.*.*;
    difference(first, second)
}
```

实际指针来源在各实参求值时保存，指向内容则在全部实参求值后读取；后续实参对槽或目标的写入不能借用写入前的范围。导入按加载深度建立被调用函数的独立观察身份，不混用两个函数的局部绑定编号。

这项前置条件检查不要求函数体有只读内存摘要：函数可以要求入口值满足范围，随后写入新指针。该入口证明不承诺调用后仍保留相同事实；未知写入仍使相关事实保守失效。默认实参的任意间接计算、间接后置条件的完整传递和精确槽写入时序仍未全部实现。


默认实参复制已求值参数时，可以携带其明确记录的调用方指针来源：

```flurry
fn read_default(source: **Byte, .slot: **Byte = source) -> Byte
    where requires slot.*.* <= 252 {
    slot.*.* + 3
}
```

连续默认值复制、条件选择以及默认构造的结构体指针字段遵循相同规则。条件选择要求所有候选满足前置条件；前面的显式实参已经写入目标时，不能恢复写入前的观察。默认值自身必须通过既有的稳定性与内存检查。

实现区分调用方与默认实参的求值环境，只接受附有调用方环境标识的指针来源，不把默认值内部的局部编号解释为调用方存储。固定路径的只读加载也可按下述规则传递；只读辅助调用可按完整内存摘要传递来源；缺少明确来源的表达式仍保持未知。


只读函数的后置条件可以将返回值与已导入的多层读取关联起来：

```flurry
fn read_indirect(slot: **Byte) -> result: Byte
    where ensures result == slot.*.* {
    slot.*.*
}

fn checked_read(slot: **Byte) -> Byte {
    assumes slot.*.* <= 252;
    read_indirect(slot) + 3
}
```

导出只沿已经建立的指针观察寻找最终标量观察，逐层保持槽地址与加载值身份的区别。这也支持字段投影、函数转发和两个返回值之间由输入关系推导出的算术范围。后置条件本身仍需在被调用函数的每个返回点证明。

这项传递要求调用及默认实参满足现有只读、绑定稳定性条件；它不会在导出时执行函数调用或生成新的读取事实。另一槽的范围、后续实参写入前的范围、被调用函数写入前的范围都不能据此套用。含写入函数的间接出口关系仍需独立的时序模型。


默认实参也可从已求值的参数逐层加载指针：

```flurry
fn read_loaded(slot: **Byte, .pointer: *Byte = slot.*) -> Byte
    where requires pointer.* <= 252 {
    pointer.* + 3
}
```

来源分析在显式实参求值时保存槽地址，再按实际默认值求值顺序读取当前槽；连续默认加载和已知结构体字段采用同一规则。较早实参把槽改成另一指针时，默认值使用新指针；不能沿用旧目标的范围。只读且保持参数绑定稳定的默认值才可使用这条传递规则。普通默认表达式检查仍执行，跨环境只交付带来源标识的指针，不搬用默认环境中的标量观察编号。


默认表达式可以通过只读辅助函数取得指针，例如：

```flurry
fn load_pointer(slot: **Byte) -> *Byte { slot.* }

fn read_via_helper(slot: **Byte, .pointer: *Byte = load_pointer(slot)) -> Byte
    where requires pointer.* <= 252 {
    pointer.* + 3
}
```

编译器推导默认表达式的完整内存摘要，再把每条返回来源映射回已求值实参。函数转发、局部绑定、字段加载和多个可能返回目标采用同一条路径；每层间接加载都需要摘要中的对应读取类型。任何候选缺少来源或范围时，整体不能获得前置条件证明。

此规则要求摘要无写入、无未知清理，并继续满足默认值的 P3 检查和参数绑定稳定性检查。辅助函数读取外部存储，不因此获得 runtime `pure` 所要求的 P4 承诺。未知调用摘要、任意写入及无法追踪的返回来源仍保持未知。

只读默认辅助函数返回聚合值时，各指针字段按摘要中的独立字段路径传递来源，而不是只处理顶层指针结果。嵌套结构体、后续默认值从聚合字段取得指针，以及同一字段的多个可能来源都采用完整候选检查。某个字段的范围不能用于另一字段。

字段来源记录独立于默认值的私有求值环境，不要求把调用方存储复制为默认环境中的标量槽。名义聚合涉及的 Copy／Drop 协议和默认值 P3 证明仍须成立；字段来源已知不等于允许复制或清理该聚合。

普通只读调用返回的聚合也保留逐字段指针来源。例如，返回 `Outer { link: Link { pointer: slot.* } }` 的函数经过转发后，调用方仍可将 `outer.link.pointer.*` 与槽当前目标的范围关联。实现只取得已知结构布局，不展开类型函数的 normal-form 头，也不把返回聚合认作某个输入聚合本身。

每个返回字段独立收集完整候选。任一候选范围未知，不能靠另一字段或另一候选的范围通过检查；调用前的实参写入、调用后的目标写入及来源版本失效都继续限制证明。当前这条间接来源规则要求函数摘要无写入和未知清理；含写入函数仍需更完整的时序规格。

返回字段的来源若全部是已知本地位置，写入分析也保留完整目标集合：直接经字段写入或把聚合传给已知写入函数时，只失效可能受影响的位置，无关本地存储的范围仍可保留。多个候选分别合并“未被选中”的旧值与可能写入的新值，不能把写入当作同时更新所有目标。

只要来源中含外部候选，就不把其中已知的本地部分当作完整写入集合。完整读取来源与精确本地写入集合保持一致，不能因只保存了本地子集而漏掉可能的别名写入。

精确调用写入分析也按默认值求值顺序准备聚合指针字段。例如，默认工厂返回 `Link { pointer: p }` 后，callee 可直接经 `link.pointer` 写入，后续默认参数也可继续取得该指针。写入集合映射到调用方的完整本地目标后，只失效可能被写入的位置。

默认聚合有多个可能来源时必须全部计入；缺少任何来源映射，都不能用已知部分冒充完整写入集合。此规则尚不把含间接槽加载的任意写入路径视为可精确映射，仍保留原有的保守失效边界。

循环写入扫描可沿只读聚合工厂的返回字段继续追踪，例如 `write(make(p))` 或 `make(slot).link.pointer.* = value`。返回字段摘要映射到显式实参，间接加载逐层检查本地槽在循环中是否稳定；嵌套字段继续组合路径。因此临时聚合不必先保存到局部变量，才能保留不相交存储的范围。

循环中改绑来源指针或经槽地址替换它时，这条证据随可能写入集合的扩大而撤销，源码中改绑出现在使用之前还是之后都不改变这一要求。未知调用、含写入或未知清理的工厂、需要尚未解析默认实参的来源以及无法确定的槽继续保守处理。

循环中的已保存 Tuple 也可提供其指针元素来源，包含结构体字段内保存的 Tuple。当前程序位置没有元组元素类别，失效分析因此保留元组所在的存储前缀：替换元组或其父聚合会撤销来源；写入父结构体中不相交的兄弟字段不必撤销。此处理不把 Tuple 转成结构体身份，也不展开 Tuple 的 normal-form 头。

含标量写入的函数也可以通过返回聚合保留输入指针的直接地址来源。例如 `set(p)` 写入 `p.*` 后返回 `Link { pointer: p }`，调用方仍知道该字段指向原位置，但写入前的数值范围已经失效；需要当前事实或 checked `assumes` 才能继续证明算术。

直接地址路径不需要读取槽内容；间接路径则需要下述指针存储保持证明，不能直接把含任意写入函数的入口或出口槽内容当作实际加载时的内容。普通指针返回与聚合字段返回复用同一套路径解析和完整候选检查。

间接调用写入还有一个可精确处理的子集：完整摘要的所有写入都是 bool 或定宽整数，因而不会替换路径中的指针槽；默认实参也必须保持存储和准备绑定稳定。此时在所有实参求值完成后，沿摘要中有对应读取类型的槽链定位写入目标。只有每个最终目标都解析为本地位置，才采用精确失效。

这支持多层槽和最终字段投影。较后实参把槽改为另一个指针时，以改写后的槽内容定位 callee 写入，不能错误地失效旧目标而保留新目标范围。任一写入目标未知、包含外部候选，或摘要允许替换指针存储／未知清理时，整个调用继续保守失效。该规则不等于支持任意含指针槽改写的时序规格。

循环预扫描也可定位上述标量间接调用写入，但每层本地槽必须与循环的可能写入集合不相交。扫描使用稳定来源并随写入集合扩大重新检查：改绑槽、经槽地址写入，或未知外部候选会使精确映射失效。它不执行 callee，也不把当前一次迭代的槽内容当作整个循环的不变量。

只读默认实参也可沿这些稳定槽取得来源，并把结果传给后续默认实参。例如：

```flurry
typealias Byte = .u8'builtin;

fn write(slot: **Byte, .target: *Byte = slot.*) {
    target.* = 255;
}

fn checked(flag: bool) -> Byte {
    var active = flag;
    var a: Byte = 10;
    let p = a.ref;
    let b: Byte = 20;
    let exposed = b.ref;
    while active {
        write(p.ref);
        active = false;
    }
    b + 3
}
```

这里默认参数只读取稳定槽 `p`，写入集合落在 `a`；即使 `b` 已取址，仍可保留它的范围。多层加载和连续默认参数按准备顺序组合；若循环也改绑 `p`，或默认值有多个候选，则必须重新检查并合并全部目标，不能继续只认原来的 `a`。默认表达式修改准备绑定、来源不全或清理未知时仍保守处理。

默认表达式使用的聚合字段也是调用依赖，即使 callee 正文不再提及该字段。例如以下接口中，不能只扫描正文的 `target`，还须把 `holder.slot` 映射回调用方：

```flurry
struct Holder { slot: **Byte }

fn write_holder(holder: Holder, .target: *Byte = holder.slot.*) {
    target.* = 255;
}
```

循环中的 `write_holder(Holder { slot: p.ref })` 因而使用与前例相同的稳定槽检查。默认工厂先把指针包装为聚合、后续默认参数再取出字段时，依赖继续沿准备顺序传递；条件分支选择不同字段时，全部候选都必须计入写入集合。

返回聚合字段也复用这套准备规则，而不是直接把 callee 的参数绑定当作调用方局部位置。例如：

```flurry
struct Link { pointer: *Byte }

fn make_link(slot: **Byte, .target: *Byte = slot.*) -> Link {
    Link { pointer: target }
}
```

循环中的 `make_link(p.ref).pointer.* = 255` 可追踪至稳定槽 `p` 所指向的位置。嵌套返回字段、显式覆盖 `.target` 和默认值的全部条件候选按同样规则映射；callee 自身若只写标量，地址来源可以保留，但标量写入仍须计入循环写入集合。循环改绑 `p` 或经其别名改写槽时，返回字段不能继续使用旧来源。

返回的间接指针也可使用指针存储保持证明：完整摘要若仅写 bool／定宽整数、没有未知清理，就不会替换路径中的指针槽。对于能够解析的槽链，先加载指针再写标量与写完标量再加载指针可保留同一地址来源，包括聚合中的指针字段。

这项扩展只恢复地址来源，不恢复写入前的值事实。返回指针指向已被写成 255 的 Byte 时，旧的 `<= 252` 范围不能支持加法；调用方必须使用调用后的事实或 checked `assumes`。含指针槽替换或无法证明存储保持的摘要仍不能采用此规则。

循环中使用这类返回指针时也可复用指针存储保持证明，包括 `set(slot).* = value` 和返回聚合字段的后续写入。callee 的标量写入仍进入循环写入集合，每层来源槽仍须保持稳定；循环内改绑槽会撤销来源，不因 callee 自身只写标量就忽略调用方的改绑。

对于不含 guard、不会暂停的 direct handler arm，如果完整调用摘要证明每个捕获指针字段在所有完成路径上仍来自原输入字段，可以据此重建整个捕获值，而不要求把整槽赋值一概拒绝。例如保留 `state.target`、更新数据字段：

```flurry
struct State { target: *bool, next: bool }

fn advance(state: State) -> State {
    State { target: state.target, next: not state.next }
}
```

handler 中的 `state = advance(state)` 可以保留原指针来源；它是否满足 Copy、移动、借用与清理要求，仍由相应资源检查决定。来源保持证明逐字段检查，不能把“字段类型相同”或“退出时还有一个指针”当作证明。字段交换、多个可能来源、局部来源和未决摘要均不满足这项规则。

这份证据只适用于已检查 arm 内的写入，不授权安装者在 handler 存活期间改绑槽位，也不允许对捕获槽位取址。guard 失败可能在恢复写入之前离开，effect 暂停则可能让另一个 handler 观察中间状态；这两种情况仍需要更强的写回契约。variant 条件下的字段及一般跨暂停写回也不由此规则自动放行。

同一安装中的多个 arm 可以各自提供这份来源保持证明，包括同一操作的不同模式分支和不同操作的 handler。检查器先收齐各 arm 的证明，再核验整个安装范围；某个 arm 的合法写入不会使另一个 arm 的未知写入合法。任一位置缺少所需证据，安装整体仍不能通过检查。安装者的计算和 guard 不因其它 arm 已取得证明而获得写回权限。
