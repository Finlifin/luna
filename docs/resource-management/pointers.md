# 指针与访问

## Intro

指针记录要访问的位置。复制指针后，两份表示仍指向同一个目标；写入目标后，它们可以读到新的内容。

指针类型说明目标类型，但访问是否合法还取决于目标此刻是否存在、是否含合法值，以及操作所需的资格是否成立。

## 语法

~~~text
pointer_type -> *expr
reference -> expr.ref
dereference -> expr.*
projection -> expr.id
~~~

## 正式定义

### 表示与投影

普通 `*T` 的位宽与 usize 相同。指针本体布局不要求展开 T 的完整按值布局。

`value.ref` 取得位置的指针，`pointer.*` 访问目标。经结构指针投影字段时，结果为字段指针，相当于解引用、字段投影后再取址。

在具有明确值目标的位置，编译器可以按[目标引导读取](../type/receiver-adaptation.md#字段指针与目标引导读取)插入合法 Copy 读取；无目标的字段投影仍保留指针关系。

### 复制与访问

普通指针可 Copy。复制只传播真实目标依赖，不复制 pointee、不取得其终结责任，也不依赖中间指针变量自己的槽位。

每次实际读取需要目标存活、相应值已初始化、布局和目标类型条件成立。写入还须满足其写入、旧值清理和写后不变量要求。仅有相容位宽或指针类型不能替代这些条件。

### 别名

多个指针指向同一对象，不自动使顺序访问非法。前一次写入会改变后一次读取的值，并撤销依赖旧内容的事实。

若算法要求两个区域分离、某个值在区间内不变，或允许并行访问，就要为这些额外要求提供依据。普通 `*T` 不隐含独占访问或后端 noalias 属性。这一设计与 Rust 的引用系统不同：Rust 通过共享引用/独占引用在类型层面强制执行别名规则，而 Flurry 将分离性作为按需证明的契约，从而允许同一目标上的多个指针在顺序代码中自然共存。

### 保存失效表示与使用失效目标

原始指针的表示可以在目标结束后仍留在一个位置中；但程序不能因此继续解引用。清理不读取目标的普通指针表示，与会解引用指针的用户 Drop 有不同要求。

替换该表示可以建立新的有效依赖；前提是目标槽位本身仍合法，且旧值的真实清理允许这样做。相同数值地址重新出现，不使旧目标世代复活。

## 常见示例

### 字段投影取得字段指针

~~~flurry
struct Cell {
    value: u32,
}

test {
    let cell = Cell { value: 7 }
    let pointer: *Cell = cell.ref;
    let field: *u32 = pointer.value;
    field.* = 9;
    println("{}", cell.value);
}
~~~

### 顺序别名读取最新内容

~~~flurry
fn write_then_read(first: *i32, second: *i32) -> i32
where outcomes write<first> and read<second>
{
    first.* = 11;
    second.*
}

test {
    var number = 3i32;
    let result = write_then_read(number.ref, number.ref);
    println("{}", result);
}
~~~

输出 `11`。签名没有承诺参数分离，因此检查和优化都必须考虑它们相同的情况。

### 中间指针槽位不成为目标

~~~flurry
test {
    var number = 5i32;
    let second = do {
        let first = number.ref;
        first
    }
    number = 8i32;
    println("{}", second.*);
}
~~~

输出 `8`。first 的局部存储已经结束，但不影响 second 对 number 的依赖。

### 完整覆盖替换依赖

~~~flurry
fn choose_outer(outer: *i32) -> *i32 {
    let local = 1i32;
    var saved = local.ref;
    saved = outer;
    saved
}
~~~

saved 是单个精确槽位；完整覆盖后，它保留 outer 的目标依赖，不继续背负 local 的地址。返回时仍须交付 outer 原有的有效性要求。

## 与 Rust / Zig / C / C++ 的关键差异

Rust 区分共享引用、可变引用与原始指针，原始指针解引用要求 unsafe；不能把其引用独占规则直接套到 Flurry 的 `*T`。[Rust 指针类型](https://doc.rust-lang.org/reference/types/pointer.html)

C/C++ 指针是表示上的直接类比，但普通 C 指针类型不承担这套逐操作有效性检查。Zig 的指针可包含 const、对齐等类型信息；而 Flurry 的本节规则还通过程序契约跟踪具体目标与访问状态。

## 运行时实现设计引导

字段指针由合法基址和布局偏移取得；指针复制保留地址，不复制目标。静态检查的依赖关系无需改变普通指针的机器表示。

需要动态有效性证据的库可以使用代际句柄或访问租约。句柄查验后取得的新指针与旧指针不是同一份资格；运行时监控也须维持检查和使用之间的关系。

## 编译器实现引导

编译器分别记录指针槽位、所指区域和该项操作的前提。字段投影产生字段指针；需要读取字段指针表示或字段值时，编译器分别插入对应 read。

调用时先按实际别名关系解释参数契约。参数有可能相同，因此不能分别假设两个独立对象后再应用摘要。

精确覆盖执行强更新；目标对应多个槽位时，编译器保守保留所有仍存在的依赖。诊断区分"指针槽位非法""目标世代结束""目标未初始化"和"旧内容事实已失效"。
