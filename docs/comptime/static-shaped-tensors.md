# 案例：静态形状的张量加法

## Intro

张量加法可以在编译时决定结果形状，在运行时处理元素。一个矩阵与向量相加时，编译器知道向量应当沿哪一维复用，不需要先读取向量里的数值。

这个例子把类型、可执行命题和按阶数确定的代码结构放在同一次计算中。

## 语法

本章使用 Tensor 教学接口。`random` 构造相应形状的数据，`zeros` 构造零值张量；其数据来源和存储方式不影响这里的阶段分析。

```text
tensor_type -> Tensor<expr*>
              | Tensor<expr, .dims = expr>
addition -> expr + expr
```

类型调用、普通调用、加法及 `test` 复用[全局语法](../grammar/syntax)。后文的形状算法使用数学伪代码，不是新的 Flurry 语法或标准库函数。

## 正式定义

### 示例的输入与结果

本章的形状是有限的正整数列表；空列表表示零阶。列表长度是阶数。以下方括号除 Flurry 代码外均为数学数据表示。

对元素类型 T，零阶 Tensor 与 T 相等。这是类型关系：一个零阶值仍可以在 runtime 才取得，并不因为阶数为零就成为 comptime 常量。

张量加法要求元素类型支持结果仍为该元素类型的加法。两输入形状从右向左对齐：

1. 对应维度相同，可以配对。
2. 某侧维度为 1，可以沿该维复用其唯一切片。
3. 某侧缺少前导维度，在该维保持整个输入，不实际插入存储。
4. 其余配对不相容，编译时形状检查失败。

结果类型使用广播后的形状，不能固定为左操作数形状。例如 [128] 与 [128, 128] 相加，结果是 [128, 128]。

### 命题与计算

`broadcastable` 表达两形状是否相容；它是具有可执行语义的 comptime predicate。`broadcast_shape` 计算结果形状。检查相容性和取得具体结果是相关的两项工作。

在输入尚未知时，ordinary 可以利用相应操作契约检查后续使用。它并不因此已经获得结果形状的每一维；凡是需要具体维度的计算，仍等待输入。

### 检查放置与诊断

元素加法能力可以作为 implementation 的适用要求。形状相容性也可以在已选 implementation 内通过 PTC assumes 检查，并在 instantiation 直接执行。

后者使不相容形状成为该实现内部的具体检查失败，而不只是使实现因形状约束不满足而不可用。失败发生于编译时，不能把不相容张量交给 runtime 加法继续处理。

### 执行阶段

| 工作 | 阶段与输入 |
|---|---|
| 定义中的操作合法性检查 | normalization，使用类型与操作契约 |
| 相容性验证、结果形状计算 | 输入形状确定后的 comptime 执行 |
| 填充长度、投影分支、递归实例的确定 | comptime，依赖形状 |
| 获取元素、执行元素加法、写入结果 | runtime，依赖实际数据 |

按形状确定实例不要求将普通元素循环全部展开，也不要求编译器消除所有函数调用。

## 常见示例

### 相同形状

```flurry
test {
    let xs = Tensor<f64, 128, 128>.random();
    let ys = Tensor<f64, 128, 128>.random();
    let zs = xs + ys;
}
```

两边的每一维对应相加，结果形状为 [128, 128]。

### 标量广播

```flurry
test {
    let zeros = Tensor<f64, 128, 128>.zeros();
    let ones = zeros + 1.0;
}
```

标量按零阶参与形状计算。沿矩阵的各层投影时保持该标量，最终对每个元素执行加法；不必先构造一个同形状的输入张量来保存重复的标量。

### 向量广播

```flurry
test {
    let matrix = Tensor<f64, 128, 128>.random();
    let vec = Tensor<f64, 128>.random();
    let matrix_e = matrix + vec;
}
```

向量缺少最左侧的一维。遍历矩阵各行时，向量保持自身；进入行内计算后，两边才一起降阶。

| 输入形状 | 第一层递归 | 结果形状 |
|---|---|---|
| [128, 128] 与 [128, 128] | 两行 [128] 相加 | [128, 128] |
| [128, 128] 与 [] | 行 [128] 与同一标量相加 | [128, 128] |
| [128, 128] 与 [128] | 行 [128] 与原向量相加 | [128, 128] |

## 与 Rust / Zig / C / C++ 的关键差异

| 对照语言 | 对应机制与差异 |
|---|---|
| Rust | const 参数可把固定尺寸放入类型，但允许的参数类型不包含任意形状列表；实际还可用嵌套数组或类型编码组织阶数。[Rust const generics](https://doc.rust-lang.org/reference/items/generics.html#const-generics) |
| Zig | comptime 类型函数和参数可生成按形状确定的类型；Flurry 另用 PTC 契约连接未知形状时的检查。[Zig comptime](https://ziglang.org/documentation/master/#comptime) |
| C11 | 无对等的任意阶数类型计算；实际用多维数组、维度描述数据、宏或生成的专用函数。[C11 草案 §6.7.6.2](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf) |
| C++ | 模板参数包可编码不同长度的维度参数，配合模板与 constexpr 计算结果；Flurry 用编译时形状值和 PTC 检查组织计算。[C++ 参数包](https://eel.is/c++draft/temp.variadic) |

## 运行时实现设计引导

下面是张量接口上的算法，不规定底层布局、借用或分配 API。投影和结果构造必须满足该接口自己的类型与资源契约。

前置条件：输入形状 A、B 已通过广播检查，结果形状 S 已知；元素加法可用。

```text
AddData(a, A, b, B, S):
    如果 S 为空：
        对两个标量执行元素加法，返回结果

    pad_a = length(S) - length(A)
    pad_b = length(S) - length(B)
    构造形状为 S 的结果容器

    对 i 从 0 到 S 的首维减 1：
        若 pad_a > 0：保留 a 和 A
        否则：沿首维投影 a；A 首维为 1 时取索引 0，否则取 i
              新形状为 A 去掉首维

        对 b 和 B 执行同样的选择
        递归计算两个片段的加法
        将返回片段写入结果的第 i 个切片

    返回完整结果
```

这描述数学递归的零阶终点，不依赖为标量提供 Tensor 索引操作。如何把它组织成具体 implementation，由对应 trait 与 Tensor 接口契约决定。

不变量：

- 虚拟填充只改变投影选择，不需要给输入增加实际存储。
- 递归结果形状等于 S 去掉首维。
- 两输入阶数的最大值在每次递归调用中减少 1。
- 每个结果切片获得与其形状相符的完整值；最终返回前满足结果初始化要求。

设结果元素数为 N，阶数为 r。算法执行 N 次元素加法；若投影是常数代价的视图操作，直接递归遍历的保守上界为 O(Nr)，递归深度为 O(r)。具体布局与优化可以降低额外索引代价，但不能从 comptime 本身推导出固定存储成本。

## 编译器实现引导

### 形状计算

以下使用索引扫描避免每一步复制列表前缀。输入为本章定义域内的形状 A、B，输出为结果形状 S 或不相容错误。

```text
r = max(length(A), length(B))
准备 r 个结果维度
从最右边开始逐维处理：
    x = A 的对应维度；若该侧已无维度则为 1
    y = B 的对应维度；若该侧已无维度则为 1
    若 x == y：结果维度为 x
    否则若 x == 1：结果维度为 y
    否则若 y == 1：结果维度为 x
    否则：形状不相容，失败
返回 S
```

复杂度为 O(r) 时间、O(r) 结果空间。相容性谓词可以使用相同扫描而不分配结果列表。

### 支撑 ordinary 检查的性质

形状计算和投影操作的契约需要使下列性质可用于相应检查：

1. 广播成功时，结果阶数为两输入阶数的最大值。
2. 对非零阶结果，按上述填充与投影规则得到的两片段仍然相容。
3. 两片段的广播结果是外层结果形状的尾部。
4. 元素加法的结果满足对应结果元素要求。

这些性质可以检查递归调用与切片写入的类型关系。仅知道 `broadcastable` 为真，不等于编译器已经知道任意函数调用的结果契约；合法性检查必须有对应依据。

### 实例化与生成

1. 代入元素类型及两个具体形状。
2. 执行适用的形状检查；不相容时报告输入形状和触发调用。
3. 求出结果形状及各层投影选择。
4. 实例化相应的递归加法操作，确定各层返回形状。
5. 输出 runtime 元素循环、投影和加法；只有使用 inline 展开的部分承担强制展开要求。

不同调用可以使用相同形状计算结果，但 runtime 输入值和运算仍彼此独立。缓存、递归调用复用和普通循环优化不得改变这一点。
