# 效应 ABI 与可替换控制后端

## Intro

一次效应请求需要找到处理入口，并按该入口的约定传递控制和结果。只有需要保存剩余计算时，才涉及 continuation 的存储与恢复。

ABI 把这些交接规定清楚，使独立编译的主体、库提供的控制后端和调度器可以配合。栈池只负责执行存储的管理，同步使用不需要附带异步运行时。

## 语法

~~~text
algebraic_effect -> async? inline? effect id(parameter*) (-> result)? clauses?
catch_param -> catch parameter
handler_application -> expr.use(expr)
attribute -> ^expr
~~~

函数的外部 ABI 通过属性指定，例如 ^attrs.abi(.c)。控制后端通过处理协议供应，不为函数签名增加另一个能力段。

## 正式定义

### ABI 类别

| 类别 | 输入与交付 | 不变量 |
|---|---|---|
| 错误结果 | 普通返回的成功／错误标签与载荷 | 不含恢复权；按错误行嵌入 |
| 普通直接处理 | 操作实参、环境，返回 Y | 分支使用外层处理上下文 |
| Direct passing | 安装时取得值，之后传递值 | 不重复执行提供分支 |
| 捕获处理 | 操作实参、环境及 continuation | 单次消费，保留恢复与清理契约 |
| Async 处理 | 请求登记子工作，返回 Future | 子工作与等待由协议接入 |

内联可以把某些交接消除为局部控制流，但 inline 意向不改变可观察语义。错误结果有独立 ABI；中止控制不能编码为一个可被用户错误 arm 截获的普通错误。

### 路由与控制分离

Evidence 保存选定 operation occurrence 的入口依据。它可以在运行时指向具体 handler，不意味着所有 handler 对象在编译时就是常量。直接入口不必搜索整个动态链。

动态路由则从当前有效处理上下文查找入口。它必须维持相同的操作身份、同名层次和分支外层环境规则；不能只按名称取得任意一个最近对象。

动态分派本身不意味着丢失操作签名。没有合法处理入口的静态程序不能自动退化为未检查的动态搜索；动态入口也必须满足其明确的供应和失败契约。

路由结果不指定 continuation 必须用栈复制、状态机还是某种上下文交换。首版使用地址稳定的有栈后端；兼容同一有栈调用约定的后端可共享一份主体代码，每次安装分别选择。

### 控制后端与存储

标准库提供池化后端实现，具体栈池实例通过处理协议供应。后端须支持限定边界、捕获、单次恢复、尾恢复、放弃与正常完成；栈存储策略另负责分配、容量、地址稳定性及回收。

### 显式栈池实例

独立使用池化控制时，通过 .use(pool) 显式接入所选栈池实例。pool 按处理协议提供该实例的执行存储；范围内的调用通过协议取得供应，不要求每层函数重复声明一个普通 pool 参数。不同安装可以使用同一实例，也可以选择不同实例，各自仍须满足实际后端的 ABI 与访问契约。

runtime 可以封装 stack pool，并通过自己的处理协议供应执行存储。使用者安装 .use(runtime) 即可取得调度和栈存储服务，无需再显式指定 pool，也不必知道内部栈池的构造方式。runtime 承担所封装栈池的供应与存活契约。

栈池负责分配、保留与回收，runtime 还负责工作调度、等待和唤醒。这些职责允许组合封装；同步 continuation 独立使用栈池时则只需 .use(pool)。

continuation 持有的每段栈保留其分配来源。恢复点重新供应外层效应入口，不改变已经分配的栈所属的 pool；以后新建控制边界使用其选定实例，已有栈在完成清理后归还原实例。捕获跨过多个池化边界时，各段分别保留来源。

栈池的有效期必须覆盖所有尚未归还的栈及其关联依赖。continuation 逃逸时，这份存储依赖也随之保留；不能只让恢复权逃逸而先销毁它使用的 pool。

保存在 continuation 中的内部处理关系随恢复重新安装。外层 evidence 在恢复点重新供应，主体不得跨可挂起调用继续使用已经失效的外层入口缓存。此前保存的普通值、固定对象依赖和已分配栈的来源保持各自身份。

### 跨语言边界

C ABI 入口的效应行为空。需要处理效应时，由 Flurry 包装层在边界内安装处理器，再向 C 交付符合其 ABI 的结果。目标 pipeline 还检查其他目标相关限制；空行不是全部合规条件。

挂起区域中的 C 帧允许保留后再恢复，但禁止放弃。编译器不能静态排除这种放弃时，必须保留运行时检查；实际放弃越过 C 帧屏障才触发 trap。不能静默跳过外部帧及其未知资源责任。

## 常见示例

### 三个相同结果类型，不同交接方式

~~~flurry
effect read_number() -> u32;

^attrs.effects.direct_passing
effect installed_number() -> u32;

effect captured_number(catch continuation: builtin.Continuation) -> u32;

fn direct() -> #[read_number] u32 { read_number()# }
fn installed() -> #[installed_number] u32 { installed_number()# }
fn captured() -> #[captured_number] u32 { captured_number()# }
~~~

三个请求的最终结果都是 u32。direct 每次执行入口，installed 取得安装值，captured 许可控制后端交出剩余计算。把三个入口简单转换成同一种裸函数指针会丢失必要契约。

### C ABI 包装

~~~flurry
effect configured_limit() -> u32;

fn limit_times_two() -> #[configured_limit] u32 {
    let limit = configured_limit()#;
    limit * 2u32
}

^attrs.abi(.c)
pub fn exported_limit() -> u32 {
    limit_times_two()# {
        configured_limit() => 8u32,
    }
}
~~~

exported_limit 的接口没有效应行，返回 16。处理发生在 Flurry 包装层内；C 调用者不需要供应 handler evidence。

### 显式选择同步栈池

下面的 pool 是使用者已经创建、按池化控制协议接入的栈池实例。示例展示使用端，构造和容量配置由所选库提供。

~~~flurry
effect pause(catch continuation: builtin.Continuation);

fn work() -> #[pause] u32 {
    pause()#;
    42u32
}

let result = (work()# {
    pause(continuation) => { resume; },
}).use(pool);

println("{}", result);
~~~

输出 42。主体使用显式供应的 pool，处理分支立即恢复计算，完成后归还不再使用的栈。这个过程不要求安装 runtime。

### 同步栈池的工作关系

以下是内部表示示意，不是公开结构体或库 API：

~~~text
调用栈 S0：安装 H_outer
    │
栈槽 S1，来自 pool_outer：H_outer 的主体，安装 H_inner
    │
栈槽 S2，来自 pool_inner：H_inner 的主体，请求 H_outer

捕获：K 持有 S1…S2 的执行链和内部处理关系
处理：在选定边界外执行 H_outer 的分支
恢复：连接本次返回位置，恢复内部关系，向请求交付 Y
完成：向本次恢复位置交付 B，兑现清理后将 S1、S2 分别归还原实例
~~~

pool_outer 与 pool_inner 可以指向同一栈池，也可以是两个兼容实例。这个驱动过程不要求创建 task 或访问事件循环。调度器只是在此基础上决定哪一份恢复权何时执行。

## 与 Rust / Zig / C / C++ 的关键差异

这些语言可以用显式回调或协程库提供控制后端，ABI 的兼容性仍需另外约定。C++ 的异常展开与本篇隐藏中止通道都可能触发清理，但它们不是同一用户控制机制；Rust、Zig 的错误结果则更接近本篇独立的错误返回侧。[C++ 异常](https://eel.is/c++draft/except)、[Rust Result](https://doc.rust-lang.org/std/result/)

## 运行时实现设计引导

### 入口描述

内部入口应能区分操作身份、occurrence、分支环境、外层路由、限定边界、控制后端及协议供应的存储实例。存储可以由独立 pool 或已安装的 runtime 提供。每段栈另保存其分配来源和归还依据。某种入口不使用的字段可以消去；这张逻辑描述不规定所有 ABI 都分配一个统一大结构。

直接路径把 perform 降为经入口调用，返回 Y。可捕获路径的入口桩保存该机器约定要求的状态，并把控制交给边界外的分支；恢复后，该入口向主体表现为取得 Y 并继续。

调用约定还要允许内部中止沿正在退出的调用链传递。它可以采用独立控制状态或约定结果通道，但不能让它成为用户 Y 的一个未经声明分支。

### 池化执行算法

1. 安装需要捕获的边界时，从协议供应的池实例领取地址稳定的执行栈，记录分配来源，建立完成与清理入口。
2. 在该栈执行主体；直接处理边界可以只维护逻辑入口，不单独领取栈。
3. 捕获时取得目标边界，保存机器状态，并把对应执行链转交给新的恢复权。
4. 在边界外执行分支；恢复时接入调用这次恢复的位置，并更新外层供应槽。
5. 尾恢复完成分支清理后直接切入；非尾恢复保留等待 B 的后继。
6. 主体正常完成时经过正常结果转换，再交付 B。
7. 放弃时切入隐藏中止路径，逐帧执行清理；检查 C 帧屏障，到边界停止。
8. 确认所有恢复权、借用和环境依赖均已结束后，把不再存活的栈槽归还各自的来源实例，再结束相关存储依赖。

逃逸的 continuation 不能继续保存一个已经退出的安装者栈地址作为返回位置。恢复必须重建本次接收位置，而被保留的 handler 环境必须有合法的实际 owner。

### 状态与开销

每份恢复权只能在持有、运行、转交、清理与完成之间按协议转换。恢复与放弃争用同一个消费权；后端不得让同一执行栈同时运行两次。

已知栈链端点时，链的拆接可以保持常数次指针操作。完整开销仍包括查找、上下文供应、协议工作与清理：动态搜索可能与链长相关，清理与尚存责任相关，池扩容也可能调用操作系统。

栈槽耗尽或溢出必须走后端已经声明的失败路径，不能覆盖相邻槽。保留虚拟地址、按需提交物理页和批量回收是可选存储策略，不是用户程序需要依赖的固定页数。

## 编译器实现引导

1. 保存操作类别、属性和完整 ABI 描述，不在类型擦除时丢失。
2. 根据允许行与处理 occurrence 建立 evidence；取得所选控制后端与栈池实例，检查供应及存活关系。动态入口另保留检查与查找契约。
3. 在可挂起调用点保留恢复所需状态；不得缓存已要求重绑定的外层入口。
4. 建立正常完成、显式非局部退出和内部中止的独立控制边；复用资源清理图时保留各自目标。
5. 验证尾恢复确实没有遗留等待当前恢复的分支帧。
6. 对不同后端检查共同调用约定；不兼容时要求显式适配或拒绝，不自动重解释机器状态。
7. 保留外部帧屏障及目标 pipeline 所需元数据，交给后端完成机器级合规检查。
8. 在生成代码中验证结果槽、恢复位置、栈的来源实例和环境存活关系，未完成交付的代码不得进入链接。
